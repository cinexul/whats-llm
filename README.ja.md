# やさしいLLM入門 · 大模型学习手册 · LLM Learning Book

> 言語 / Language：[简体中文](README.md) · **日本語** · [English](README.en.md)

文系出身の私は、IT会社に就職し、システムエンジニアになりました。専門知識のない人がどこでつまずきやすいかは、身をもって知っています。この本は、プログラミングをやったことがない人のために書きました。コードを一行も書いたことがなくても大丈夫です。

前半では、大規模言語モデル（LLM）がどういうものかを説明します。文章をどう読んでいるのか、なぜ間違ったことをもっともらしく言うことがあるのか、いろいろなAI製品は何が違うのか、といったことです。後半ではClaude CodeやCodexのようなAIコーディングツールを使って、個人サイトから始めて6つの小さなプロジェクトを作ります。最後の章では、この本とアプリそのものをどう作ったかを紹介しています。コードはほとんどAIと一緒に書きました。

中国語・日本語・英語の3つの版があり、読みながらいつでも切り替えられます。各章の終わりには小テストがあって、その場で答えて解説を読めます。間違えた問題は、あとで復習に出てきます。

このリポジトリには、本の原稿と、この本を読むためのアプリが入っています。

## ダウンロード

そのまま使えるアプリをダウンロードするのがおすすめです。開発用のツールは要りません。[Releases](https://github.com/cinexul/whats-llm/releases)で最新のバージョンを開いて、次の2つのどちらかを選んでください。

- インストーラー（ファイル名が`-setup.exe`で終わるもの）：ダブルクリックでインストールして、あとはスタートメニューから開きます。たいていの人はこちらで大丈夫です。
- ポータブル版（`.zip`）：フォルダーに全部展開してから、中の`whats-llm.exe`をダブルクリックします。インストールしたくないときや、USBメモリに入れて持ち歩きたいときはこちらです。

中身はどちらも同じで、本文とフォントはプログラムに入っているので、ネットにつながっていなくても読めます。Windows 10か11（64ビット）が必要です。違いや学習記録の保存先は[Windows版の説明](docs/windows-portable.md)にあります。

いま配布しているのはWindows版だけです。MacやLinuxでは、いまのところ下の「ソースから動かす」の手順で自分で動かすしかありません。コマンドラインを使います。

## 本の中身

本編は41章で、6つの部に分かれています。LLMを知る、日常や仕事で使う、ツールの全体像をつかむ、AIコーディングの実践、プロジェクトを作る、リスクと責任ある使い方、の6つです。ほかに終章と、付録が5つ（3言語の用語集、プロンプトのテンプレート、Claude Code / Codexの機能リファレンス、公開前のチェックリスト、よく使う数字の早見表）あります。

アプリには本文のほかに、こんな機能があります。

- 学習コース：概念をつかみたい、出典付きの業務レポートを書きたい、初めてのWebページを作りたい、の3コースです。各ステップに自分でチェックを付けられます。
- 体験ラボ：本物のトークナイザー2つで、同じ文が中国語・日本語・英語でそれぞれ何トークンになるかを比べられます。ほかにコンテキストの予算、RAGでの根拠探し、エージェントの権限の3つのシミュレーションがあります。どれも手元の端末で動くので、APIは要りません。
- 復習と間違えた問題：忘れかけたころに復習が回ってくるように並べます。間違えた問題は、テーマや章ごとに練習できます。
- マイライブラリ：学習記録をバックアップとして書き出して、新しいパソコンで読み込めます。Web版では、ここから本全体をダウンロードしてオフラインで読むこともできます。
- 続きから読む：どの段落まで読んだかを、言語ごとに覚えています。
- 本文を自分で直す：章の本文を編集して、プレビューや変更点を確認できます。元の文章にはいつでも戻せます。使い方は[利用ガイド](docs/local-chapter-edits.md)にあります。
- 各章に改訂日と出典を載せています。製品の機能や料金のように変わりやすい内容には、いつ確認したかを書いています。

## ソースから動かす

ここと次の節は、自分で手を加えたい人や、MacやLinuxを使っている人向けです。本を読むだけなら、上でダウンロードしたもので十分です。

Node.js 24（24.15.0以降）とnpmを入れてから、次を実行します。

```bash
cd app
npm ci
npm run dev        # http://localhost:1420 を開く
```

本番用にビルドするときは、次のコマンドを使います。

- `npm run build`でWeb版を作ります。出力先は`app/build/`です。
- ビルドしたあとに`npm run preview`を実行すると、`http://127.0.0.1:4173`でオフライン機能も試せます。
- `npm run tauri -- build`でデスクトップ版を作ります。先にRustとシステムのWebViewライブラリを入れておいてください。

スマートフォンでオフラインで読むには、本番ビルドをHTTPSのサイトに置き、「マイライブラリ」で本全体をダウンロードしてから、ブラウザでホーム画面に追加します。開発用の`npm run dev`ではオフラインキャッシュを使いません。画面例は[モバイル版の記録](docs/mobile-reader.md)にあります。

## コードや本文を直すときは

コードはすべて`app/`の中にあります。ページは`app/src/routes/`、各章の本文は`app/src/lib/content/{zh,ja,en}/`、デスクトップのシェルとRustで書いた学習データのモジュールは`app/src-tauri/`です。保守の説明は[文書一覧](docs/README.md)から読んでください。

直したら、`app/`で次のチェックを一通り実行します。

```bash
npm run check          # 型チェック
npm test               # 単体テスト
npm run content:check  # 3言語の章と出典が合っているか
npm run check:quiz     # 小テストの登録
npm run build
npx playwright install chromium   # 初めてブラウザテストを動かす前に一度だけ
npm run test:e2e       # ブラウザテスト
npm run test:e2e:pwa   # オフライン機能のテスト
```

Rustの部分は`app/src-tauri/`で`cargo test --locked -p study-core`を実行します。

毎回手で実行しなくても大丈夫です。`main`にプッシュしたときやPull Requestを出したときに、GitHubが全部自動で実行します。毎週月曜には、見直しの時期が来た章を一覧にして、出典のリンクが切れていないかも自動で確かめます。知らせるだけで、本文を勝手に変えることはありません。`v*`タグを付けると、Windows版を自動で作り、Windows上で実際にインストールと起動を確かめてからReleaseの下書きに置きます。公開するのは人が確認してからです。

## 使っている技術

画面はSvelte 5 + SvelteKit（静的なSPA）とTypeScript、デスクトップ版はTauri 2とRustです。Markdownは`marked`と`shiki`で表示しています。学習記録はWeb版ではlocalStorage、デスクトップ版ではSQLiteに保存します。自分で直した本文は、どちらもIndexedDBに入ります。
