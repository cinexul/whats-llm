第19章里我们认识了Agent：会“自己动手”的AI。这一章登场的**Claude Code**和**Codex**，就是专门干“编程”这件事的Agent——你用大白话交代一件事，它会**自己去读项目里的文件、改代码、运行命令**，而不只是给你一段文字让你复制粘贴。

先别因为“编程”两个字紧张。**这一章不要求你会写代码。** 我们要学的，是“怎么带着这样一个会动手的助手干活”——派什么活、怎么看它做得对不对、出了岔子怎么收场。这套工作流，懂电脑的普通人都学得会，而且学会之后，你对“让AI替你做事”会有一种全新的掌控感。

## 一、它们到底是什么

Claude Code和Codex不是某个固定的网页按钮，而是一类**会在你的项目上动手的编程智能体（coding agent）**。你通常会在**终端（命令行）、代码编辑器（IDE）、网页任务或云端环境**里接触到它们——**有的在你自己的机器上运行，有的在云端运行，具体形态各不相同、而且在更新，以官方文档/产品官方形态为准**。它们的共同点是：

- **能看见你的项目**：自己浏览文件夹、读代码，搞清楚现状——而不是只知道你贴给它的那几行。
- **能动手**：直接修改文件、运行命令（比如跑测试）、必要时联网查资料。
- **能连续干好几步**：朝着你给的目标，自己跑“看一看→改一改→试一试→再改”的循环。

> **要点：**Claude Code来自Anthropic、内核是Claude；Codex来自OpenAI——这两个“出品方／内核”的归属是稳定事实。但**它们的具体形态（CLI／IDE插件／网页／云端）、安装方式、命令、能力各不相同，而且都在快速更新**——所以本章不写“按哪个键、敲哪条命令、在哪运行”（那些易变，属第28、29章、附录C与官方文档的事）。本章讲的是它们**共享的那套干活方式**，学一次，两边通用、也不易过时。

## 二、和“网页聊天”的根本区别

| | 网页/App聊天（产品层） | 编程智能体（Agent层） |
| --- | --- | --- |
| 它怎么对待代码 | 给你一段文字，你自己复制去用 | **直接改你项目里的文件** |
| 它知道多少 | 只知道你贴进去的内容 | 自己**探索整个项目**来了解现状 |
| 推进方式 | 你问一句、它答一句 | 朝目标**自己连走好几步** |
| 出错的后果 | 顶多答得不对，你不用就行 | 它真的动了你的文件——**所以要能回滚** |

最后一行是关键：因为它**真的会动你的东西**，所以“在一个能反悔的环境里用它”不是讲究，是前提（下面第五节细说）。

## 三、心智模型：把它当“能干但刚入职的新同事”

整本书反复用这个比喻，到这里最贴切：**Claude Code / Codex就像一个很能干、手很快、但刚入职第一天的同事。**

- 他**手脚麻利**：交代的体力活做得又快又多。
- 他**不了解你的项目习惯**：不知道你们的规矩、命名、雷区——你得告诉他（第28章的“项目入职须知”就是干这个的）。
- 他**会自信地犯错**：可能用一个根本不存在的写法（这就是第9章的“幻觉”，写代码时照样发生）。
- 所以——**你是带他的人**。活儿可以交给他，但**派活和验收是你的责任，最终署名也是你的**。

> **要点：** 这句话请记一辈子：**“看不懂、没验证的东西，不要放行。”** 他做完不等于做对。你不必会写每一行，但你得能判断“这事儿成没成”——本章第四节的工作流，就是帮你把这份判断落到实处。

## 四、核心工作流：调查 → 计划 → 动手 → 验收

几乎所有顺利的任务，都走同一个四步循环。**中间两道“闸门”由人把守**，其余交给AI：

```text
   你给目标
      │
      ▼
 ①调查 ──→ ②计划 ──→【人批准】──→ ③动手 ──→ ④验收 ──→【人放行】
（它读项目） （它出方案）   ↑闸门1      （它改文件） （看diff/跑测试） ↑闸门2
```

**① 调查（它做，你看一眼）**
先别急着让它“开始改”。让它**先调查**：“要做这件事，相关的代码在哪几个文件？现在是怎么实现的？” 它会去翻项目、给你一份带位置的说明。你扫一眼，确认它没找错地方。
> 一句话指令示例：*“先别动手，只调查：要给页面加搜索框，涉及哪些文件、现在是怎么做的？”*

**② 计划（它做，你批准）——闸门1**
让它把“打算怎么改”先**写成计划**：动哪些文件、加不加新东西、分几步。**你读这份计划、批准了，它才开始动手。** 这一步花几十秒，却能挡掉绝大多数“跑偏了几十分钟”的返工。很多工具内置了“先出计划、批准再动手”的模式（第27章细讲；**具体叫法和开关以官方文档为准**）。

**③ 动手（它做，你随时可叫停）**
批准后它开始改。文件修改和命令执行是否需要逐次确认，取决于工具、沙箱和权限设置；**已经授权的操作可能自动执行**。开始前先确认允许的范围，删除、发布和外部发送等操作要按约定的审批规则处理（第26章）。觉得它走歪了，**随时打断**，把话说清楚再让它继续。

**④ 验收（你做）——闸门2**
这是**你最重要的一步**，就三个动作（第25章详解）：
- **看diff**：diff就是“改动前后的对比”，它会清楚标出“加了哪行、删了哪行”。你看它**到底改了什么**、有没有动到不该动的地方。
- **跑测试**：让它跑测试，确认**没把原来好好的功能弄坏**。
- **能不能讲清**：试着用一句话说“这段在干嘛”。说不上来，就回去问它“这段是干嘛的”——**看不懂别合并**。

> **为什么非得有这两道闸？** 因为编程智能体的两个特性叠在一起：**它会犯错 + 它能动手**。只要这两条同时成立，“动手前看计划、动手后验收”就不是可选项。把这两道闸守住，剩下的体力活尽管放心交给它。

## 五、第一次跑起来，该期待什么

降低一下预期，免得你被“理想中的AI”吓到或失望：

1. **先布置好“能反悔”的环境。** **当它在你本地项目上动手时**，务必在用**版本控制（Git）**管理的项目里、并**切一个新分支**再让它动手（还没用过Git的话，先看第26章的“Git最小起步”）。动手前还要保存现有工作，并为需要保留的文件提交或备份。**分支本身不是备份**：Git只能恢复已保存的版本，不能替你恢复未跟踪文件，也不能撤回邮件、部署或外部数据修改。（若你用的是网页/云端形态，平台通常有对应的隔离与回滚方式，以官方文档为准。）
2. **它会先“读一会儿”。** 它需要时间浏览项目，别以为卡住了。
3. **看清权限设置和确认内容。** 有些操作会请求确认，有些会在已授权范围内自动执行；不要把“没弹窗”当成“没有风险”。
4. **它可能会犯错、会跑偏。** 正常。这时候——**不要在一团乱里硬纠**。最干脆的止损是：**回滚到干净状态，开一个新对话，把“刚才踩的坑”作为前提重新交代**（第13、30章）。在乱掉的上下文里追着它一句句改，往往越改越糟。
5. **它不联网就不知道最新的东西。** 涉及很新的技术，记得在话里**说清版本**，或把资料贴给它（第9章的知识截止）。

> **实际会怎么遇到：** 新手最常见的翻车，是“让它一口气把一个大功能全做完”。改动一大，你根本没法逐行验收，出了问题也难回滚。**正确姿势是把任务拆小**——做一小块、验收一小块、提交一次，再做下一块（第27章）。小步慢跑，反而是最快的路。

## 六、安全与花费，从第一天就放心上

- **别把密钥/密码/真实个人信息**贴进对话或写进代码——它会被发出去（第37章）。
- **订阅套餐的使用额度与API按量计费要分开看。** 有些入口使用订阅额度，有些通过API或云平台按量计费，具体以账号、入口和官方说明为准。更长的上下文可能增加用量，但不能把每次聊天都换算成同一张token账单；任务聚焦仍有助于减少无效处理（第3、38章）。
- 它生成的代码**算你的责任**：合并前要复核、要为它负责（第39章）。

## 七、Claude Code与Codex：同在哪、不同在哪

| | 相同（本章重点，稳定） | 不同（**以官方文档为准**，会变） |
| --- | --- | --- |
| 定位 | 都是“会在你项目上动手”的编程智能体 | 出品方、内核模型、**运行形态（本地／云端／网页）**不同 |
| 工作流 | 都适用“调查→计划→动手→验收”循环 | 具体命令、快捷键、界面各异 |
| 安全 | 都该配许可机制 + 可回滚环境 | 默认行为、许可粒度不同 |
| 上手 | 都先在Git分支里小步试 | 安装方式、登录方式不同 |

> **要点：** 你在本章学到的工作流，**换哪个工具都管用**——因为它来自“会犯错的Agent该怎么带”这个不变的道理，而不是某个产品的按钮。具体到“怎么装、敲什么”，请看第28、29章和附录C，并**以官方文档为最新依据**。

## 八、常见误解，集中纠正

| 误解 | 实际 |
| --- | --- |
| 它是AI，写的代码应该对，直接合并 | 它会自信地写错；diff要看、测试要跑、看不懂别合并 |
| 让它一次把大功能全做完最省事 | 大改动难验收、难回滚；拆小、小步验收才最快 |
| 它记得我整个项目和昨天的对话 | 模型本体靠“每次读项目 + 这次的上下文”工作，默认没有跨对话记忆；不过很多工具在**产品层**提供“项目记忆”（如CLAUDE.md／项目上下文文件）让它跨会话记住项目规矩——那是产品功能、不是模型本体记忆（第9、28章） |
| 我不会编程就没法用 | 你不用会写每一行，但要会“派活 + 验收三问”；门槛在判断，不在敲代码 |
| 它跑偏了就追着它一直改 | 该回滚 + 开新对话重来；在乱上下文里硬纠往往更糟 |

## 小结

- Claude Code / Codex是一类**会在你项目里动手**的编程智能体；在终端、编辑器、网页还是云端使用，取决于产品，**具体形态各异、且在更新，以官方文档为准**。
- 和网页聊天的根本区别：它**直接改文件、自己探索项目、连走好几步**——所以必须在**能回滚**的环境里用。
- 心智模型：**能干但刚入职的新同事**；活能交给他，**派活与验收是你的责任**。
- 核心工作流是**调查 → 计划 →【人批准】→ 动手 → 验收 →【人放行】**，人把守两道闸：批准计划、验收变更（看diff、跑测试、讲得清）。
- 第一次用：先保存工作并切Git分支（Git的基本用法见第26章）、任务拆小、跑偏就回滚重来、密钥绝不外贴。
- 这套工作流**与具体工具无关**，因为它来自“会犯错的Agent该怎么带”——学一次，到哪都管用。

下一章（第25章）先学整套工作流里最该练熟的一步：看懂diff、跑测试、回滚和验收。安装和第一次实操放在第28、29章。

## 小测验

> 共6题，涵盖概念、误区、情景、操作四类。先自己想，再看引用块里的答案解析。

1. **[基础·概念题]** 编程智能体（如Claude Code / Codex）和网页聊天AI最根本的区别是？ <!-- quiz: q01 revision: 2 -->
   - A. 它用的模型更强大，所以回答更准确、也更少出错
   - B. 它能记住你的整个项目，换了对话也不会忘
   - C. 它只回答编程问题，其他领域的问题都不管
   - D. 它能直接读写项目文件、运行命令，不只给文字
   > **答案D。** 聊天AI是“你来回复制粘贴”；编程智能体是“它直接在你的项目里动手”。这正是它高效、也需要“许可机制”看着的原因。A、C把区别当成了模型强弱或话题范围；B混淆了模型和产品：模型本体没有跨对话记忆，所谓“项目记忆”是产品每次把文件重新放进上下文。

2. **[基础·概念题]** “调查 → 计划 → 动手 → 验收”这个循环里，人最关键的工作在哪一步？ <!-- quiz: q02 revision: 2 -->
   - A. 调查：亲自找出相关文件，再交给它去改
   - B. 动手：盯着它的每一处修改，一条条点确认通过
   - C. 批准计划，并在动手后看diff、跑测试
   - D. 写清目标就够了，后面几步都交给它自己
   > **答案C。** 让AI干活，人守两道闸：**动手前批准计划、动手后验收变更**。调查和动手这类体力活交给它（A、B），你只需扫一眼、随时能叫停；D则把两道闸都放掉了。

3. **[基础·误区题]** “它是AI，写的代码应该是对的，直接合并就行”——错在哪？ <!-- quiz: q03 revision: 2 -->
   - A. 它会自信地写错，看不懂、没验证的不该合并
   - B. 没有错，只要代码能运行起来，就说明它是对的
   - C. 错在没让它自己确认一遍“确实没有问题”
   - D. 错在没有全部重写，它写的代码总得人来改
   > **答案A。** 幻觉（第9章）在写代码时照样发生：编造不存在的函数、用错版本的写法。能运行不等于做对（B）；让它自己打包票也不算验证（C）；全部重写又走到了另一个极端（D）。diff要看、测试要跑、看不懂就先问清楚。

4. **[进阶·误区题]** “让它一次把整个大功能全做完，最省事”——为什么往往更费事？ <!-- quiz: q04 revision: 2 -->
   - A. 其实不会，大任务一次说清，反而省了来回沟通
   - B. 因为它一次只能改一个文件，大功能要分很多次
   - C. 改动越大越难逐行验收，出了错也难定位和回滚
   - D. 唯一的问题是大任务用的额度多，其他都一模一样
   > **答案C。** 大改动等于大盲区：diff看不完，错误混在一大坨改动里，回滚也不干净。把任务拆小、先看计划、小步验收，反而最快（第27章）。B不对，它能一次改很多文件，问题恰恰在这里；D只看到了额度，没看到验收和回滚的难处。

5. **[基础·情景题]** 你让它改代码，它跑偏了，越改越乱。最佳止损动作是？ <!-- quiz: q05 revision: 2 -->
   - A. 在同一个对话里一句句纠正，直到它改对为止
   - B. 回滚到干净状态，开新对话，说明踩过的坑
   - C. 让它在现有改动上再改一版，把错误覆盖掉
   - D. 删掉整个项目，从头让它重新生成一遍代码
   > **答案B。** 在乱掉的上下文里硬纠（A、C），往往越纠越歪。**回滚 + 重开一个带着教训的干净对话**，几乎总是更快（第13、30章）。提前提交或备份现有工作，才有可恢复的起点（Git的基本用法见第26章）；回滚时只退这次任务的修改，删项目（D）会连好的部分一起丢掉。Git也不能撤销外部操作。

6. **[进阶·操作/观察题]** 不必真装工具：找一段你看得懂的代码改动（或第25章的diff示例），练习只回答三个问题——**它改了什么？会不会弄坏别的？我能不能用一句话说清这段在干嘛？** 第三个答不上来，就该回去问“这段是干嘛的”。 <!-- quiz: q06 revision: 2 -->
   > **该观察到：** “验收”不神秘，就是这三问。养成“看不懂就别放行”的肌肉记忆，比会任何命令都重要。具体工具的安装与命令**以官方文档为准**（见第28、29章与附录C）。
