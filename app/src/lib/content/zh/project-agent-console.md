前面三个项目（第31～33章），AI基本是你说一句、它做一句。这一章换个做法：给它一个目标和一套流程，让它自己连着跑好几步，你在旁边看它按“调查→计划→动手→验收”往前推进，只在关键处出手。做完你会得到三样东西：一张“必停清单”，一份它写好、你核对过的摘要文件`summary.md`，以及一次亲眼确认：它要写文件时，确实先停下来问了你。

这是第19章那个“会动手的AI”第一次真正交到你手上。正因为它会动手，这一章先练刹车。刹车有两层：第一层是工具的**权限设置**（只读、改动前先问你之类），它能真正拦住操作；第二层是你写在提示词里的规矩，它让Agent晓得该在哪停下来问你，但拦不住它真去做。

## 一、准备

- 挑一个多步、但每步都不危险的小目标。第一次就用这个：读一个文件夹里的三份文档，各写一句话摘要，汇总成一张清单。它要好几步（列出文件、逐个读、逐个总结、汇总），但不删东西、不发东西、不花钱。别第一次就让它“清理我的邮箱”“自动回复客户”，那等于把新手司机直接送上高速。
- 想清楚拆成哪几步。你自己说不清的流程，没法交给它跑（第14章）。
- 准备一个能反悔的环境：一个单独的练习文件夹，里面只放文档的副本，并用Git管起来（第26章）。用平台自带的Agent时，看它提供什么样的隔离环境。
- 列一张“必停清单”：哪几步必须你点头才能做。第2步教你列。

## 二、一步步做

### 第0步：最小可跑路径——用编程智能体，先把权限收紧

你不需要另外搭平台：编程智能体本身就会连跑多步，你和它对话的界面，就是你看它做事、随时叫停的地方。第一次按下面做：

1. 建一个练习文件夹，比如`agent-practice`，放进三份短文档的副本（每份一两页，别放原件），按第26章初始化Git并提交一次，作为起点。
2. 在这个文件夹里启动编程智能体（第28、29章），先问它“你现在在哪个文件夹里”，确认没走错。
3. 把权限调到“改动之前先问我”。截至2026年10月：Claude Code从v2.1.283起，在终端和VS Code里默认以自动模式（auto）启动，由另一个模型审查操作，通常不弹确认，所以要先换掉。可以用`claude --permission-mode manual`启动，或者启动后按`Shift+Tab`，直到状态栏显示“manual mode on”。手动模式下，它读文件不用问，改文件、跑大多数命令、联网之前都会先问你。Codex在用Git管理的文件夹里默认是能直接改文件的Auto模式，用`/permissions`换成Read Only：能读当前文件夹里的文件，改文件或联网都要你批准。这些名称和入口会随版本变。
4. 不接能发送或删除的工具。这次用不到邮箱、聊天、云盘、日历这类外部工具。在会话里输入`/mcp`看看当前接了哪些（MCP见第22、36章）；能替你发消息、删东西、花钱的，先停用，或换一个没接它们的环境。

这样跑，它想改任何东西都要先问你，你在弹出的确认里选拒绝就好。

### 第1步：用大白话给它一个目标 + 一套流程

别只丢一个目标就撒手，把“按什么步骤走”也交代清楚：

```text
目标：给这个文件夹里的三份文档各写一句话摘要，汇总成一张清单。

请按这个流程走：
① 先调查：列出文件夹里有哪几份文档，先别往下做，给我看一眼。
② 等我说"继续"，再逐个读、逐个写一句话摘要。
③ 把汇总清单直接写在对话里，先不要存成文件。

规则：
- 不许删除或修改任何已有文件，不许把任何内容发出去。
- 拿不准的地方别替我猜，停下来问我。
```

这段话有一半篇幅在说“不许做什么”和“在哪停”，这是刹车的第二层。真正拦得住它的，是第0步的权限设置。

### 第2步：先列“必停清单”——这章的核心

按下开始之前，先把下面这类动作标成“必须人工确认”。判断标准就一句：这一步能撤回吗？有没有后果？

| 可以让它自己做的 | 必须停下来等你点头的 |
| --- | --- |
| 读文件、整理、归类、生成草稿、列清单 | 花钱：调用按次收费的服务、下单、扣额度 |
| 在几个无关紧要的小选项里挑一个 | 删数据或覆盖：删除、清空、改写你的原始文件 |
| 做完一步、汇报一下再做下一步 | 对外发送：发邮件、提交、发布、调用外部接口 |
| 把内容从一种形式换成另一种 | 它拿不准、需要你来判断的 |

这张清单靠两层落实。第一层交给工具：右边这些动作用权限设置拦住，能发送、能删除、能花钱的工具第一次干脆不接。第二层才是提示词里的规矩。第26章讲过，没有弹出确认不代表操作无害；附录C也提醒过，写在Markdown文件或提示词里的一句话，代替不了系统层面的强制限制。清单和权限都要在它动手之前定好，不是等它闯了祸再补。

### 第3步：让它跑，你盯着“调查→计划→动手→验收”的过程

按下开始后别走开，第一次要把每一步看在眼里：

- 看它的“调查”对不对：找对文件了吗？理解对目标了吗？第一步歪了，后面会在错的前提上越做越工整（第14章）。
- 看它列完文档后有没有停下来等你说“继续”。
- 看必停点有没有真的拦住它：在手动模式或Read Only下，它想改文件、跑会改东西的命令时，工具会先弹出确认。如果它没问你就做了改动，说明权限设得太松，或者接了不该接的工具，跟提示词写得严不严无关。立刻中断，按第30章盘点和恢复，收紧权限再跑。
- 觉得它跑偏了，随时打断，说清楚再让它继续；或者退回干净状态重来。

### 第4步：验收，再批准一次写入

一轮跑完，按第25章的“验收三问”来：

1. 它到底做了什么？不只看最终清单，还要看它中途碰了哪些东西。让它运行`git status`给你看（一条只读的Git命令，列出文件夹里有哪些改动），应该没有任何改动。
2. 该停的地方停了吗？列完文档它有没有等你说“继续”？中途有没有出现你没批准的写入、删除、发送？这一条比结果漂不漂亮更要紧。
3. 结果你能不能信？挑两条摘要对照原文抽查，它的自检不能全信（第14章）。

都没问题，再让它把清单存下来：

> 大白话请求：*“清单我核对过了。请把它存成这个文件夹里的新文件`summary.md`，别的文件一个都不要动。”*

这时它会先弹出确认，问你是否允许创建这个文件。看清文件名和内容再批准。存好后再看一次`git status`：应该只多出一个未跟踪（Untracked）的`summary.md`，没有任何已有文件被修改。这一步让你亲眼看到刹车怎么工作：它停下来说清要做什么，由你决定放不放行。

### 完成标准

下面几条都做到了，这个项目就算完成：

- 它是在只放副本的练习文件夹里、用手动模式或Read Only跑的，没有接能发送或删除的工具。
- 它先列出了三份文档，并停下来等你说“继续”。
- 你抽查了至少两条摘要，和原文对得上。
- 它创建`summary.md`之前问过你；你批准后，`git status`里只多出这一个新文件。
- 全程没有出现你没批准的写入、删除或发送。

## 三、常见问题

| 问题 | 怎么回事 / 怎么避免 |
| --- | --- |
| 一上来就给它不可逆的大活 | 删邮件、发消息、动钱，出事就是真出事。先用不发、不删、只在最后写一个新文件的目标练手 |
| 只靠提示词当刹车 | 提示词里写了“删之前先问我”，却给了它能删、能发的权限和工具，它可能照样做。先收紧权限、不接危险工具，提示词是第二层 |
| 以为默认设置会先问你 | 新版Claude Code默认是自动模式；Codex在Git管理的文件夹里默认也能直接改文件。第一次跑之前，确认状态栏或`/permissions`里的模式 |
| 按下开始就走开 | 第一次必须全程盯着，尤其看它到必停点有没有被拦住（第19章） |
| 把“它说检查过了”当成真检查过 | 它的自检也还是在“接话”，关键信息自己再核（第14章） |
| 跑偏了还在乱局里硬纠 | 退回干净状态、开个新对话，把刚才碰到的问题作为前提重讲（第13、30章） |
| 以为步数越多越强 | 一口气跑十几步，你没法逐步把关。步子小一点、节点密一点，反而更稳 |

## 四、可以再往前一步

每往前一步，都重新问一遍“刹车够不够”：

- 给它接一两个工具或数据源（MCP，第22、36章）。每接一个新能力，就多一个出错和被攻击的入口，要按需接、先只给读的权限。
- 把常跑的流程固化成技能（Skills，第22、36章），下次一句话调用。
- 逐步放宽权限，但要克制：只有对某一步彻底有把握、而且它可逆时，才让它不问你就做。花钱、删数据、对外发送这三类，建议一直留在必停清单里。
- 写一份“它该怎么做事”的说明：把规矩、能碰和不能碰的东西写进项目说明文件（第28章）。模型本身记不住上一次对话，是产品每次开工都把这份文件放回上下文，它才“记得”这些规矩。

<aside data-callout="gift">

**附送一份小礼物：** 等你开始让编程智能体写真正的程序，可以把下面这段放进项目说明文件（`CLAUDE.md`或`AGENTS.md`，第28、29章）。这段话是写给AI看的，你不必每条都懂：它请AI从一开始就把代码写得清楚、好改，少留以后难收拾的乱子。它代替不了验收（第25章），AI也不保证条条照做，但通常能省下不少返工。

```text
写代码时，请一直守住这些原则：
1. 动手前先读懂现有结构和相关代码，沿用项目已有的技术栈、命名和分层，不重复实现已有的功能。
2. 模块之间通过清楚的接口和类型协作，不依赖隐藏的全局状态、调用顺序或别的模块的内部实现。
3. 用类型和数据结构排除不合理的状态，比如互斥的几种状态，不要用几个各自独立的开关来表示。
4. 同一条业务规则只放在一个地方；需求变了，改动应该集中在相关模块里。
5. 每个模块只管一件主要的事。真正相同、会一起变化的逻辑才合并，表面相似的不要硬凑。
6. 不为想象中的未来需求加抽象层、只转发参数的包装函数或设计模式，先用能满足当前需求的简单做法。
7. 外部输入和接口返回在系统边界验证，不拿前端验证代替后端验证；错误要处理或报告，不要悄悄吞掉。
8. 先做出能运行、能验证的最小版本，再逐步完善；临时验证用的代码和正式实现要分开。
9. 每做完一块，检查有没有引入上面这些问题，并运行类型检查和测试。
10. 改动控制在任务范围内；需要较大重构时，先说明原因和影响，等我确认。规则不明确的地方，写明你的假设，不要擅自定成正式实现。
```

## 小结

- 这个项目让你第一次带一个会自己连跑多步的Agent（第19章），练的是“跑得住”，不是“跑得猛”。
- 最小路径：练习文件夹只放副本、用Git起步；权限调到手动模式或Read Only（新版Claude Code默认是自动模式，要先切换）；不接能发送或删除的工具。
- 刹车分两层：工具的权限设置是第一层，提示词里的规矩是第二层。它没问你就做了改动，说明权限太松，收紧再跑。
- 过程中盯着“调查→计划→动手→验收”；验收看它做了什么、该停的地方停没停、结果能不能信，最后亲手批准一次写入，用`git status`确认只多了`summary.md`。
- 花钱、删数据、对外发送这三类动作，建议一直设成必须人工确认（第14、19、26章）。

## 小测验

> 共6题，涵盖概念、误区、情景、操作四类。答案与解析在每题下方的引用块里——先自己想，再对照。

1. **[基础·概念题]** 让Agent连跑一个多步任务，和前几个项目里“你问一句它答一句”最根本的区别是？ <!-- quiz: q01 revision: 3 -->
   - A. 它背后的模型更强，所以能处理更难的问题
   - B. 它会自己连跑多步，你只在关键处把关
   - C. 它的界面功能更完整，能同时看到更多信息
   - D. 它会自己检查结果，所以基本不会出错了
   > **答案B。** Agent的要害是“会自己往前走一段”（第19章），而不是更聪明或更不会错。正因为它自己跑、还可能不停下来问你，这一章才把“装刹车”放在第一位。A和C说的模型、界面都不是区别所在；D正相反，它的自检不可全信（第14章）。

2. **[基础·概念题]** 这一章反复强调的“刹车”（必停清单），本质是什么？ <!-- quiz: q02 revision: 3 -->
   - A. 在提示词里写清“不许删、不许发”，它就会照做
   - B. 让Agent每一步都慢下来，给你更多反应时间
   - C. 预先把删除、发送、花钱等步骤设成要你确认
   - D. 出问题时用来强行关掉Agent的停止按钮
   > **答案C。** 刹车不是拖慢它，而是**圈定安全范围**：范围内放手跑，碰到不可逆、有后果的动作就必须停下等你点头。落实时先靠工具的权限设置（手动模式或只读，不接能发送或删除的工具），提示词里的规矩是第二层。A就是只靠第二层，它可能照样做；B和D都没回答“哪些步骤必须经过你”。

3. **[基础·误区题]** “我把目标交代清楚、按下开始，就可以去忙别的了”——第一次搭Agent时，这个想法错在哪？ <!-- quiz: q03 revision: 3 -->
   - A. 第一次得全程盯着，看必停点拦没拦住它
   - B. 错在目标给得太笼统，写细了就能放心离开
   - C. 没问题，只要在提示词里写了“遇事先问我”
   - D. 错在没开最高权限，它会卡在半路等你确认
   > **答案A。** Agent会自己跑没错，但它碰到必停点时有没有被拦下、有没有先来问你，要你亲眼确认过才放心。如果它没问你就做了不可逆的事，说明权限设得太松，要立刻中断。B和C都以为说清楚、写进提示词就能撒手；D正好反过来，第一次就该用最紧的权限，等它来问你恰恰是你想要的。

4. **[进阶·情景题]** 你让Agent帮你整理一个客户资料文件夹。下面哪一步**最该**被设成“必须停下来问你”？ <!-- quiz: q04 revision: 2 -->
   - A. 把资料从表格整理成一段文字说明
   - B. 把客户资料按公司名称重新排一遍序
   - C. 把几张表格统一整理成同一种格式
   - D. 直接删掉它认定重复的客户记录
   > **答案D。** 删除是**不可逆**且有重大后果的动作，正是必停点。A、B、C都是范围内可以放手的低风险整理（前提是结果另存、原件不动）。区分标准始终是：这一步可逆吗、有没有后果（呼应第14章）。

5. **[进阶·情景题]** Agent跑到一半明显跑偏了，越做越乱。最佳止损动作是？ <!-- quiz: q05 revision: 2 -->
   - A. 就在当前对话里一句一句追着纠正它
   - B. 先让它把这一轮做完，最后再统一改
   - C. 中断、回滚，开新对话把前提重讲一遍
   - D. 把权限放宽一些，让它自己把乱局收拾好
