前面三个项目（第31、32、33章），AI基本是“你说一句、它做一句”地陪着你干。这一章我们换个玩法：搭一个**Agent控制台**——给它一个目标和一套流程，让它**自己连着跑好几步**，你坐在旁边看它按“调查→计划→动手→验收”往前推进，只在关键处出手。

这正是第19章那个“会动手的AI”第一次真正落到你手上。也正因为它会动手，这一章的重头戏不是“怎么让它跑得更猛”，而是反过来——**先给它装好“刹车”**。刹车分两层：第一层是工具本身的权限设置（只读、先出计划、每一步都问你），这一层才真正拦得住它；第二层是你写在提示词里的规矩，它帮Agent知道该在哪停下来问你，但拦不住它真去做。搭一个能放心用的Agent，难的不是让它跑，而是想清楚**哪几步绝不能让它自己做主**，再用这两层把它们管住。

> 〔本章讲的是“怎么带一个会自己跑的Agent”这套通用做法，练习时用编程智能体（如Claude Code或Codex）当例子，但不绑定某个产品。具体在哪个产品、用什么界面、怎么配权限和工具，各家不同且更新很快，一律**以官方文档为准**。〕

## 一、准备

动手前，先把“我到底要搭个什么”想明白，别上来就堆功能。

- **挑一个“多步、但每步都不危险”的小目标练手。** 第一次搭Agent，目标要小、要安全。好例子：让它“读一个文件夹里的几份文档，各写一句话摘要，汇总成一张清单”——这需要好几步（逐个读、逐个总结、最后汇总），但**每一步都不删东西、不发东西、不花钱**。坏例子：让它“自动清理我的邮箱”“自动回复客户”——第一次就碰这种不可逆的活，等于把新手司机直接扔上高速。
- **想清楚这件事拆成哪几步。** 你得先在脑子里（或纸上）把目标拆成“调查→计划→动手→验收”的几步。你自己都说不清的流程，没法交给它跑（这是第14章那个工作流循环的实战版）。
- **准备好一个“能反悔”的环境。** Agent会真的动手，所以**它能碰到的东西，最好都是能恢复的**。涉及本地文件，就在一个单独的练习文件夹里试，里面只放文档的**副本**，并用Git管起来（第26章的“Git最小起步”）；用平台自带的Agent，则看它提供的隔离/沙箱方式——**以官方文档为准**。
- **最重要的一件事：列一张“必停清单”。** 在让它跑之前，先把“哪几步必须我点头才能做”写下来。这张清单是这一章的灵魂，下面第二节会手把手教你列，并告诉你怎么用权限设置把它落实。

> **要点：** 搭Agent的准备工作，一半是技术（环境、权限、工具），另一半是**判断**（目标够不够安全、流程拆没拆清、刹车列没列全）。后面这一半，才是真正决定你会不会翻车的地方。

## 二、一步步做

下面这套流程不依赖某个具体产品，第0步用编程智能体给出一条最小可跑的路径。你用别的平台，把同样的思路套进去即可（具体按钮、命令**以官方文档为准**）。

### 第0步：最小可跑路径——用编程智能体，先把权限收紧

这一章的“控制台”不需要你另外搭平台：一个编程智能体本身就是会连跑多步的Agent，你和它对话的那个界面，就是你的控制台。第一次按下面做：

1. **建一个练习文件夹。** 比如叫`agent-practice`，往里放三份短文档的**副本**（每份一两页就够，别放原件），然后按第26章初始化Git、做一次提交，当作起点。
2. **在这个文件夹里启动编程智能体。** 打开文件夹，或在终端`cd`进去再启动，取决于产品（第28、29章）。启动后先问它“你现在在哪个文件夹里”，确认没走错。
3. **把权限调到最紧。** 第一次只用只读、计划模式，或“每一步都先问我”的设置。截至2026年10月的例子：Claude Code可以用`/plan`（或按`Shift+Tab`切换）进入计划模式，这时它只读文件、出计划，不改你的文件；它默认的手动模式下，改文件、跑命令前也会先问你。Codex可以用`/permissions`选“Read Only”（只读：改文件或联网都要你批准），也有`/plan`计划模式。名称和入口会变，以官方文档为准。
4. **不接能发送或删除的工具。** 这次练习用不到邮箱、聊天、云盘、日历这类外部工具。用`/mcp`看看当前接了哪些（第22、36章讲MCP）；能替你发消息、删东西、花钱的，先停用，或换一个没接它们的环境。
5. **把第1步那段“目标 + 流程 + 规矩”贴给它**，并让它把汇总清单**直接写在对话里**，不要存成文件。这样整个任务在只读权限下就能完成。

这样跑，就算它想越界，工具也会拦下或先来问你；你只要在弹出的确认里选“拒绝”。

### 第1步：用大白话给它一个目标 + 一套流程

别只丢一个目标就撒手。把“按什么步骤走”也一起交代清楚。一个面向非程序员的请求大概长这样：

```text
目标：把这个文件夹里的几份文档，各写一句话摘要，汇总成一张清单。

请按这个流程走：
① 先调查：列出文件夹里有哪几份文档，先别动手，给我看一眼。
② 再逐个读、逐个写一句话摘要。
③ 最后把汇总清单直接写在对话里交给我，不要存成文件。

规则（很重要）：
- 你只能"读"和"在对话里写清单"，不许删除、不许修改任何文件、不许把任何东西发出去。
- 调查完先停下来给我看清单对不对，等我说"继续"再往下做。
- 任何拿不准的地方，别替我猜，停下来问我。
```

注意这段话里，**一半篇幅在说“不许做什么”和“在哪停”**。这是刹车的第二层：它让Agent知道在哪停下来问你。真正拦得住它的，是第0步那层权限设置。

### 第2步：先列“必停清单”——这章的核心

在你按下“开始”之前，把下面这类动作**预先**标成“必须人工确认”。判断标准只有一句话：**这一步可逆吗？有没有后果？**

| 可以让它自己做的 | 必须停下来等你点头的 |
| --- | --- |
| 读文件、整理、归类、生成草稿、列清单 | **花钱**：调用按次收费的服务、下单、扣额度 |
| 在几个无关紧要的小选项里挑一个 | **删数据 / 覆盖**：删除、清空、改写你的原始文件 |
| 做完一步、汇报一下再做下一步 | **对外发送**：发邮件、提交、发布、对外调用接口 |
| 把内容从一种形式换成另一种 | **它拿不准、需要你拍板**的判断 |

这张清单要靠两层落实。第一层交给工具：用权限设置让右边这些动作必须经过你，能发送、能删除、能花钱的工具第一次干脆不接。第二层才是写进提示词的规矩。第26章讲过，没有弹出提示不代表操作无害；附录C也提醒过，Markdown文件或提示词里的一句话，不能替代系统层面的强制限制。这张表就是第14章“握着刹车”和第26章“许可机制”在项目里的落地。**列清单、调权限的时机都在它动手之前，不是等它闯了祸再补。**

### 第3步：让它跑，你盯着“调查→计划→动手→验收”的过程

按下开始后，**别走开**。Agent的价值是它自己往前跑，但你第一次用，要把它跑的每一步看在眼里：

- **看它的“调查”对不对**：它有没有找对文件、理解对目标？第一步就歪了，后面会在错的前提上越做越“工整”（第14章讲过这个坑）。
- **看必停点有没有真的拦住它**：在只读或计划模式下，它想改文件、跑会改东西的命令时，工具会拦下或先弹出确认，你选拒绝就行。如果它没问你就做了不可逆的事，说明权限设得太松，或者接了不该接的工具，这不是提示词写得不够狠的问题：立刻中断，按第30章盘点和恢复，下次先把权限收紧再跑。
- **觉得它跑偏，随时打断**：把话说清楚，再让它继续；或者干脆退回干净状态重来。

### 看结果 / 验收

一轮跑完，按这三条验收（思路来自第25章的“验收三问”）：

1. **它到底做了什么？** 不只看它给的最终清单，还要看它中途碰了哪些东西——有没有动到你没让它动的地方。在练习文件夹里看一眼`git status`（或请它运行这条只读命令给你看），应该没有任何改动。
2. **该停的地方停了吗？** 回头确认：调查完它有没有停下来等你说“继续”；中途有没有出现你没批准的写入、删除、发送。这一条比结果漂不漂亮更重要。
3. **结果你能不能信？** 它生成的摘要，关键信息自己抽查几条——它的自检不可全信（第14章），漂亮不等于对。

### 完成标准

下面几条都做到了，这个项目就算完成：

- 它是在练习文件夹里、用只读 / 计划 / 逐步询问的权限跑的，没有接能发送或删除的工具。
- 它先列出了文件夹里的文档，并停下来等你说“继续”。
- 三份文档各有一句摘要，汇总清单出现在对话里。
- 你抽查了至少两条摘要，和原文对得上。
- 练习文件夹里的文件没有被改动（`git status`看不到改动）。
- 全程没有出现你没批准的写入、删除或发送；它想越界时，是被权限设置拦下或先来问你的。

## 三、常见坑

| 坑 | 怎么回事 / 怎么躲 |
| --- | --- |
| **一上来就给它“不可逆”的大活** | 第一次就让它删邮件、发消息、动钱——出事就是真出事。先用“只读不写”的安全目标练手 |
| **只靠提示词当刹车** | 光在提示词里写“删之前先问我”，却给了它能删、能发的权限和工具——它可能照样做。先用只读 / 计划 / 逐步询问的权限，不接能发送或删除的工具；提示词里的规矩是第二层 |
| **按下开始就走开** | Agent会自己跑，但第一次用必须全程盯着，尤其盯它“到必停点有没有被拦住”。撒手不管正是第19章反复警告的危险用法 |
| **把“它说检查过了”当成真检查过** | 它的自检还是在“接话”，不是真有一双客观的眼睛（第14章）。关键信息自己再核 |
| **跑偏了还在乱局里硬纠** | 越纠越歪。干脆**退回干净状态、开个新对话**，把“刚才踩的坑”作为前提重讲（第13、30章） |
| **以为“步数越多 = 越强”** | 让它一口气跑十几步，你根本没法逐步把关。**步子迈小一点、节点设密一点**，反而更稳 |

## 四、可以再往前一步

把第一个安全的小Agent跑顺之后，可以这样**谨慎地**扩展——每一步都要重新问“刹车够不够”:

- **给它接一两个工具或数据源**（用第22章的MCP/Skills思路），让它能读更多东西、做更多事。但记住第22章和第36章反复讲的：**每接一个新能力，就多一个出错和受攻击的入口**，要按需接、最小化接，先只给读的权限。
- **把你常跑的流程固化下来**：如果某套“调查→计划→动手→验收”你反复要用，可以把它打包成一个固定流程（Skills的思路，第22、36章），下次一句话调用。
- **逐步放宽权限——但要非常克制**：只有当你对某一步的安全性彻底有把握、且它真的可逆时，才考虑让它不问你就做。**涉及花钱、删数据、对外发送的那几条，建议一直留在“必停”里**，无论你多熟。
- **写一份“它该怎么干活”的说明**：把这个项目的规矩、雷区、它能碰和不能碰的东西写进项目说明文件（项目上下文的思路，第28章）。模型本身记不住上一次对话，是产品每次开工都把这份文件重新放进上下文，它才“记得”这些规矩。

> **要点：** 搭Agent控制台，真正的功夫不在“让它能干多少事”，而在**你提前想清楚了哪几步不能让它自己做主，并用权限设置把它们拦住**。能力是它带来的，安全是你设计出来的。先装刹车再给油门：花钱、删数据、对外发送这三类动作，始终先问过你。

## 小结

- 这个项目让你第一次真正带一个**会自己连跑多步的Agent**（第19章），核心练的不是“让它跑猛”，而是“让它跑得住”。
- 最小可跑路径：一个练习文件夹（只放副本、用Git起步），在里面启动编程智能体，**权限先调到只读 / 计划 / 逐步询问**，不接能发送或删除的工具，让它把结果写在对话里。
- 刹车分两层：**工具的权限设置是第一层**，提示词里的规矩是第二层。它没问你就做了不可逆的事，说明权限太松，要先收紧再跑。
- 做的时候：用大白话给目标 + 流程 + 规矩，盯着它“调查→计划→动手→验收”的过程。验收三问：它到底做了什么、该停的地方停没停、结果能不能信。
- **花钱、删数据、对外发送**这三类不可逆动作，建议一直设成“必须人工确认”（呼应第14、19、26章）。具体平台与配置**以官方文档为准**。

1. **[基础·概念题]** 搭一个Agent控制台，和前几个项目里“你问一句它答一句”最根本的区别是？ <!-- quiz: q01 revision: 2 -->
   - A. 它背后的模型更强，所以能处理更难的问题
   - B. 它会自己连跑多步，你只在关键处把关
   - C. 它的界面功能更完整，能同时看到更多信息
   - D. 它会自己检查结果，所以基本不会出错了
   > **答案B。** Agent的要害是“会自己往前走一段”（第19章），而不是更聪明或更不会错。正因为它自己跑、还可能不停下来问你，这一章才把“装刹车”放在第一位。A和C说的模型、界面都不是区别所在；D正相反，它的自检不可全信（第14章）。

2. **[基础·概念题]** 这一章反复强调的“刹车”（必停清单），本质是什么？ <!-- quiz: q02 revision: 2 -->
   - A. 在提示词里写清“不许删、不许发”，它就会照做
   - B. 让Agent每一步都慢下来，给你更多反应时间
   - C. 预先把删除、发送、花钱等步骤设成要你确认
   - D. 出问题时用来强行关掉Agent的停止按钮
   > **答案C。** 刹车不是拖慢它，而是**圈定安全范围**：范围内放手跑，碰到不可逆、有后果的动作就必须停下等你点头。落实时先靠工具的权限设置（只读、计划、逐步询问，不接能发送或删除的工具），提示词里的规矩是第二层。A就是只靠第二层，它可能照样做；B和D都没回答“哪些步骤必须经过你”。

3. **[基础·误区题]** “我把目标交代清楚、按下开始，就可以去忙别的了”——第一次搭Agent时，这个想法错在哪？ <!-- quiz: q03 revision: 2 -->
   - A. 第一次得全程盯着，看必停点拦没拦住它
   - B. 错在目标给得太笼统，写细了就能放心离开
   - C. 没问题，只要在提示词里写了“遇事先问我”
   - D. 错在没开最高权限，它会卡在半路等你确认
   > **答案A。** Agent会自己跑没错，但它碰到必停点时有没有被拦下、有没有先来问你，得你亲眼确认过才放心。如果它没问你就做了不可逆的事，说明权限设得太松，要立刻中断。B和C都以为说清楚、写进提示词就能撒手；D正好反过来，第一次就该用最紧的权限，等它来问你恰恰是你想要的。

4. **[进阶·情景题]** 你让Agent帮你整理一个客户资料文件夹。下面哪一步**最该**被设成“必须停下来问你”？ <!-- quiz: q04 revision: 2 -->
   - A. 把资料从表格整理成一段文字说明
   - B. 把客户资料按公司名称重新排一遍序
   - C. 把几张表格统一整理成同一种格式
   - D. 直接删掉它认定重复的客户记录
   > **答案D。** 删除是**不可逆**且有重大后果的动作，正是必停点。A、B、C都是范围内可以放手的低风险整理（前提是结果另存、原件不动）。区分标准始终是：这一步可逆吗、有没有后果（呼应第14章）。

5. **[进阶·情景题]** Agent跑到一半明显跑偏了，越做越乱。最佳止损动作是？ <!-- quiz: q05 revision: 2 -->
   - A. 就在当前对话里一句一句追着纠正它
   - B. 先让它把这一轮做完，最后再统一改
   - C. 中断、回滚，开新对话把前提重讲一遍
   - D. 把权限放宽一些，让它自己把乱局收拾好
