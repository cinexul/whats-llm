Claude Code是Anthropic的编程智能体，可以探索项目、修改文件、运行命令，也能协助Git操作。它有终端、编辑器插件、桌面应用和网页等入口；本章以终端为例，完成一次具体的入门练习。

本章的安装方式、账号要求和命令核查于2026-10-29。动手前先记下你装的版本，老教程里的安装方式或界面可能已经变了。

## 一、安装并打开一个小项目

先确认账号。截至2026年10月，Claude Code需要Pro、Max、Team、Enterprise套餐或Console（API）账号，免费的claude.ai套餐不包含它；也可以通过Amazon Bedrock等第三方云平台使用。不习惯终端的话，可以改用官方的桌面应用（macOS、Windows、Linux），下载入口在安装文档里。

官方推荐原生安装器，装好后会在后台自动更新。macOS、Linux（以及Windows的WSL）：

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows的PowerShell（CMD也有对应的命令）：

```powershell
irm https://claude.ai/install.ps1 | iex
```

这两条命令都会下载并执行安装脚本，请确认地址来自官方，并遵守所在组织的规定。在Windows上，建议再装Git for Windows（见第26章），Claude Code就能运行Bash命令；不装也能用，它会改用PowerShell。

也可以用包管理器：Homebrew的`brew install --cask claude-code`，或WinGet的`winget install Anthropic.ClaudeCode`。这两种方式默认不自动更新，要定期运行`brew upgrade claude-code`或`winget upgrade Anthropic.ClaudeCode`。选一种就好。旧教程里的`npm install -g @anthropic-ai/claude-code`已被官方README标为弃用。

装好后打开一个新的终端窗口，确认命令可用，再进入练习项目。下面的`git`命令需要先装好Git；项目还没交给Git管理的话，先按第26章“Git最小起步”存一个起点：

```bash
claude --version
claude --help
cd /path/to/your/project
git status
git switch -c practice/claude-first-task
claude
```

把路径换成真实目录。`git status`确认没有未保存的修改，`git switch -c`新建一个练习分支。第一次运行`claude`时按浏览器提示登录，之后用`/status`查看版本、模型和当前账号。安装出了问题，运行`claude doctor`看诊断信息。

## 二、先调查，再完成一个修改

一个合适的初次请求：

```text
阅读项目指引和README。说明项目做什么、入口在哪里、
现有检查怎样运行。先不要修改，建议一处很小的文档改进。
```

看回答有没有引用真实的文件和命令，再授权修改：

```text
完成刚才的文档改进，控制改动范围。
查看diff并做相关检查。报告修改的文件、实际运行的命令
以及还没解决的问题。不要推送或部署。
```

然后按第25章验收：让它用大白话解释`git diff`里的每处改动，你对照着看。改的是功能，还要运行相应测试，并亲手试一遍修改后的行为。

## 三、项目指引、记忆和技能不是一回事

`CLAUDE.md`保存项目约定、常用命令和限制，每次会话开始时被放进上下文。`/init`可以帮你起草，但生成后要自己检查。一个小例子：

```markdown
# 项目指引
- 改变行为前，先读README和现有实现。
- 使用仓库文档规定的包管理器和测试命令。
- 除非任务要求，不要手工修改生成文件。
- 示例使用虚构数据。
- 说明验证了什么，以及仍有哪些不确定性。
```

核对过实际命令后，再把泛泛的要求换成具体命令。别把完整手册或密钥塞进来。

| 机制 | 保存什么 | 怎样对待 |
| --- | --- | --- |
| `CLAUDE.md`与项目规则 | 在这个项目里工作的明确要求 | 像其他项目文档一样审查和更新 |
| 自动记忆（启用时） | 产品从以往工作中保存的笔记 | 查看并纠正，旧的观察可能已经过时 |
| Skills | 可复用的流程，可附带脚本或参考文件 | 核对来源，任务匹配时使用 |
| 当前对话 | 这次任务的要求、证据和进度 | 换会话时交接关键状态 |

`/memory`可以编辑`CLAUDE.md`、开关和查看自动记忆。这些都是产品把保存的文字重新放进上下文，模型本身并没有“学会”你的项目；记忆里的说法也不会因此自动变成事实。

## 四、按用途认识几个命令

下面的会话内命令截至2026年10月都可用；输入`/`就晓得你的版本实际有哪些。

| 会话内命令 | 用途 |
| --- | --- |
| `/help` | 查看可用命令 |
| `/status` | 查看版本、模型、账号和连接状态 |
| `/plan` | 进入计划模式：先出方案，不改文件（第27章） |
| `/permissions` | 查看或调整允许、询问、拒绝的规则 |
| `/memory` | 编辑`CLAUDE.md`，管理自动记忆 |
| `/diff` | 查看工作区的改动，包括它刚才做的修改 |
| `/code-review` | 审查当前diff里的正确性问题（别名`/review`） |
| `/rewind` | 把对话和它改过的文件退回之前的检查点（输入框为空时按两次Esc也可以） |
| `/usage` | 查看本次会话的用量和套餐额度（别名`/cost`） |

两点提醒。`/rewind`只追踪Claude Code用自己的编辑工具改过的文件，只被终端命令改过或你手动改的文件不在其中，外部操作更撤不回；文档明确说它不替代Git。`/code-review`在同一个会话里运行，适合做第一道检查；涉及钱、个人数据、密钥、删除或发布的改动，仍按第25章另开新会话或请人复查。

## 五、看清权限、执行和费用

权限的四级和对应模式见第26章。截至2026年10月，新版Claude Code在终端里默认以auto模式启动：由另一个模型替你审查操作，不一定每次都问你。第一次练习时，可以按Shift+Tab切到状态栏显示“manual mode on”的Manual模式，它在大多数改文件、跑命令之前都会先问；再按Shift+Tab还能切到`acceptEdits`或计划模式。遇到权限请求，读清楚是什么命令、动哪些文件或服务、有什么后果。一次许可可能覆盖之后的重复操作，别假定每次都会再弹窗。终端命令、hooks（在特定时机自动运行的脚本）、带脚本的skills和外部工具都能产生真实影响，Git分支撤不回已发出的消息或付款。

产品支持、任务也授权时，可以让子智能体（subagent）分担调查或实现。先分好各自负责的范围，并指定谁来整合。不同对话不一定在不同的目录里工作，并行修改可能互相覆盖；委派任务也不会扩大原任务的权限。

费用要分账号路径看：订阅套餐消耗套餐额度，用`/usage`查看；API或第三方云平台按各自的账单计费；额外的用量积分开启后另算。订阅不会替API密钥买单。给一个量级：截至2026年10月，Anthropic称按API计费的企业部署平均每位开发者每个活跃日约13美元，九成用户低于30美元。用量异常时，先看当前账号、模型、任务长度和后台工作（第38章）。

## 小测验

1. **[基础·概念题]** 哪条安装建议符合核查到的官方文档？ <!-- quiz: q01 revision: 2 -->
   - A. npm是官方首选，先装好Node.js再装最稳妥
   - B. 用Homebrew或WinGet装好后，它会自己更新
   - C. 选一种官方列出的方式，如原生安装器；npm已弃用
   - D. 免费的claude.ai账号装好后，就能直接使用
   > **答案C。** 官方推荐原生安装器，也列出Homebrew、WinGet等方式；README已把npm安装标为弃用（A）。Homebrew和WinGet默认不自动更新，要自己运行升级命令（B）。Claude Code需要Pro、Max、Team、Enterprise或Console账号，免费套餐不包含（D）。

2. **[基础·概念题]** 什么适合写进`CLAUDE.md`？ <!-- quiz: q02 revision: 2 -->
   - A. 核实过的项目约定、常用命令和限制
   - B. API密钥，方便它每次直接调用服务
   - C. 之前所有对话的完整记录，方便回忆
   - D. 一句“以后不用再问我权限”的总授权
   > **答案A。** 项目指引应简洁、准确、有用。密钥不能写进项目文件（B）；完整历史太长，反而淹没重点（C）；项目指引也不能代替权限控制或给出无限授权（D）。

3. **[进阶·误区题]** 自动记忆保存了一个过时的测试命令，应怎样处理？ <!-- quiz: q03 revision: 2 -->
   - A. 以记忆为准，它是从以前的工作里总结出来的
   - B. 说明模型权重改了，只能等新版本来修复
   - C. 关掉全部记忆功能，以后都自己记命令
   - D. 核实当前的命令，再纠正那条保存的笔记
   > **答案D。** 记忆是产品保存的上下文笔记，会过时。它不是比当前仓库更可靠的事实来源（A），也不是模型权重的变化（B）。笔记可以查看和纠正，不必因为一条过时内容就关掉全部功能（C）。

4. **[基础·情景题]** 开始长任务前，什么检查有助于避免费用意外？ <!-- quiz: q04 revision: 3 -->
   - A. 确认安装成功，能正常显示版本号就好
   - B. 查看当前账号、套餐额度和已开启的付费项
   - C. 只要是订阅用户，API调用就都已包含在内
   - D. 把任务描述写短一点，费用就一定不会超
   > **答案B。** 订阅额度、API计费和可选附加项要分开确认，当前账号和用量页面提供相关证据。安装成功（A）和费用无关；订阅不会自动替API密钥买单（C）；提示写短并不能保证用量，长任务里工具输出和后台工作也会消耗（D）。

5. **[进阶·情景题]** 两个子智能体准备修改仓库，什么措施有用？ <!-- quiz: q05 revision: 2 -->
   - A. 两个对话天然隔离，各改各的不会冲突
   - B. 让它们同时改同一批文件，最后挑好的那版
   - C. 分好各自负责的文件或工作树，指定整合者
   - D. 给它们更大的权限，这样协作起来会更加顺畅
   > **答案C。** 没有明确隔离时，并行工作者可能共享文件，不同对话不等于不同目录（A），同改一批文件会互相覆盖（B）。委派任务也不会扩大原任务的权限（D）；范围、权限和整合仍需协调。

6. **[基础·操作题]** 写五条项目指引，其中区分一个核实过的命令、一项约定和一条数据处理限制；再与已有记忆对照。 <!-- quiz: q06 revision: 1 -->
   > **该观察到：** 项目指引表达应遵循的规则；记忆可能保存有用观察。但仓库变化时，两者都需要复查。
