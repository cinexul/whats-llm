第19章认识了Agent（智能体）：不只回答一句话，还会自己拆解目标、调用工具、连着走好几步的AI。这一章看Agent家族里最成熟、也和普通人最相关的一支：编程智能体（coding agent），代表是你多半听说过的Claude Code和Codex。

这一章不要求你会写代码。我们要弄清楚的是：它是什么、能做到哪一步、不能指望它什么、最后谁负责。想明白这些，后面几章那些看diff、跑测试、回滚、看计划的动作，你才晓得各自在防什么。

## 一、它是Agent的一种：会“做事”，不只是“会写代码”

很多人对“编程AI”的印象停留在网页聊天：你问“怎么写一个排序函数”，它给你一段代码，你复制走（第17章讲过模型、产品、Agent的分层）。编程智能体高一个层级：它会拿写代码这件事去把一件事办成。

| | 会“写代码”（聊天层） | 会“做事”（智能体层） |
| --- | --- | --- |
| 你给它什么 | 一个具体的小问题 | 一个目标（“给这个网站加个搜索框”） |
| 它给你什么 | 一段文字，你自己去用 | 自己读文件、改代码、跑命令，把事做了 |
| 它知道多少 | 只知道你贴进去的几行 | 自己去翻整个项目，搞清楚现状 |
| 推进方式 | 你问一句、它答一句 | 朝目标连走好几步：看一看、改一改、试一试、再改 |

这就是第19章那个Agent循环落到编程上的样子：读项目（感知）→ 想方案（决策）→ 改文件、跑命令（行动）→ 看结果对不对（再感知），自己转这个圈。所以，编程智能体就是第19章那个会动手的Agent，只不过它动手的地方是你的代码项目。把它当成“更聪明的搜索框”，既会低估它能做的事，也会低估它能闯的祸。

## 二、在哪里用它：取决于产品

截至2026年10月，Claude Code（Anthropic出品，背后是Claude模型）和Codex（OpenAI出品）都提供好几种入口：终端里的命令行程序、代码编辑器插件、桌面应用和网页。有的入口直接在你自己的电脑上改文件、跑命令，有的把任务放到云端的隔离环境里执行。一个产品有哪些入口、任务在哪里执行，取决于产品和你选的入口，而且一直在变。

所以本书把易变的细节集中放在第28、29章和附录C，这几章只讲不随入口改变的东西：它怎么做事，你怎么带它。

## 三、心智模型：能干、但第一天上班的新同事

把Claude Code或Codex想象成一个手脚麻利、能力蛮强，但今天刚到岗、对你们公司一无所知的新同事。这个形象的每一面，都对应它一个真实的脾气：

- 手快：交代的体力活，它做得又快又多。这是它最大的价值。
- 不懂你的门道：项目的规矩、命名习惯、哪些地方碰不得，你不说它就不知道。（让它“记住规矩”的办法见第28章。）
- 会自信地犯错：它可能一脸笃定地用一个根本不存在的写法。这就是第9章讲的幻觉，写代码时照样发生，而且代码看起来很专业，更容易骗过外行。
- 知识有截止日期：很新的技术它可能没听过，或者记成旧版本，除非你把最新资料给它（第9章）。

带这样一个新同事，有经验的人不会撒手不管，也不会事事代劳：派活，盯住关键节点，最后验收。很多人一上来把它当全自动代写机器，丢个需求、等它交活、拿来就用。它更像你带的实习生，而不是交钥匙的承包商。你不必会写每一行代码，但要会派活，会判断它做得对不对。

## 四、责任在人这边

它做完，不等于做对；它说“搞定了”，也不等于真的做好了。它会犯错，又真的能改你的东西，两条叠在一起，就可能出现最麻烦的情况：它一脸自信地把项目改坏，还告诉你“完成了”。

所以无论工具多强，有一条边界不会动：改动合并进你的项目、交给客户、挂上你的名字之前，复核和验收是你的责任（第39章专门讲AI生成内容的责任）。

不会编程的人怎么验收？你不需要读懂每一行代码，但要做到几件具体的事：事先写下“怎样算做成了”，改完亲手照着检查；让它用大白话解释改了什么、哪里有风险；涉及钱、个人数据、密码或密钥、删除文件、对外发布的改动，再请另一个新会话或一个懂行的人复查；退不回的操作不运行。第25章会把这几件事展开成具体做法。

> **要点：** 你守住验收这一关，它那些又快又多的活才是真正省下的时间。判断“这件事到底做成了没有”，靠的是具体的检查，不是读懂每一行代码。

## 五、后面几章怎么接上

把上面几点连起来，就是后面几章的地图：

- 它会动手、也会犯错，需要一套固定的做事顺序：第24章的“调查 → 计划 → 动手 → 验收”。
- 改完要把关：第25章讲看diff、跑检查、回滚和验收，是第四部分最该练熟的一章。
- 它真的会改你的东西：第26章讲怎样让它在能反悔的环境里动手，危险操作先问过你。
- 大事不能一口气做完：第27章讲先出计划、你点头再动手，大任务拆小、小步验收。

## 六、常见误解

| 误解 | 实际 |
| --- | --- |
| 编程智能体就是更会写代码的聊天AI | 它是会动手的Agent（第19章）：自己读项目、改文件、跑命令、连走好几步 |
| 它就是某个固定的网页或软件 | 有终端、编辑器、桌面应用、网页等入口，本地和云端执行都有，取决于产品 |
| 它是AI，写的代码应该对，拿来就用 | 它会自信地写错；做完不等于做对，要验收 |
| 我不会编程，根本用不了 | 不用会写每一行；要会的是派活，再用具体的检查判断做成了没有 |
| 它说“完成了”，责任就交给它了 | 署名和责任都在你；合并、交付前的复核是人的活（第39章） |

## 小结

- 编程智能体（Claude Code、Codex）是第19章“会动手的Agent”在编程领域的样子：自己读项目、改文件、跑命令，连走好几步，把一件事办成。
- 入口有终端、编辑器、桌面应用和网页，任务在本地还是云端执行取决于产品；易变的细节放在第28、29章和附录C。
- 心智模型：能干但第一天上班的新同事，手快肯干，但不懂你的规矩，会自信地犯错。
- 责任在人。不必读懂每一行代码，但要用具体的检查确认它做对了（第25章）。
- 后面几章依次讲工作流（第24章）、验收（第25章）、许可与回滚（第26章）、先计划后动手（第27章）。

## 小测验

> 共6题，涵盖概念、误区、情景、操作四类。先自己想，再看引用块里的答案解析。

1. **[基础·概念题]** 把“编程智能体”和第19章的“Agent”对照，下面哪句最准确？ <!-- quiz: q01 revision: 2 -->
   - A. 它是Agent的一种，只不过动手的地方是你的代码项目
   - B. 它是聊天AI的升级版，区别主要在于代码写得更准
   - C. 它和Agent是两回事：Agent会动手，它只给代码建议
   - D. Agent是它内置的一个小功能，专门用来搜索资料
   > **答案A。** 第19章的Agent是会自己拆目标、调工具、连走好几步的AI；编程智能体就是把这套本事用在“改代码项目”上。B只看到了“写代码”，没看到它会自己读项目、改文件、跑命令；C还停留在“聊天AI只会给文字”的旧印象里；D把包含关系弄反了。

2. **[基础·概念题]** “会写代码”和“会做事”，对编程智能体来说差别在哪？ <!-- quiz: q02 revision: 3 -->
   - A. 没有本质差别，“会做事”只是厂商宣传用的说法
   - B. 前者给你代码自己用；后者自己读项目、改文件、跑命令
   - C. “会做事”是指它能一次写出更长、更完整的一整套程序
   - D. 差别在速度：“会做事”的那种回答得比较快
   > **答案B。** 这正是聊天层和智能体层的分界：前者给出文字、你来执行；后者自己执行、连走好几步。C和D把差别理解成了“写得更多”“答得更快”，其实关键在于谁来动手；A则忽略了它真的会改你的文件这一点。

3. **[基础·误区题]** “它是AI，写的代码应该是对的，做完直接用”——错在哪？ <!-- quiz: q03 revision: 3 -->
   - A. AI写的代码一般都对，只是风格不统一，要再整理一下
   - B. 它写的代码通常跑不起来，所以拿到后都要重写
   - C. 只有免费版会出错，付费版写的代码可以直接用
   - D. 它会自信地写错，“做完”不等于“做对”，要验证
   > **答案D。** 幻觉（第9章）在写代码时照样发生，还因为代码看起来“专业”更容易骗过外行，所以后面要学“看diff、跑测试”。A把问题看小了；B走到了另一个极端，它常常能跑，问题在于“能跑”不等于“对”；C以为付费就不会出错，但哪个版本都会犯错。

4. **[进阶·误区题]** “Claude Code / Codex就是某个固定的网页（或某个软件），形态是定死的”——为什么这么想会出问题？ <!-- quiz: q04 revision: 2 -->
   - A. 不会出问题，主流形态这几年都不会有什么变化
   - B. 会出问题，因为它们其实只能在云端网页里运行
   - C. 形态多样且在更新，钉死一种很快过时，以官方为准
   - D. 会出问题，因为它们只能在命令行里用，没有任何界面
   > **答案C。** 形态是“会变”的那一类：可能在终端、编辑器、网页或云端使用，取决于产品，所以本书只讲不会过时的心智模型，把“在哪用、怎么装”交给官方文档。B和D又把它钉死在了另一种形态上。不过有两点是稳定的：Claude Code来自Anthropic（内核Claude），Codex来自OpenAI。

5. **[基础·情景题]** 你第一次用它，它三下五除二就说“功能加好了”。作为“带他的人”，你接下来最该做的是？ <!-- quiz: q05 revision: 3 -->
   - A. 让它自己再从头检查一遍，它说没问题就直接合并
   - B. 验收：看改了什么、有没有弄坏别的、能否讲清
   - C. 先让它接着做下一个功能，最后再统一检查
   - D. 先合并上线看看效果，出了问题再让它修
   > **答案B。** “做完不等于做对”。它像能干但刚到岗的新同事，验收是带他的人的责任（具体三个动作见第25章）。A让它给自己打分，等于没验收；C让问题越积越多、越难查；D是把它当“交钥匙的承包商”，这正是最常见的失误。

6. **[进阶·操作/观察题]** 不必真装任何工具：找一个你身边“会做事vs只给建议”的对比——比如“导航软件直接带你转弯”对比“路人给你指个方向”。想一想：编程智能体更像哪个？它和“只会给你一段代码让你复制”的聊天AI，差在哪一步？ <!-- quiz: q06 revision: 2 -->
   > **该观察到：** 编程智能体像“直接带你转弯”的导航——它自己执行、连走好几步；聊天AI像“指个方向”的路人——给你信息，路要你自己走。差就差在“谁来动手、谁连走好几步”。也正因为它自己动手、还可能指错路，“验收”这道关才必须留给你（第25、26章）。具体工具的形态、安装、命令**以官方文档为准**。
