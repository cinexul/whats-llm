打开聊天应用，你可能看到模型选择器，又听说同一家公司提供API和Agent。这些词描述的是系统的不同部分。分清它们，才能知道自己在用什么、为什么付费，以及AI到底能做什么。

## 一、先上地图：四个角度

| 术语 | 描述什么 | 简单例子 |
| --- | --- | --- |
| **模型** | 处理输入、生成输出的系统 | 阅读一段文字，生成摘要 |
| **产品** | 给人使用的应用，包括界面、存储和工具 | 在聊天应用里上传文档 |
| **API** | 程序请求服务的约定接口 | 文档软件把文字发送给模型服务 |
| **Agent（智能体）** | 为目标选择步骤，通常会使用工具并检查结果的系统 | 查找文档、比较内容、整理有出处的报告 |

接着第1章的餐厅比方：模型像厨师的手艺，产品像整家餐厅，有菜单、座位和服务员。API像餐厅给外卖平台开的接单窗口，别的程序按固定格式下单、取餐。Agent像一位领班，接到“办一桌生日宴”后，自己查菜单、问忌口，发现缺货就调整方案。

这是四个观察角度，不是四个互斥的盒子，也不是必须依次搭建的四层楼。产品可以包含Agent，Agent可以通过API调用模型；本地应用也可以直接在电脑上运行模型，不经过云端API。

## 二、角度① 模型：生成内容的“内核”

模型提供理解语言、识别图像、生成文字等能力。支持哪些输入和输出，要看具体模型。能看图不等于能生成图片，能处理音频也不等于产品提供实时语音对话。

仅凭模型名称，不能判断有没有联网搜索、偏好记忆或文件编辑功能，这些还取决于外围系统。模型本身也不会跨对话记住你：所谓“记忆”，是产品把保存下来的信息在之后的对话里重新放进上下文（第9章）。

## 三、角度② 产品：包给“人”用的那一面

ChatGPT是OpenAI的产品；Claude和Gemini既用于指模型家族，也用于指各自公司的产品。需要区分时，可以说“Claude应用”或“一个Gemini模型”。

产品可能在多个模型之间选择，保存聊天历史，检索文件，通过另一个服务生成图片，或者提供Agent模式。实际体验还取决于套餐、地区、组织设置和权限。所以同一个模型放进两个产品里，用起来可能很不一样。

## 四、角度③ API：开给“程序”用的接口

API像一张程序可以填写和读取的订单表：程序按约定提交请求，例如要总结的文字，再收到规定格式的结果。API提供的服务可以是运行模型（推理，inference），也就是把输入交给模型、让它算出输出；也可以是搜索、文件访问等。这里的“推理”只是“运行模型”的意思，和第8章的“推理强度”（模型作答时投入多少思考）不是一回事。API本身也不是模型。

使用基于API构建的产品，不要求你懂编程。另外，聊天订阅不自动包含另行计费的开发者API用量。有些工具可以用订阅账号登录，有些需要API密钥或单独余额。先确认具体工具采用哪条付费路径，不要把不同账户权益混为一谈。API密钥可能授权访问和消费，应当像密码一样保管。

## 五、角度④ Agent：会“自己动手”的工作方式

Agent围绕结果推进工作：它可能先搜索，阅读结果，发现缺口，再搜索，最后整理交付物。本章关注的特征是**根据观察结果选择和调整步骤**。

调用一次搜索工具，不足以说明系统具备有意义的自主性；固定流程也能调用工具。反过来，只做调查并写报告、没有修改外部文件的系统，也可能是Agent。“Agent”在实际产品里用法很宽，判断时要看行为和权限。

## 六、四个角度怎样组合在一起

对于“比较这三份合同”，一种可能的路径是：

```text
你使用产品
  → Agent 决定查看哪些条款
  → 工具检索有权访问的片段
  → API 把片段交给模型
  → 模型生成比较结果
  → 产品显示结果和来源
```

这只是一种组合。工具、模型服务和文件存储可能属于不同公司。

> **要点：** 运行在笔记本上的程序，仍可能把文档片段发给云端模型。判断隐私要追踪内容去了哪里，不能只看应用图标在哪里。

## 七、实用判断：我面对的是什么？

问三个具体问题：

1. **我打开的是什么？** 网站、手机应用、桌面工具属于产品。
2. **谁在处理内容，在哪里处理？** 找出模型或服务，确认本地还是远程；产品没有披露的细节就标为未知。
3. **它能决定并执行什么？** 区分建议方案、固定自动流程和会调整下一步的Agent，查看它实际拥有的工具和权限。

## 八、常见误解，集中纠正

| 误解 | 纠正 |
| --- | --- |
| Claude一定只指模型 | 也可能指产品，要看语境 |
| 买了订阅，所有API调用都包含在内 | 各服务的登录方式和计费安排不同 |
| Agent一定是独立而且更强的模型 | Agent行为来自围绕模型和工具构建的系统 |
| 调一次工具就代表自主工作 | 固定流程也能调用工具 |
| 桌面应用表示本地处理 | 模型或连接的工具仍可能在云端 |

## 小结

四个词分别帮你回答：**谁生成、你用什么、软件如何连接、工作怎样组织**。它们在真实系统里会重叠。下一章用这张地图，为实际任务选择产品。

## 小测验

1. **[基础·概念题]** 对这四个术语，哪种描述最准确？ <!-- quiz: q01 revision: 2 -->
   - A. 四个依次叠加的层级，每个产品都要具备
   - B. 四种互相竞争的模型，挑最强的那个就行
   - C. 观察同一系统的不同角度，彼此可以重叠
   - D. API和Agent是同一样东西的两种叫法
   > **答案C。** 产品可以包含Agent，Agent可以通过API调用模型，也可以有别的组合。A把它们当成必须按顺序搭建的楼层；D混淆了“连接程序的接口”和“推进任务的工作方式”。

2. **[基础·概念题]** API是什么？ <!-- quiz: q02 revision: 2 -->
   - A. 程序向服务发请求时遵守的约定接口
   - B. 参数更多、能力更强的一类大模型
   - C. 聊天订阅里自带的一项高级功能
   - D. 让AI自己决定下一步该做什么的方式
   > **答案A。** API连接程序和服务，背后可以是模型，也可以是搜索、文件等其他服务。它本身不是模型（B）；聊天订阅也不自动包含API用量（C）；D描述的是Agent。

3. **[基础·误区题]** 助手联网搜索了一次。你能得出什么结论？ <!-- quiz: q03 revision: 2 -->
   - A. 它就是Agent，能自己完成整件任务
   - B. 它同时拿到了修改你文件的权限
   - C. 搜索在本地完成，内容不会外传
   - D. 它能搜索，但还不足以证明会自主推进
   > **答案D。** 调用一次工具，固定流程也做得到。要判断是不是Agent，看它会不会根据结果选择、调整下一步。搜索能力不等于文件权限（B），也说明不了内容在哪里处理（C）。

4. **[进阶·情景题]** 你买了聊天订阅，另一个工具要求API密钥。应该检查什么？ <!-- quiz: q04 revision: 2 -->
   - A. 不用查，订阅账号已经包含所有用量
   - B. 这个工具的认证和用量是否另行计费
   - C. 两个产品显示的模型名称是否一致
   - D. 能否把密钥贴进聊天，让AI帮忙配置
   > **答案B。** 聊天订阅和开发者API余额不自动是同一项权益；有的工具接受订阅登录，有的需要密钥或单独余额。A正是这个误解；模型名一致说明不了计费方式（C）；密钥是凭据，不该贴进聊天（D）。

5. **[基础·情景题]** 桌面助手使用云端模型读取文档。文档内容可能在哪里处理？ <!-- quiz: q05 revision: 2 -->
   - A. 可能在云端处理，要看应用发送了什么
   - B. 只在本机处理，因为应用装在电脑上
   - C. 只在本机处理，因为文档存在本机硬盘里
   - D. 先在本机加密，云端完全看不到内容
   > **答案A。** 安装位置和处理位置是两个问题。用云端模型时，应用发出的片段会在服务商那边处理。B、C把文件或应用所在的位置当成了处理位置；D假设了产品并没有承诺的保护。

6. **[基础·观察题]** 产品没有披露处理这次请求的具体模型。怎样描述最稳妥？ <!-- quiz: q06 revision: 2 -->
   - A. 根据回答风格，推断一个最可能的模型
   - B. 写上这家公司最新、最强的那个模型
   - C. 写明产品和可见能力，模型标为未知
   - D. 让产品自己报出模型名，照抄下来
   > **答案C。** 有用的地图可以包含未知项。回答风格（A）和品牌名（B）都不能证明具体模型版本；模型自己报出的名字也可能不准（D）。
