打开聊天应用，你会看到一个模型选择器；又听说同一家公司还提供API和Agent。这几个词说的是同一套系统的不同部分。分清它们，你就知道自己在用什么、钱花在哪里，以及AI到底能替你做什么。

## 一、先上地图：四个角度

| 术语 | 描述什么 | 简单例子 |
| --- | --- | --- |
| 模型 | 处理输入、生成输出的系统 | 阅读一段文字，生成摘要 |
| 产品 | 给人使用的应用，包括界面、存储和工具 | 在聊天应用里上传文档 |
| API | 程序向服务发请求时遵守的约定接口 | 文档软件把文字发给模型服务 |
| Agent（智能体） | 为目标选择步骤、通常会使用工具并检查结果的系统 | 查找文档、比较内容、整理有出处的报告 |

接着第1章的餐厅比方：模型像厨师的手艺，产品像整家餐厅，有菜单、座位和服务员。API像餐厅给外卖平台开的接单窗口，别的程序按固定格式下单、取餐。Agent像一位领班，接到“办一桌生日宴”，就自己查菜单、问忌口，发现缺货再调整方案。

这四个词是看同一个系统的四个角度，会互相重叠，也不必按顺序一层层搭起来。产品可以包含Agent，Agent可以通过API调用模型；本地应用也可以直接在电脑上运行模型，完全不经过云端API（第21章）。

## 二、角度① 模型：生成内容的“内核”

模型是真正把输入变成输出的那部分：读一段文字、看一张图，然后生成回答。它支持哪些输入和输出，要看具体模型。能看图不等于能生成图片，能听懂音频也不等于产品提供实时语音对话。

光看模型名，判断不了有没有联网搜索、记忆或文件编辑，这些都是外围系统加上的。模型本身也不会跨对话记住你：产品里的“记忆”，是把保存下来的信息在之后的对话里重新放进上下文（第9章）。

## 三、角度② 产品：包给“人”用的那一面

ChatGPT是OpenAI的产品；Claude和Gemini既是各自公司的产品名，也是模型家族名。需要区分时，可以说“Claude应用”或“某个Gemini模型”。

产品在模型外面加了很多东西：模型选择器、聊天历史、文件上传和检索、联网搜索、调用另一个服务来生成图片、Agent模式等。你能用到哪些，还取决于套餐、地区和组织设置。所以同一个模型放进两个产品里，用起来可能差别很大。

## 四、角度③ API：开给“程序”用的接口

API像一张程序可以填写和读取的订单表：程序按约定格式提交请求，再收到约定格式的结果。下面是一次调用模型的简化样子，各家的字段名略有不同：

```text
程序发出的请求：
  模型：（某个模型名）
  输入：“把下面这段会议记录总结成三点：……”
  最多输出：300个token

服务返回的结果：
  输出：“1. …… 2. …… 3. ……”
  用量：输入812个token，输出96个token
```

返回结果里的用量，就是按量计费的依据（第38章）。API背后可以是运行模型的服务，也可以是搜索、文件存储等别的服务。运行模型在英文里叫inference，中文常译作“推理”，意思就是让模型算出输出，和第8章的“推理强度”（作答时投入多少思考）不是一回事。API本身也不是模型。

使用基于API做成的产品，不需要你会编程。但要知道，聊天订阅和开发者API通常是两笔账。截至2026年10月，Anthropic帮助中心写明，Claude的付费套餐不包含API用量，API在开发者平台另行计费（Max和Team套餐每月附带一些API额度）；OpenAI的Codex用ChatGPT账号登录时消耗套餐额度，改用API密钥则按API价格另计。所以遇到要你填API密钥的工具，先弄清它走哪条付费路径。API密钥能直接产生费用，要像密码一样保管。

## 五、角度④ Agent：会“自己动手”的工作方式

Agent围绕结果推进工作：先搜索，读结果，发现缺口，再搜索，最后整理成交付物。本章看重的特征是：它会根据看到的结果选择和调整下一步。

只调用了一次搜索工具，还说明不了它有多少自主性，固定流程也能调用工具。反过来，一个只做调查、写报告、不改任何外部文件的系统，也可以是Agent。产品里“Agent”这个词用得很宽，判断时要看它实际的行为和权限，第19章会细讲。

## 六、四个角度怎样组合在一起

对于“比较这三份合同”，一种可能的路径是：

```text
你使用产品
  → Agent 决定查看哪些条款
  → 工具检索有权访问的片段
  → API 把片段交给模型
  → 模型生成比较结果
  → 产品显示结果和来源
```

这只是一种组合。工具、模型服务和文件存储可能分属不同公司。

> **要点：** 运行在笔记本上的程序，仍可能把文档片段发给云端模型。判断隐私要追踪内容去了哪里，不能只看应用装在哪里（第37章）。

## 七、实用判断：我面对的是什么？

问三个具体问题：

1. 我打开的是什么？网站、手机应用、桌面工具都是产品。
2. 谁在处理内容，在哪里处理？找出背后的模型或服务，确认是本地还是远程；产品没有披露的细节就标为未知。
3. 它能决定并执行什么？分清只给建议、固定的自动流程，还是会根据结果调整下一步的Agent，再看它实际拥有哪些工具和权限。

## 八、常见误解，集中纠正

| 误解 | 纠正 |
| --- | --- |
| Claude一定只指模型 | 也可能指产品，要看语境 |
| 买了订阅，所有API调用都包含在内 | 订阅和API通常分开计费，登录方式也不同 |
| Agent一定是独立而且更强的模型 | Agent行为来自围绕模型和工具构建的系统 |
| 调一次工具就代表自主工作 | 固定流程也能调用工具 |
| 桌面应用表示本地处理 | 模型或连接的工具仍可能在云端 |

## 小结

四个词分别回答四个问题：谁在生成内容（模型），你在用什么（产品），程序之间怎么连接（API），工作怎样一步步推进（Agent）。它们在真实系统里会重叠。下一章用这张地图，为实际任务挑选产品。

## 小测验

1. **[基础·概念题]** 对这四个术语，哪种描述最准确？ <!-- quiz: q01 revision: 3 -->
   - A. 四个依次叠加的层级，每个产品都要具备
   - B. 四种互相竞争的模型，挑最强的那个就好
   - C. 观察同一系统的不同角度，彼此可以重叠
   - D. API和Agent是同一样东西的两种叫法
   > **答案C。** 产品可以包含Agent，Agent可以通过API调用模型，也可以有别的组合。A把它们当成必须按顺序搭建的楼层；D混淆了“连接程序的接口”和“推进任务的工作方式”。

2. **[基础·概念题]** API是什么？ <!-- quiz: q02 revision: 2 -->
   - A. 程序向服务发请求时遵守的约定接口
   - B. 参数更多、能力更强的一类大模型
   - C. 聊天订阅里自带的一项高级功能
   - D. 让AI自己决定下一步该做什么的方式
   > **答案A。** API连接程序和服务，背后可以是模型，也可以是搜索、文件等其他服务。它本身不是模型（B）；聊天订阅也不自动包含API用量（C）；D描述的是Agent。

3. **[基础·误区题]** 助手联网搜索了一次。你能得出什么结论？ <!-- quiz: q03 revision: 2 -->
   - A. 它就是Agent，能自己完成整件任务
   - B. 它同时拿到了修改你文件的权限
   - C. 搜索在本地完成，内容不会外传
   - D. 它能搜索，但还不足以证明会自主推进
   > **答案D。** 调用一次工具，固定流程也做得到。要判断是不是Agent，看它会不会根据结果选择、调整下一步。搜索能力不等于文件权限（B），也说明不了内容在哪里处理（C）。

4. **[进阶·情景题]** 你买了聊天订阅，另一个工具要求API密钥。应该检查什么？ <!-- quiz: q04 revision: 3 -->
   - A. 订阅的到期日，免得调用API时中断
   - B. 这个工具的认证和用量是否另行计费
   - C. 两个产品显示的模型名称是否一致
   - D. 能否把密钥贴进聊天，让AI帮忙配置
   > **答案B。** 聊天订阅和开发者API余额不自动是同一项权益；有的工具接受订阅登录，有的需要密钥或单独余额。A默认API用量走的是聊天订阅，这正是本章纠正的误解；模型名一致说明不了计费方式（C）；密钥是凭据，不该贴进聊天（D）。

5. **[基础·情景题]** 桌面助手使用云端模型读取文档。文档内容可能在哪里处理？ <!-- quiz: q05 revision: 2 -->
   - A. 可能在云端处理，要看应用发送了什么
   - B. 只在本机处理，因为应用装在电脑上
   - C. 只在本机处理，因为文档存在本机硬盘里
   - D. 先在本机加密，云端完全看不到内容
   > **答案A。** 安装位置和处理位置是两个问题。用云端模型时，应用发出的片段会在服务商那边处理。B、C把文件或应用所在的位置当成了处理位置；D假设了产品并没有承诺的保护。

6. **[基础·观察题]** 产品没有披露处理这次请求的具体模型。怎样描述最稳妥？ <!-- quiz: q06 revision: 2 -->
   - A. 根据回答风格，推断一个最可能的模型
   - B. 写上这家公司最新、最强的那个模型
   - C. 写明产品和可见能力，模型标为未知
   - D. 让产品自己报出模型名，照抄下来
   > **答案C。** 有用的地图可以包含未知项。回答风格（A）和品牌名（B）都不能证明具体模型版本；模型自己报出的名字也可能不准（D）。
