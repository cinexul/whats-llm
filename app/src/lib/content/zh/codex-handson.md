Codex 是 OpenAI 的编程智能体：它可以查看项目、修改文件、运行命令，也能协助审查改动。本章把第24章的“调查、计划、执行、检查”变成一次能实际完成的练习。

以下示例于 **2026-10-22** 对照官方来源核查。你安装的版本和组织设置可能不同；先记录版本，再查看当前可用的命令。

## 一、先选工作在哪里运行

| 形态 | 工作入口 | 开始前确认什么 |
| --- | --- | --- |
| CLI | 终端，通常操作本地项目目录 | 当前目录、Git 状态、命令权限 |
| IDE 扩展 | 支持的代码编辑器 | 打开的项目、准备修改的文件 |
| 桌面应用 | 独立应用 | 任务使用哪个项目和执行环境 |
| 网页／云端任务 | 浏览器，任务在配置好的环境里执行 | 仓库、分支、初始化步骤、网络和密钥 |

本地 CLI **不等于** 模型离线运行：客户端仍可能把任务上下文发送到服务端。云端任务也不会自动拥有你电脑上的依赖、未提交文件和登录凭据。

第一次用一个已有的小 Git 项目练习。先确认工作区干净；已有的未完成修改要另行保存，新建分支本身不是未提交文件的备份。

## 二、安装、登录、查看会话

如果已经装好 Node.js 和 npm，官方仓库列出了这种安装方法：

```bash
npm install -g @openai/codex
codex --version
codex --help
```

Mac 上已经使用 Homebrew 的读者也可以选 `brew install --cask codex`。选一种安装方式即可；官方 README 还提供原生安装器和各平台的二进制文件。

进入已有项目，把示例路径换成自己的目录：

```bash
cd /path/to/your/project
git status
git switch -c practice/codex-first-task
codex
```

登录时，符合条件的账号可以选择 **Sign in with ChatGPT**。官方 README 列出 Plus、Pro、Business、Edu、Enterprise；实际能用什么、额度多少，以你的账号为准。API 密钥是**另一条认证与计费路径**，不是所有 Codex 用户都必须准备的东西。不要把密钥贴进聊天框。

进入交互式 CLI 后，`/status` 显示会话配置和 token 用量，`/permissions` 用于查看或选择允许的操作，`/diff` 查看改动。输入 `/` 可以发现当前版本的命令。终端里的 `codex --help` 和会话里的 `/` 菜单不是同一个入口。

## 三、完成一个小任务

先提出范围明确的请求：

```text
阅读项目说明和 README。找出项目文档里规定的检查方法。
先不要改文件。建议一处很小的 README 澄清，并说明准备怎样验证。
```

看懂建议后，再授权执行：

```text
只完成刚才那处 README 澄清，保留无关的已有改动。
查看 diff，核对相关链接或命令。报告改了什么、实际检查了什么、
还有什么没能确认。这次练习不要发布、推送或部署。
```

这里拆成两步，是为了熟悉工具。以后需求清楚时，可以一次授权实现和验证，不必对每个无害的小步骤反复批准。

完成后查看 `/diff`，或在终端运行：

```bash
git diff --stat
git diff
git status --short
```

文档修改要核对文字和链接；功能修改则应运行相关测试，并实际试用变化后的行为。“智能体说通过了”的证据强度，低于真实命令输出和可复现的运行结果。

## 四、把项目规矩写下来

Codex 支持用 `AGENTS.md` 保存项目指引，`/init` 可以辅助创建。使用前先审阅内容，例如：

```markdown
# 本项目的工作约定
- 修改前先读 README。
- 每次改动聚焦于用户要求的任务。
- 使用仓库文档规定的包管理器和检查命令。
- 示例不得包含凭据或真实客户数据。
- 报告验证结果，以及没能执行的检查。
```

确认实际命令后，可以把泛泛的规则换成准确命令。长篇资料另存文件并提供链接。项目指引会被加载进上下文，不会重新训练模型，也不能保证每条规则必然被遵守。Skill 封装可复用的流程，保存的记忆保留笔记；两者都不能代替明确的项目规则或真正执行的权限限制。

## 五、看清权限、云端环境和费用

**沙箱**限制执行环境能访问什么；**审批策略**决定哪些操作要批准。两者共同决定行为：有些操作已经允许，有些需要询问，有些会被阻止。不能假定每条有后果的命令前都会弹确认框。

云端任务要确认目标仓库和分支，通过环境初始化安装依赖，并检查可访问的网络地址及可用密钥。合并前审查 diff 和验证输出。分支可以帮助撤销代码改动，却不能撤回已经发出的邮件或自动还原外部数据库。

费用要按账号路径区分：

- **ChatGPT 套餐：** 包含的 Codex 使用量按套餐规则消耗额度。大任务可能消耗更多额度，但不一定产生单独的按 token 账单。
- **API 认证：** 按 API 价格和该账号限制计费；ChatGPT 订阅不会自动为 API 使用买单。
- **可选购买与服务：** 额外积分、连接的服务、云基础设施等，开启后可能有各自的费用。

检查实际登录的账号、用量页面和已启用的附加服务。任务聚焦、材料相关，有助于控制工作量；“按月订阅”不等于无限使用，“token 更多”也不等于订阅必然额外扣钱。

## 小测验

1. **[基础·概念题]** 下面哪句准确描述了 Codex？ <!-- quiz: q01 revision: 1 -->
   - A. 只能通过网页使用
   - B. 它是 OpenAI 的编程智能体，有多种使用入口
   - C. 只要使用 CLI，模型就是离线运行
   - D. 每个用户都必须提供 API 密钥
   > **答案 B。** CLI、编辑器扩展、应用和网页／云端入口可能使用不同执行环境。本地执行不等于模型离线推理。

2. **[基础·情景题]** 你已有符合条件的 ChatGPT 套餐。购买 API 额度前，应该先做什么？ <!-- quiz: q02 revision: 1 -->
   - A. 认定订阅绝不包含 Codex
   - B. 把密码贴进对话
   - C. 检查 ChatGPT 登录方式和账号实际可用的额度
   - D. 默认所有 API 使用都已包含
   > **答案 C。** ChatGPT 登录和 API 认证是不同路径。先查当前账号及额度，再决定是否使用另行计费的 API。

3. **[基础·概念题]** `AGENTS.md` 提供什么？ <!-- quiz: q03 revision: 1 -->
   - A. 可加载到上下文里的项目指引
   - B. 无限用量
   - C. 文件系统权限控制的替代品
   - D. 对模型权重的永久修改
   > **答案 A。** 它让项目规矩显式可读，但不是计费机制，也不是安全边界。

4. **[进阶·误区题]** “命令危险时，Codex 必然先问我。”这句话漏了什么？ <!-- quiz: q04 revision: 1 -->
   - A. 没漏，这有绝对保证
   - B. 只看模型名称就够了
   - C. Git 会自动阻止外部操作
   - D. 实际行为取决于沙箱、审批策略和已有权限
   > **答案 D。** 操作可能已经被允许、需要审批，也可能直接被阻止。要检查实际配置，不能依赖“每次必问”的假设。

5. **[基础·情景题]** 云端任务因为缺依赖而失败，下一步应该？ <!-- quiz: q05 revision: 1 -->
   - A. 认定它能直接使用本机装好的包
   - B. 查看环境初始化，在该环境安装项目文档规定的依赖
   - C. 取消所有网络和文件限制
   - D. 随机修改项目代码
   > **答案 B。** 云端环境是独立的。应根据仓库规定的包管理器和依赖文件修复初始化。

6. **[基础·操作题]** 在小项目里请求一处 README 澄清，查看 diff，并记录账号路径、权限和验证结果。 <!-- quiz: q06 revision: 1 -->
   > **该观察到：** 一次成功练习应有边界明确的改动和可见证据。你也应说清任务在哪里执行、使用谁的额度或账单。
