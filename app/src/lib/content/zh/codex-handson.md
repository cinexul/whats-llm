Codex是OpenAI的编程智能体：它可以查看项目、修改文件、运行命令，也能帮你审查改动。本章把第24章的“调查、计划、动手、验收”变成一次能实际完成的练习。

安装方式、套餐和命令于2026-10-29对照官方来源核查。你装的版本和组织设置可能不同，先记下版本，再查看当前可用的命令。

## 一、先选工作在哪里运行

| 形态 | 工作入口 | 开始前确认什么 |
| --- | --- | --- |
| CLI | 终端，通常操作本地项目目录 | 当前目录、Git状态、命令权限 |
| IDE扩展 | 支持的代码编辑器 | 打开的项目、准备修改的文件 |
| 桌面应用 | 独立应用 | 任务用哪个项目和执行环境 |
| 网页／云端任务 | 浏览器，任务在配置好的环境里执行 | 仓库、分支、初始化步骤、网络和密钥 |

在本地用CLI，不等于模型在你电脑上离线运行：客户端仍会把任务上下文发到服务端。云端任务也不会自动拥有你电脑上的依赖、未提交的文件和登录凭据。

第一次先用一个已有的小Git项目练习（Git的安装和基本用法见第26章“Git最小起步”）。先确认工作区干净；已有的未完成修改要另行保存，新建分支本身不是未提交文件的备份。

## 二、安装、登录、查看会话

截至2026年10月，官方文档把独立安装器放在第一位；只有后面提到的npm方式才需要先装Node.js。macOS或Linux：

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

Windows的PowerShell：

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

这两条命令都会下载并执行安装脚本，请确认地址来自官方，并遵守所在组织的规定。也可以用Homebrew的`brew install --cask codex`，或在装好Node.js的电脑上用`npm install -g @openai/codex`。选一种就好，装好后确认：

```bash
codex --version
codex --help
```

进入已有项目，把示例路径换成自己的目录。下面的`git`命令需要先装好Git；项目还没交给Git管理的话，先按第26章存一个起点：

```bash
cd /path/to/your/project
git status
git switch -c practice/codex-first-task
codex
```

第一次运行`codex`时，可以选择Sign in with ChatGPT（用ChatGPT账号登录）。截至2026年10月，官方定价页写明ChatGPT的Free、Go、Plus、Pro、Business、Edu、Enterprise套餐都包含Codex，但额度差别蛮大：Free档定位是在快速的小任务上体验，Go档用于轻量任务；官方README推荐用Plus、Pro、Business、Edu或Enterprise登录。API密钥是另一条认证和计费路径，不是每个Codex用户都要准备。不要把密钥贴进聊天框。

进入交互界面后，输入`/`可以看到当前版本的命令。几个常用的：

| 会话内命令 | 用途 |
| --- | --- |
| `/status` | 查看会话配置和token用量 |
| `/permissions` | 选择允许Codex做什么（第26章） |
| `/plan` | 切换到计划模式（第27章） |
| `/diff` | 查看Git改动，包括还没被跟踪的新文件 |
| `/review` | 审查当前的改动，找出问题 |
| `/init` | 创建`AGENTS.md`项目指引 |

## 三、完成一个小任务

先提出范围明确的请求：

```text
阅读项目说明和README。找出项目文档里规定的检查方法。
先不要改文件。建议一处很小的README澄清，并说明准备怎样验证。
```

看懂建议后，再授权执行：

```text
只完成刚才那处README澄清，保留无关的已有改动。
查看diff，核对相关链接或命令。报告改了什么、实际检查了什么、
还有什么没能确认。这次练习不要发布、推送或部署。
```

这里拆成两步，是为了熟悉工具。以后需求清楚时，可以一次授权实现和验证，不必对每个无害的小步骤反复批准。

完成后用`/diff`查看，或在终端运行：

```bash
git diff --stat
git diff
git status --short
```

再按第25章验收：让它用大白话解释每处改动，你对照diff看。文档修改核对文字和链接；功能修改要运行相关测试，并亲手试一遍。“智能体说通过了”的分量，比不上真实的命令输出和你亲眼看到的结果。`/review`适合做第一道检查；涉及钱、个人数据、密钥、删除或发布的改动，仍要另开新会话或请人复查。

## 四、把项目规矩写下来

Codex用`AGENTS.md`保存项目指引，`/init`可以帮你起草。用之前先审阅内容，例如：

```markdown
# 本项目的工作约定
- 修改前先读README。
- 每次改动聚焦于用户要求的任务。
- 使用仓库文档规定的包管理器和检查命令。
- 示例不得包含凭据或真实客户数据。
- 报告验证结果，以及没能执行的检查。
```

确认实际命令后，把泛泛的规则换成准确的命令；长篇资料另存文件并提供链接。项目指引会被放进上下文，不会重新训练模型，也不能保证每条规则都被遵守。Skill封装可复用的流程，保存的记忆保留笔记；两者都不能代替明确的项目规则或真正生效的权限限制。

## 五、看清权限、云端环境和费用

沙箱限制执行环境能访问什么，审批策略决定哪些操作要你批准，两者共同决定行为：有些操作已经允许，有些需要询问，有些会被阻止。截至2026年10月，Codex在Git管理的文件夹里默认可以直接改项目文件、运行沙箱允许的命令，越界才问；其他文件夹默认只读（权限的四级见第26章）。所以不能假定每条有后果的命令前都会弹出确认。

云端任务要确认目标仓库和分支，在环境的初始化步骤里安装依赖，并检查它能访问哪些网络地址、能用哪些密钥。合并前审查diff和验证输出。分支能帮你撤销代码改动，却撤不回已经发出的邮件，也不会自动还原外部数据库。

费用按账号路径区分：用ChatGPT登录时，Codex消耗套餐里包含的额度，大任务消耗更多，但不一定产生单独的按token账单；用API密钥时按API价格单独计费，ChatGPT订阅不会替它买单；额外购买的额度和连接的服务另算。定价页特意提醒，不能拿API价格去估算订阅能做多少任务。细节见第38章。

## 小测验

1. **[基础·概念题]** 下面哪句准确描述了Codex？ <!-- quiz: q01 revision: 2 -->
   - A. 它只能在网页里使用，没办法装到本地电脑
   - B. OpenAI的编程智能体，有多种使用入口
   - C. 用CLI时，模型就在你自己的电脑上离线运行
   - D. 不管哪种套餐，都必须先准备一把API密钥
   > **答案B。** CLI、编辑器扩展、桌面应用和网页／云端入口都有，可能使用不同的执行环境，所以A不对。本地运行CLI不等于模型离线推理，客户端仍会把任务上下文发给服务端（C）。用ChatGPT账号登录就能用，API密钥是另一条路径（D）。

2. **[基础·情景题]** 你已有符合条件的ChatGPT套餐。购买API额度前，应该先做什么？ <!-- quiz: q02 revision: 2 -->
   - A. 认定订阅不含Codex，直接买API额度最省事
   - B. 认定订阅已经包含所有API调用，不用再查
   - C. 先用ChatGPT登录，查清账号实际可用额度
   - D. 先改用npm安装，只有它支持ChatGPT登录
   > **答案C。** ChatGPT登录和API认证是不同路径。先查当前账号及额度，再决定是否使用另行计费的API。A、B都是没查就下结论；登录方式也和安装方式无关，独立安装器、Homebrew、npm装的都能用ChatGPT登录（D）。

3. **[基础·概念题]** `AGENTS.md`提供什么？ <!-- quiz: q03 revision: 2 -->
   - A. 会被加载进上下文的项目指引
   - B. 一份限制文件访问的安全配置
   - C. 写进去的规则会被训练进模型
   - D. 让Codex百分百遵守每条规则
   > **答案A。** 它让项目规矩显式可读，并在工作时被加载进上下文。真正限制文件访问的是沙箱和权限设置（B）；它不会改动模型权重（C）；加载进上下文的规则也不能保证每条都被遵守（D）。

4. **[进阶·误区题]** “命令危险时，Codex必然先问我。”这句话漏了什么？ <!-- quiz: q04 revision: 2 -->
   - A. 没漏什么，危险命令一定会先弹窗确认
   - B. 漏了Git：Git会自动挡住所有外部操作
   - C. 漏了模型：换更强的模型它就会先问你
   - D. 实际行为取决于沙箱、审批策略和已有权限
   > **答案D。** 操作可能已经被允许、需要审批，也可能直接被阻止，所以“每次必问”靠不住（A）。Git管的是记录过的文件，挡不住外部操作（B）；换模型也不会改变审批配置（C）。要检查实际配置，并且别打开跳过审批的选项（第26章）。

5. **[基础·情景题]** 云端任务因为缺依赖而失败，下一步应该？ <!-- quiz: q05 revision: 3 -->
   - A. 先在自己电脑上装好，云端会自动用上
   - B. 查看环境初始化，在那个环境装好依赖
   - C. 关掉网络和文件限制，让它自己去装好
   - D. 让它改代码，绕开缺少的那个依赖包就好
   > **答案B。** 云端环境是独立的，用不上你电脑里装的包（A）。应根据仓库规定的包管理器和依赖文件修复初始化。为此放开所有限制会扩大风险（C），绕开依赖则可能改坏功能（D）。

6. **[基础·操作题]** 在小项目里请求一处README澄清，查看diff，并记录账号路径、权限和验证结果。 <!-- quiz: q06 revision: 2 -->
   > **该观察到：** 一次成功练习应有边界明确的改动和可见证据。你也应说清任务在哪里执行、使用谁的额度或账单。
