到目前为止，你用AI都是打开一个界面、自己在里头聊。这一章换成让你自己的程序去用AI：你的网站、App或脚本在背后自动把问题发给模型、把回答拿回来，再用到自己的应用里。

这就是第17章那张“四层地图”里的第③层：**API**（应用程序接口，专门开放给程序调用的入口）。还记得那个比喻吗：餐厅是给走进来的客人吃的，别的店想用这位厨师的手艺，就走“接单窗口”下单。API就是这个窗口，只不过来下单的是程序。

这一章先讲清数据流，再给一个真能跑的最小脚本：三十多行JavaScript，把一句话发给模型、打印回答，密钥从环境变量里读。做完你手里会有一个能运行的脚本，和一套管好密钥与费用的习惯。

## 一、准备

- 先确认你真的需要API，而不是开个会员。只是你一个人偶尔让AI改改文章，用现成的聊天产品就够了（第17、18章）。要让自己的系统自动调用AI，比如让官网客服自动回话、让程序批量处理数据，才需要走API。
- 一把**API密钥**（API key）：在平台上申请的一串字符，用来证明“是你在下单”，平台据此按token计费（第3、38章）。它泄露了，别人就能用你的账号点单、记你的账。所以第二节第0步先讲怎么管它。
- 想清楚数据流：问题出去、回答回来、再用起来。先把这条线在脑子里画清楚，写代码只是把它落地。
- 动手时需要：Node.js（第4步会装）、一个编程智能体（可选，第28、29章）、一个新的空文件夹，按第26章用Git起步。

## 二、一步步做

### 第0步：先把密钥安顿好（在写任何功能之前）

| 该怎么做 | 为什么 |
| --- | --- |
| 把密钥放进环境变量或`.env`文件，别写进代码 | 写进代码，密钥就跟着代码到处走，随时可能泄露 |
| 把`.env`写进`.gitignore`，绝不提交到仓库（尤其是公开的GitHub） | 公开仓库里的密钥会被自动扫描程序很快捡走；就算事后删掉，Git历史里也还留着 |
| 密钥由你自己设置，不贴进任何对话 | 包括你和编程智能体的对话，贴进去就等于交了出去（第37章） |
| 去平台后台设好用量上限 | 万一密钥泄露，或程序写出死循环、不停地调用，上限能兜住损失（第38章） |

几个词先说明白。**环境变量**是放在程序外面的设置，程序运行时再读进来，密钥就不用明晃晃写在代码里。`.env`是放在项目文件夹里、专门存这类设置的文本文件。`.gitignore`是一份清单，告诉Git哪些文件不要记录，把`.env`写进去，它就不会被提交。

编程智能体可能会读项目里的文件，包括`.env`。所以密钥要你自己设，并在工具允许的地方禁止它读这个文件。截至2026年10月，Claude Code可以在设置文件的`permissions.deny`里写`Read(./.env)`；Codex可以在`config.toml`的权限配置里把`.env`设为`deny`（这项功能还标着Beta）。这些规则不一定能拦住所有读取途径，比如它运行的脚本自己去读文件，所以只是多一层保护。怀疑密钥泄露，就立刻去后台作废、换一把新的（第40章）。

### 第1步：让程序代你“问一句”

最小可跑的核心就一件事：你的程序把一个问题通过API发给模型。用大白话描述这条请求：

```text
（你的程序在背后自动做这件事）
对模型说：「判断下面这条留言是好评还是差评，
          只回答'好评'或'差评'。留言：……」
```

这和你在聊天框里打字本质一样，都是把一段话发给模型。区别在于现在是程序替你发，一天可以发一万次。发什么内容，还是第11章那套讲究：把要求说清楚、把格式定死。

### 第2步：把模型的回答接回来

模型处理完，把回答传回给你的程序，通常是一段带结构的数据，里面有回答的文字和这次的用量。

新手常犯的错，是以为模型每次都乖乖按格式回答。你让它只回“好评”或“差评”，它偶尔会回一整句解释，幻觉也照样会发生（第9章）。所以程序要检查返回的内容，不合格式就走兜底处理。

### 第3步：把回答“用起来”，嵌进你的应用

拿到回答之后，就是你自己应用的逻辑了：把“好评/差评”存进数据库、显示在页面上、触发一封通知邮件，都由你的程序决定。整条数据流连起来是这样：

```text
 用户/你的数据
      │
      ▼
 你的程序  ──(通过 API，带着密钥)──→  模型
      ▲                                │
      │                                ▼
      └────────  模型把回答传回  ───────┘
      │
      ▼
 你的程序把回答用起来（存库 / 显示 / 触发下一步）
```

中间那个模型是租来的能力，你按token付费。

### 第4步：最小可跑路径——一个真能跑的脚本

下面的写法按Anthropic官方快速入门（Get started with Claude）和API版本说明核对，截至2026年10月29日。

这里用JavaScript，在Node.js（让JavaScript在电脑上直接运行的程序）里跑。选它而不是Python，是因为这个脚本在Node.js里不用装任何额外的包：发请求用Node.js自带的`fetch`，读`.env`用Node.js自带的`--env-file`选项。官方快速入门的Python写法要先安装SDK（厂商提供的代码库），读`.env`一般还要再装一个包。直接发请求还有个蛮实在的好处：第1～3步说的数据流，发到哪、带什么、回来什么，在代码里都看得见。

1. 安装Node.js：从`nodejs.org`下载标着LTS（长期支持）的版本安装。装好后在终端输入`node --version`，能看到版本号就好。
2. 建项目文件夹`api-hello`，按第26章用Git起步。
3. 建`.gitignore`，里面写一行`.env`。可以让编程智能体建，建完自己打开确认。
4. 你自己设置密钥：在Claude Console（`platform.claude.com`）创建API密钥，并按第38章设好用量上限。用文本编辑器在项目文件夹里新建`.env`，写一行`ANTHROPIC_API_KEY=你的密钥`。整个过程不经过AI，也不把密钥贴进任何对话。
5. 在你用的编程智能体里禁止读取`.env`（见第0步）。
6. 新建`hello-api.mjs`，内容如下。可以自己粘贴，也可以让编程智能体照抄，再自己打开核对一遍：

```javascript
// hello-api.mjs：把一条留言发给Claude，打印它的判断
const apiKey = process.env.ANTHROPIC_API_KEY;
if (!apiKey) {
  console.error("没找到ANTHROPIC_API_KEY，请检查.env文件");
  process.exit(1);
}

const review = "快递很快，包装也很用心。";

const response = await fetch("https://api.anthropic.com/v1/messages", {
  method: "POST",
  headers: {
    "content-type": "application/json",
    "x-api-key": apiKey,
    "anthropic-version": "2026-10-21",
  },
  body: JSON.stringify({
    model: "claude-opus-5-5",
    max_tokens: 1000,
    messages: [
      {
        role: "user",
        content: `判断下面这条留言是好评还是差评，只回答“好评”或“差评”。留言：${review}`,
      },
    ],
  }),
});

const data = await response.json();
if (!response.ok) {
  console.error("请求失败：", response.status, data.error?.message);
  process.exit(1);
}

const text = (data.content.find((block) => block.type === "text")?.text ?? "").trim().replace(/[。.]$/, "");
console.log(text === "好评" || text === "差评" ? text : `无法判断（模型原话：${text}）`);
console.log("本次用量（token）：输入", data.usage.input_tokens, "输出", data.usage.output_tokens);
```

7. 在终端里进入这个文件夹，运行：

```bash
node --env-file=.env hello-api.mjs
```

这条命令的意思是：用Node.js运行`hello-api.mjs`，运行前先把`.env`里的那一行读成环境变量。脚本里的`process.env.ANTHROPIC_API_KEY`就是从那里拿到密钥的，代码里看不到密钥本身。正常的话会打印“好评”和一行用量；密钥写错会打印`请求失败： 401 invalid x-api-key`。

对照第1～3步，这个脚本做了这几件事：

- 发到哪：`https://api.anthropic.com/v1/messages`，Anthropic的消息接口（Messages API）。
- 带了三个请求头：`x-api-key`放密钥；`anthropic-version`写接口版本的日期，截至2026年10月最新的是`2026-10-21`（官方快速入门的示例里还写着`2023-06-01`，对这个最简单的请求两者结果一样）；`content-type`说明发的是JSON。
- 发了什么：`model`是模型名，这里用快速入门里的`claude-opus-5-5`；`max_tokens`是这次回答最多生成多少token；`messages`是对话内容。
- 回来什么：一段JSON（用花括号、方括号组织数据的文本格式）。`content`是一个列表，类型为`text`的那一块就是回答的文字；列表里也可能有别的类型的块，比如模型思考过程留下的块，所以脚本按类型去找。`stop_reason`说明它为什么停下，`end_turn`表示正常说完。`usage`里的`input_tokens`和`output_tokens`就是这次计费用的token数。
- 兜底：去掉首尾空格和句末的句号后，回答仍不是“好评”或“差评”，就打印“无法判断”和模型的回答，程序不会崩。

想更省钱，可以把`model`换成`claude-haiku-5-5`：截至2026年10月，它的输入价格是每百万token 0.10美元起，`claude-opus-5-5`是4美元（更多价格见附录E）。OpenAI的接口思路相同，只是地址、请求头和字段名不一样，照它的快速入门改写即可。

### 看结果 / 验收

1. 能不能稳定地发出去、收回来？把`review`换成两三条真实留言，各跑一次。
2. 密钥安全吗？密钥只在`.env`里，没写进代码、没提交到仓库、没出现在对话里，后台设了用量上限。这一条最要紧，要反复确认。
3. 兜底管不管用？把`review`换成一句和评价无关的话，比如“明天几点开会？”，程序应该打印“无法判断”，而不是崩掉。
4. 花了多少钱？对照脚本打印的token数，去平台后台看一眼这几次的用量和花费，对“调一次大概多少钱”建立直觉（第38章）。

### 完成标准

下面几条都做到了，这个项目就算完成：

- 运行`node --env-file=.env hello-api.mjs`，能打印“好评”或“差评”，以及一行用量。
- 代码文件里搜不到你的密钥；`git status`里看不到`.env`（它被`.gitignore`挡住了）。
- 你从没把密钥贴进任何对话；工具里能禁止读取`.env`的地方已经设好。
- 平台后台设了用量上限，你也看过这次测试花了多少。
- 给它一条刁钻的输入时，程序打印“无法判断”，没有崩。

## 三、常见问题

| 问题 | 怎么回事 / 怎么避免 |
| --- | --- |
| 以为“接API = 开会员” | 开会员是给人用产品；接API是给程序用接口，要申请密钥、按token计费（第17章） |
| 把密钥写进代码 / 提交到公开仓库 | 等于把家门钥匙贴在门上。密钥放`.env`、`.env`进`.gitignore`，写第一行代码之前就做好 |
| 把密钥贴给编程智能体，让它“帮你配好” | 贴进对话就等于交了出去。密钥你自己设，让它写“从环境变量读取”的代码就好 |
| 没设用量上限，被人盗用或程序死循环，费用失控 | 程序一个bug可能一秒调几百次。先设好上限（第38章） |
| 假设模型每次都按格式回答 | 它会出错、会跑偏（第9章）。检查返回值，不合格式就兜底 |
| 把用户隐私数据原样发给API | 发出去就等于交出去了，敏感信息先脱敏（第37章） |
| 照着网上某段旧代码硬抄 | 各家API会更新，模型名和版本号会变。以官方快速入门的当前写法为准，本章的写法也是如此 |

## 四、可以再往前一步

每一步都别忘了密钥和费用：

- 打磨提示词：你发给模型的那段话直接决定回答质量，把第11、12章的技巧用上。
- 要更规整的输出：让模型按固定结构返回，程序拿到就能直接用。Anthropic和OpenAI都支持“结构化输出”，按各自文档的写法来。
- 省着用token：批量调用时，token就是钱。别把无关的长文塞进每次请求（第38章）。
- 让程序“自己做多步、调工具”：那就是在搭Agent了（第19、34章），第34章那套刹车纪律要跟上：花钱、删数据、对外发送，仍要人确认。
- 接公司内部资料或外部工具：那是第22、36章的Skills和MCP，每接一个新源，都是一个新的风险入口。

## 小结

- “给现有程序接上AI”就是用API（第17章第③层）：你的程序在背后自动把问题发给模型、收回答、用到自己的应用里。
- 数据流就一条线：你的程序 →（带密钥）→ 模型 → 回答传回 → 程序用起来。最小脚本三十多行：发到`https://api.anthropic.com/v1/messages`，带`x-api-key`、`anthropic-version`、`content-type`三个头，从返回的`content`里取出文字，`usage`里是计费用的token数。
- 最大的误区是“接API = 开会员”：会员给人用产品，API给程序用接口、按token计费。
- 密钥与费用从第一行起就管好：放`.env`并写进`.gitignore`、不写进代码、不贴进对话、设用量上限、禁止编程智能体读`.env`（第37、38、40章）。
- 模型返回的内容仍会出错、不按格式（第9章），程序要检查和兜底；发出去的数据等于交出去了，敏感信息先脱敏（第37章）。

## 小测验

> 共6题，涵盖概念、误区、情景、操作四类。答案与解析在每题下方的引用块里——先自己想，再对照。

1. **[基础·概念题]** “给现有程序接上AI”，本质上是在用四层地图（第17章）里的哪一层？ <!-- quiz: q01 revision: 2 -->
   - A. 产品层：给人点开就能用的聊天界面
   - B. Agent层：能自己多步行动的智能体
   - C. API层：专门开放给程序调用的接口
   - D. 模型层：训练出来的那个模型本身
   > **答案C。** 让**程序**在背后自动调用模型，走的就是API（第17章第③层那个“接单窗口”）。A是给**人**点开聊的；D的模型本身你的程序碰不到，要通过接口去用；B是另一回事，程序调API可以搭出Agent，但“调一次API拿回答”本身不是Agent。

2. **[基础·误区题]** “我们要在自己的系统里接入AI，那就去开个ChatGPT会员吧。”——错在哪？ <!-- quiz: q02 revision: 2 -->
   - A. 要走API，申请密钥、按用量计费
   - B. 错在会员档位不够，得开团队版才可以接入
   - C. 没错，开了会员就能在系统里直接调用
   - D. 错在应该先训练一个自己的专属模型
   > **答案A。** 这是本章头号误区。“人在界面里用”和“程序在背后自动调用”是两条不同的路：前者用产品（开会员），后者用API（第17章）。B和C都把会员当成了接入方式，档位再高也是给人用的；D跑偏了，接API用的是厂商现成的模型，不需要自己训练。

3. **[基础·概念题]** 用API时那把“密钥（API key）”是干什么的？ <!-- quiz: q03 revision: 2 -->
   - A. 一种会员卡，开通后聊天产品不限次数
   - B. 加速模型运算的通行证，越贵越快
   - C. 让模型只回答你账号相关问题的开关
   - D. 证明是你在调用，并据此按用量记账
   > **答案D。** 密钥相当于你的“点单凭证 + 记账依据”。正因为它一头连着你的账单，**泄露了别人就能拿你的账去刷**——所以放环境变量或`.env`、别提交、别贴进对话、设用量上限（第37、38章）。A把它和会员混为一谈；B和C说的速度、回答范围都和密钥无关。

4. **[进阶·误区题]** 写代码图省事，直接把密钥写在代码文件里、还推到了公开的GitHub仓库。最可能发生什么？ <!-- quiz: q04 revision: 2 -->
   - A. 没关系，公开仓库的代码太多，没人会注意
   - B. 会被扫描程序很快捡走盗用，记到你账上
   - C. GitHub会自动把密钥加密，别人看不到
   - D. 只要之后删掉那一行，泄露就算撤回了
   > **答案B。** 公开仓库会被专门的扫描程序盯着，明文密钥往往很快就被捡走。正确做法是**密钥放环境变量或`.env`、把`.env`写进`.gitignore`、绝不提交，并设用量上限兜底**（第37、38章）。A低估了自动扫描；C不成立，密钥写进去就是明文；D也不行，删掉一行后，那次提交仍留在Git历史里，已经泄露的密钥要去后台作废、换新。

5. **[基础·情景题]** 你的程序通过API让模型“只回答‘好评’或‘差评’”，但它偶尔回了一整句解释。最该怎么办？ <!-- quiz: q05 revision: 3 -->
   - A. 换一把新密钥，旧密钥可能有问题
   - B. 认定API坏了，改用聊天界面手动做
   - C. 程序里检查返回值，不合格式就兜底
   - D. 一直自动重试，直到它按格式回答为止
   > **答案C。** 模型返回的内容仍可能出错、不按格式（幻觉照样发生，第9章）。健壮的程序会预设“它可能不听话”，对返回值做检查和兜底。A和B把正常现象当成了故障；D不设上限地重试，可能一直不成功，还会白白花钱（第38章）。

6. **[基础·操作/观察题]** 先在纸上画一遍“接API”的数据流：从“你的程序把问题发出去（带着密钥）”，到“模型把回答传回来”，再到“你的程序把回答用起来”，并在图上标出三处和钱/安全有关的点：密钥放哪、在哪计费、在哪设上限。有条件的话，再按第4步的脚本真跑一遍，对照“完成标准”检查。 <!-- quiz: q06 revision: 3 -->
