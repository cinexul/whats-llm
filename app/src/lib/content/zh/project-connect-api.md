到目前为止，你用AI的方式都是“打开一个界面、自己在里头聊”。这一章要做的事不一样：让**你自己的程序**去用AI——不是你坐在对话框前打字，而是你的网站、App或脚本，在背后**自动**把问题发给模型、把回答拿回来，再嵌进你自己的应用里。

这就是第17章那张“四层地图”里的第③层——**API（接口）**。还记得那个比喻吗：餐厅是给走进来的客人吃的，而别的店想用这位厨师的手艺，就走“接单窗口”下单。API就是这个窗口，只不过来下单的不是人，是程序。

先说清楚这一章的定位：**这一章重点讲“思路与数据流”，不手把手教某一种语言的代码。** 各家API的具体写法、参数、SDK（厂商提供的现成代码库）用法不一样、还经常更新，那些一律**以官方文档为准**。最小可跑的版本，我们交给编程智能体照着厂商官方的快速入门（quickstart）来写，你负责管好密钥、运行和验收。你要带走的，是“接API到底是怎么一回事”这个能让你和工程师对上话、也能自己判断的框架。

## 一、准备

哪怕你不亲自写代码，下面几件事也得心里有数——尤其是密钥和费用，**从写第一行起就要管好**。

- **先确认你真的需要API，而不是开个会员。** 这是最常见的误区，单独拎出来说：如果只是你一个人、偶尔让AI帮你改改文章，用现成的聊天**产品**就够了（第17、18章）。只有当你要让**自己的系统自动调用**AI——比如让公司官网的客服自动回话、让你的程序批量处理数据——才需要走API。**接API和开会员是两件事。**
- **拿一把“密钥（API key）”。** 用API通常要先在对应平台申请一把密钥，用来证明“是你在下单”，并据此**按token计费**（第3、38章）。具体怎么申请**以官方文档为准**。
- **从第一天就把密钥和费用当回事。** 这把密钥极其敏感——**泄露了等于别人能拿你的账号点单、记你的账单**。所以下面第二节的第0步，专门讲怎么管它。别等出了事才补。
- **想清楚“数据流”长什么样。** 接API的本质，就是设计一条“问题出去、回答回来、再用起来”的流水线。先把这条线在脑子里画清楚，写代码只是把它落地。
- **动手时需要的东西**：一个编程智能体（第28、29章）、一个新的空文件夹，以及按第26章用Git起步。

> **要点：** 接API这件事，技术门槛其实没你想的高（最小可跑的版本很短），真正的门槛在两个判断：**一是分清“该用API还是该开会员”，二是从一开始就把密钥和费用管好**。这两件事想明白了，后面照着官方文档走即可。

## 二、一步步做

下面先讲第0步的密钥安全，再用第1～3步讲清思路和数据流，第4步给出一条用编程智能体跑通的最小路径。具体用什么语言、怎么写、调哪个接口，**以官方文档为准**。

### 第0步：先把密钥安顿好（在写任何功能之前）

这一步排在所有功能前面，因为它最容易被忽略、又最容易闯大祸。几条铁律（呼应第37章隐私、第38章费用、第40章安全）：

| 该怎么做 | 为什么 |
| --- | --- |
| **把密钥放进“环境变量”或`.env`文件，别写进代码里** | 写死在代码里，密钥就跟着代码到处跑、随时可能泄露 |
| **把`.env`写进`.gitignore`，绝不把密钥提交到仓库（尤其是公开的GitHub）** | 公开仓库里的密钥会被自动扫描程序很快捡走、盗用；就算事后删掉，Git历史里也还留着 |
| **密钥由你自己设置，不贴进任何对话** | 包括你和编程智能体的对话。贴进去就等于交了出去（第37章） |
| **去平台后台给账号设“用量上限 / 预算告警”** | 万一密钥泄露、或程序写出死循环狂刷，上限能帮你兜住损失 |

几个词先说明白：“环境变量”通俗说，就是把密钥这种敏感信息**放在程序外面**、运行时再读进来，而不是明晃晃写在代码文件里。`.env`是放在项目文件夹里、专门存这类设置的文本文件。`.gitignore`是一份清单，告诉Git“这些文件别记录”，把`.env`写进去，它就不会被提交。

还有一点容易被忽略：**编程智能体可能会读取项目里的文件，包括`.env`。** 所以密钥要你自己设，并且在工具允许的地方，限制它读取这个文件。截至2026年10月，Claude Code可以在设置文件的拒绝规则里写`Read(./.env)`；Codex可以在权限配置里把`.env`设为`deny`。这些规则不一定覆盖所有读取途径（比如它运行的脚本自己去读文件），所以它们是多加的一层，不是保险箱。万一怀疑密钥泄露，立刻去后台作废、换新（第40章）。

具体怎么设环境变量、怎么设用量上限、怎么写拒绝规则，**以官方文档为准**——但“放外面、别提交、别贴进对话、设上限”这几条原则是通用的。

> 把这一步当成“接API的安全带”：车还没开，带子先系好。

### 第1步：让程序代你“问一句”

最小可跑的核心，就一件事：**你的程序把一个问题，通过API发给模型。** 用大白话描述这条请求：

```text
（你的程序，在背后自动做这件事）
对模型说：「这是一段用户留言，请帮我判断它是好评还是差评，
          只回答'好评'或'差评'。留言内容：……」
```

这和你在聊天框里打字本质一样——都是“把一段话发给模型”。区别只在于：**现在是程序替你发，而且可以一天发一万次，不用你手动打。** 发什么内容（也就是“提示词”），还是第11章那套讲究：把要求说清楚、把格式定死。

### 第2步：把模型的回答接回来

模型处理完，会把回答**传回给你的程序**。你的程序拿到的，通常是一段文字（或带点结构的数据，具体格式**以官方文档为准**）。

这里有个新手常踩的认知坑：**模型返回的内容仍然可能出错、可能不按你要的格式来**（幻觉照样发生，第9章）。你让它“只回答好评或差评”，它偶尔可能回一整句解释。所以程序里要**对返回结果做检查和兜底**——这部分属于工程细节，但理念你得有：**别假设模型每次都乖乖听话。**

### 第3步：把回答“用起来”，嵌进你的应用

拿到回答后，接下来就和AI没关系了——是你**自己应用的逻辑**：把“好评/差评”存进数据库、显示在页面上、触发一封通知邮件……这部分完全由你的程序决定。

把整条数据流连起来看，就是这么一条线：

```text
 用户/你的数据
      │
      ▼
 你的程序  ──(通过 API，带着密钥)──→  模型
      ▲                                │
      │                                ▼
      └────────  模型把回答传回  ───────┘
      │
      ▼
 你的程序把回答用起来（存库 / 显示 / 触发下一步）
```

看明白这条线，你就抓住了“给程序接AI”的核心：**你的程序把问题发出去、把回答收回来、再嵌进自己的流程。** 中间那个“模型”是租来的能力，你付的是token的账。

### 第4步：最小可跑路径——让编程智能体照官方快速入门写一个脚本

截至2026年10月，OpenAI和Anthropic的官方快速入门都是同一个路子：在后台创建密钥 → 把密钥设成环境变量（OpenAI用`OPENAI_API_KEY`，Anthropic用`ANTHROPIC_API_KEY`）→ 安装官方SDK → 运行一段很短的示例，SDK会自动从环境变量读取密钥。你不用记这些细节，照下面做：

1. **建项目文件夹。** 比如`api-hello`，按第26章用Git起步。在这个文件夹里启动编程智能体（第28、29章）。
2. **让它先建好`.gitignore`。** 跟它说：“请在这个文件夹里建一个`.gitignore`文件，里面写上`.env`。”确认文件里真的有这一行。
3. **你自己设置密钥。** 去厂商后台创建密钥、设好用量上限。然后二选一：按官方快速入门，在你自己的终端里把密钥设成环境变量；或者用文本编辑器打开项目里的`.env`文件，自己写一行`变量名=你的密钥`。整个过程不经过AI，也别把密钥贴进对话。用`.env`时，脚本需要额外加载这个文件，让AI按官方说明处理。
4. **限制它读`.env`。** 在你用的工具里，能加读取限制的就加上（见第0步）。
5. **请它写脚本**，大致这样说：

> 大白话请求：*“请按<厂商名>官方快速入门（quickstart）的最新写法，在这个文件夹里写一个最小的脚本：把一句用户留言发给模型，让它只回答‘好评’或‘差评’，然后把结果打印出来。要求：密钥只从环境变量<变量名>读取，代码里不要出现密钥，也不要打印密钥；不要让我把密钥发给你，也不要去读`.env`文件；需要安装什么，先告诉我、等我同意再装；最后告诉我用哪条命令运行。”*

6. **运行并验收。** 在设好密钥的那个终端里，用它给的命令运行脚本（比如`python quickstart.py`；如果让智能体代为运行，先看清它要执行的命令再批准）。先用两三条普通留言，再喂一条刁钻的（比如一句与评价无关的话），看结果。

### 看结果 / 验收

最小版本跑起来后，按这几条验收：

1. **能不能稳定地“发出去、收回来”？** 拿几条真实数据走一遍，确认这条流水线通了。
2. **密钥安全吗？** 回头检查：密钥是不是只在环境变量或`.env`里、没写进代码、没提交到仓库、没出现在对话里、设了用量上限。**这一条要反复确认。**
3. **返回结果有没有兜底？** 故意喂一条刁钻的输入，看模型不按格式回时，你的程序会不会崩、有没有处理。
4. **花了多少钱？** 去平台后台看一眼这次测试的用量和花费，对“调一次大概多少钱”建立直觉（第38章）。

### 完成标准

下面几条都做到了，这个项目就算完成：

- 脚本能跑通：给一条留言，打印出“好评”或“差评”。
- 代码文件里搜不到你的密钥；`git status`里看不到`.env`（它被`.gitignore`挡住了）。
- 你从没把密钥贴进任何对话；工具里能限制读取`.env`的地方已经限制。
- 平台后台设了用量上限或预算告警，你也看过这次测试花了多少。
- 喂一条刁钻的输入时，程序不会崩，或者会给出一个兜底结果（比如“无法判断”）。

## 三、常见坑

| 坑 | 怎么回事 / 怎么躲 |
| --- | --- |
| **以为“接API = 开会员”** | 这是最大的误区。开会员是给**人**用产品；接API是给**程序**用接口，要申请密钥、按token计费（第17章）。先分清你要哪个 |
| **把密钥写死在代码里 / 提交到公开仓库** | 等于把家门钥匙贴在门上。密钥放环境变量或`.env`、`.env`进`.gitignore`、设上限——**第一行代码之前就做**（第37、38章） |
| **把密钥贴给编程智能体，让它“帮你配好”** | 贴进对话就等于交了出去。密钥你自己设，让它写“从环境变量读取”的代码就行 |
| **没设用量上限，被狂刷或死循环烧爆** | 程序一个bug可能一秒调几百次。后台设好预算告警和用量上限，给账单兜底（第38章） |
| **假设模型每次都按格式乖乖回** | 它会出错、会跑偏（第9章）。程序里要对返回结果做检查和兜底，别裸奔 |
| **把用户隐私数据原样发给API** | 记住第37章那句话：**发进去就等于交出去了**。敏感信息要先脱敏，是否用于训练取决于条款与设置（第37章，以官方文档为准） |
| **照着网上某段旧代码硬抄** | 各家API写法不同、还常更新。让智能体按**官方快速入门的最新写法**来，别迷信过时的代码片段 |

## 四、可以再往前一步

最小流水线跑通后，可以这样扩展（每一步都别忘了密钥和费用这根弦）：

- **把“提示词”打磨好**：你发给模型的那段话，质量直接决定回答质量。把第11、12章的提示词技巧用上，必要时固化成模板。
- **接更结构化的输出**：让模型返回更规整的结构（方便程序直接用），具体怎么要求**以官方文档为准**。
- **省着用token**：批量调用时，token就是钱。别把无关的长文一股脑塞进每次请求，保持请求精简（第38章那套“省着用”在这里直接变成省钱）。
- **如果开始让程序“自己做多步、调工具”**：那你其实正在从“调一次API”走向搭一个**Agent**（第19、34章）——这时第34章那套“装刹车”的纪律就得跟上：花钱、删数据、对外发送，仍要设成需要人确认。
- **想给它接公司内部资料 / 外部工具**：那是第22、36章Skills / MCP的话题——每接一个新源，都是一个新的风险入口。

> **要点：** “给程序接AI”就是用**API**（第17章）：你的程序把问题发给模型、拿回答、再嵌进自己的应用，思路简单，数据流清晰。有两件事要从第一行代码就盯住：**一是接API不等于开会员**（分清人用产品还是程序调接口）；**二是密钥与费用从一开始就管好**——放环境变量或`.env`、`.env`进`.gitignore`、不贴进对话、设用量上限（第37、38章）。具体写法**以官方文档为准**。

## 小结

- “给现有程序接上AI” = 用**API**（第17章第③层）：让你自己的程序在背后自动把问题发给模型、收回答、嵌进应用。
- 最小可跑的数据流就一条线：**你的程序 →（带密钥）→ 模型 → 回答传回 → 程序用起来**。代码让编程智能体照官方快速入门来写，你负责密钥、运行和验收。
- **最大的误区是“接API = 开会员”**：开会员给人用产品，接API给程序用接口、按token计费。
- **密钥与费用从写第一行就管好**：放环境变量或`.env`（并写进`.gitignore`）、别写进代码、别贴进对话、设用量上限；编程智能体可能读`.env`，能限制就限制（呼应第37、38、40章）。
- 模型返回的内容仍会出错、会不按格式来（第9章），程序要做检查和兜底；发进去的数据等于交出去了，敏感信息先脱敏（第37章）。

下一章，我们把第22章那两个概念——**Skills与MCP**——真正落地，给AI扩展出读数据、用工具的新能力。

   > **答案B。** 公开仓库会被专门的扫描程序盯着，明文密钥往往很快就被捡走。正确做法是**密钥放环境变量或`.env`、把`.env`写进`.gitignore`、绝不提交，并设用量上限兜底**（第37、38章）。A低估了自动扫描；C不成立，密钥写进去就是明文；D也不行，删掉一行后，那次提交仍留在Git历史里，已经泄露的密钥要去后台作废、换新。

5. **[基础·情景题]** 你的程序通过API让模型“只回答‘好评’或‘差评’”，但它偶尔回了一整句解释。最该怎么办？ <!-- quiz: q05 revision: 1 -->
   - A. 换一把新密钥，旧密钥可能有问题
   - B. 认定API坏了，改用聊天界面手动做
   - C. 程序里检查返回值，不合格式就兜底
   - D. 一直自动重试，直到它按格式回答为止
   > **答案C。** 模型返回的内容仍可能出错、不按格式（幻觉照样发生，第9章）。健壮的程序会预设“它可能不听话”，对返回值做检查和兜底。A和B把正常现象当成了故障；D不设上限地重试，可能一直不成功，还会白白烧钱（第38章）。
