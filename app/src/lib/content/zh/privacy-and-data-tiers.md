把文档交给 AI 前，先问：**数据会去哪里，谁能访问，这条路径适合当前任务吗？** 答案取决于整个产品和工作流程，不只是模型名称。

本章给你一把实用的四级尺子：在合适的保护下使用有价值的信息，同时把真实密码和密钥留在安全设置里。

## 一、沿着数据找路径，也要看工具

AI 应用发送的可能不止你刚打的那句话。选入上下文的历史消息、附件、检索到的文档、截图和工具结果，都可能成为模型输入。应用会选择、概括或截断上下文，并不一定每轮都发送完整历史。

| 路径 | 要检查什么 |
| --- | --- |
| **云端模型** | 哪家供应商接收所选上下文，使用哪个账号和哪套条款 |
| **本地模型** | 推理是否留在设备上，应用是否还使用云端功能 |
| **连接的工具** | 搜索服务、连接器、外部 API 或远程 MCP 服务器收到和返回什么 |
| **模型周围的存储** | 聊天历史、运行日志、追踪记录、缓存、共享文件夹和备份 |

本地模型可以把推理留在你的机器上，但不自动意味着**整个流程**离线：网页搜索可能把查询发出去，连接器可能读取私人资料，追踪服务可能记录工具输入和输出。本地文件和备份同样需要访问控制。

反过来，用云端产品也不表示所有连接方都会收到一切。要查看实际路径和权限。画一条简单的线——**来源 → 应用 → 模型/工具 → 日志/存储**——通常比“本地”“企业版”标签更能说明问题。

## 二、训练、保留与访问，分别看

这是几个不同的问题：

| 问题 | 要查清什么 |
| --- | --- |
| **训练** | 内容是否用于改进模型？适用什么开关和例外？ |
| **保留** | 保存什么、多久，删除操作会移除什么？ |
| **访问与共享** | 工作区成员、管理员、供应商或工具服务能否访问？ |
| **位置与合同** | 当前服务和数据路径是否获准用于组织及这项任务？ |

**“不用于训练”不等于“不保留”。** 产品可能按另一套规则保留历史、运行记录或工具追踪。关闭历史、新开聊天、删除聊天，也可能各有不同作用。不要假定其中任何一个操作会立即抹掉全部日志和备份。

要看具体产品、套餐、设置和合同。企业账号或 API 的条款可能不同于个人聊天账号，但“付费”两个字本身不能回答这些问题。连接的工具也可能另有政策。别背一个通用保留天数，应查实际路径当前适用的规定。

## 三、数据四级：实用默认值，不是通用法律

所在组织可能使用不同名称，或有更严格的规则。下面这张表，是日常判断的起点。

| 级别 | 例子 | 默认做法 |
| --- | --- | --- |
| **1. 公开** | 已发表文章、公开产品介绍 | 通常适合使用；仍需尊重使用权，检查是否混入私人材料 |
| **2. 内部** | 日常工作草稿、未公开会议议程 | 使用获准工具，只提供必要部分 |
| **3. 敏感** | 客户记录、私人合同、个人信息 | 采用授权流程，设置合适的访问、保留和数据处理规则；移除任务不需要的细节 |
| **4. 高度受限** | 生产凭证、身份证件、医疗记录、核心商业秘密 | 凭证不进提示词；其他高度受限数据只在专门批准且保护适当的环境处理 |

数据最小化，就是**只提供任务需要的信息**。请 AI 润色客户邮件，可以把姓名换成“客户 A”，去掉账号。确实需要识别具体客户的客服流程，则可以在权限适当、经过批准的系统中处理这类信息。

去掉姓名，不自动等于匿名，也不会自动降低级别。地址、罕见职位、订单历史或多项细节组合，仍可能识别一个人。截图和附件同样算数据。

> **要点：** 敏感个人信息不适合随手贴进任意聊天框。这不等于一切经过正式授权的医疗、客服或内部流程都禁止使用 AI。要让信息、用途、服务和保护措施相匹配。

## 四、真实凭证，放进安全设置

密码、API 密钥、会话 Cookie 和访问令牌都代表能力：能使用它们的人或程序，可能就能读数据、改系统或花钱。

示例里用 `YOUR_API_KEY` 这样的占位符。真实凭证放进产品指定的密钥设置、密钥管理器或批准的认证流程，不要贴进聊天、源代码、截图或诊断日志。即便安全保存，也要限制谁能使用，以及凭证的权限范围。

**你没有输入密钥，连接的 Agent 也可能已经有权限。** 已登录的账号或连接器，可能让它通过委托访问来读取文档或发送消息。只连接任务需要的账号和工具，数据发出前检查目的地。

如果真实凭证意外暴露，把它视为可能已泄露：尽快撤销或轮换，检查相关访问记录，并按服务或团队的事件处理流程执行。仅删除聊天，不会让凭证失效，也不能移除所有副本。

## 小结

- 沿模型、连接的工具、日志和备份检查数据。“本地模型”只描述这条路径的一部分。
- 训练、保留、访问与删除，是不同的控制。
- 用数据分级和最小化做判断；授权的敏感数据流程仍需要适当保护。
- 真实凭证放在安全设置里，也要限制连接器已经获得的权限。
- 密钥暴露后应轮换和调查，不能只靠删除聊天。

1. **[基础·概念]** AI 流程中的信息可能去哪里？ <!-- quiz: q01 revision: 1 -->
   - A. 只去聊天窗口
   - B. 只去模型训练集
   - C. 根据配置，可能去模型、工具、日志和存储
   - D. 永远发给每一个已连接服务
   > **答案：C。** 要追踪实际数据路径。模型上下文可能包含所选文件、工具结果，而不只是输入的消息。

2. **[基础·概念]** 配置一个已获准的集成时，真实 API 密钥放哪里？ <!-- quiz: q02 revision: 1 -->
   - A. 提示词里
   - B. 公开代码示例里
   - C. 聊天附件截图里
   - D. 指定的安全设置或获准密钥管理器里
   > **答案：D。** 讨论配置时用占位符。安全存储还应限制谁、哪些程序能够使用密钥。

3. **[进阶·误区]** 服务承诺不拿你的内容训练，还要查什么？ <!-- quiz: q03 revision: 1 -->
   - A. 什么都不用查，它不可能保留任何内容
   - B. 保留、访问、删除，以及连接工具如何处理数据
   - C. 只看模型名字
   - D. 聊天窗口用深色还是浅色
   > **答案：B。** 不训练是一项具体承诺，不是零存储承诺，也不代表可以任意处理敏感数据。

4. **[进阶·情景]** 本地模型连接了云端搜索和远程追踪，整个流程一定离线吗？ <!-- quiz: q04 revision: 1 -->
   - A. 是，因为模型在本地
   - B. 新开聊天就一定离线
   - C. 不是，工具请求和追踪记录可能离开设备
   - D. 本地模型都不能离线运行
   > **答案：C。** 本地推理可以离线，但完整数据路径由周围的应用和工具共同决定。

5. **[基础·情景]** 只需要润色邮件措辞，客户姓名和账号怎样处理更合适？ <!-- quiz: q05 revision: 1 -->
   - A. 即使没用也全部提供
   - B. 替换或去除，使用获准服务
   - C. 发截图，这样它们就不算数据
   - D. 相信去掉姓名就一定匿名
   > **答案：B。** 尽量少提供。其他细节仍可能识别人，删姓名不是保证。正式批准的流程可以在适当保护下处理必要个人信息。

6. **[操作·观察]** 不输入任何私人信息，检查你常用的一个 AI 应用：模型路径、连接工具、训练设置、保留或删除政策分别是什么？ <!-- quiz: q06 revision: 1 -->
   > **应当观察到：** 答案可能分散在不同设置或文档里。也要包括自己控制的日志、共享工作区和备份。若真实凭证已经暴露，需要撤销或轮换；删聊天不能代替它。
