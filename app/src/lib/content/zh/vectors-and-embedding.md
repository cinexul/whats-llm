第4章我们看到，模型靠"猜下一个词"把话顺出来。但这里有个绕不过去的难题：计算机只认数字，它根本不认识"猫""狗""开心"这些字。那它怎么知道**"猫"和"狗"意思相近，而"猫"和"钢筋"八竿子打不着**?它又怎么算得出"哪些词该接在一起"?

答案藏在一个听起来很数学、其实特别好懂的想法里：**给每个词、每句话，都安一个"坐标"。在适合的嵌入模型中，相关的意思往往得到相近的坐标。** 这个"坐标"就是本章的两个主角——**向量（vector）**和**嵌入（embedding）**。

这章是第一部分里最"抽象"的一章，但它撑起了后面一大块内容：为什么"换个说法"结果就变（第11章）,搜索和 RAG（第20章）凭什么能"按意思"找资料。咱们用好比喻，一步步来，保证不掉队。

## 一、核心想法：把"意思"变成"坐标"

先做个你熟悉的类比：**地图上的城市，用经纬度两个数字就能定位。**

- 北京是 `(116, 40)`,天津是 `(117, 39)`——两组数字很接近，因为两座城市**地理上很近**。
- 上海是 `(121, 31)`,离北京那组数字就**远一些**。

光凭这两个数字，计算机不用"认识"城市，只要**算两组数字的距离**,就知道谁离谁近。

**向量与 embedding 干的，就是把这套"用坐标表示远近"的思路，搬到"词义"上。** 只不过这次，坐标表示的不是"地理位置"的远近，而是**"意思"的远近**:

```text
地图:    用 (经度, 纬度) 表示"地理位置"  →  算距离 = 地理上多近
词义图:  用 (一长串数字)  表示"意思"     →  算距离 = 意思上多近
```

- **向量（vector）**:就是这"一长串数字"本身——给某个词/句子安的那个"坐标"。（地图坐标只有 2 个数字；词义的坐标要用到**几百甚至上千个数字**,因为"意思"比"地理位置"复杂太多，两三个数字根本不够分。）
- **嵌入（embedding）**:就是"**把一段文字转换成这种坐标**"这件事（以及转出来的结果）。"嵌入"这个名字的意思是，把词"嵌进"一个用坐标描述的空间里，让每个词都有个落脚点。

> **要点：** embedding 把文字映射为向量，也就是可以帮助估计语义相似度的数值表示。这是从数据学到的近似，并非完美的语义地图。相似度取决于嵌入模型、语境与比较方法；相关内容可能被漏掉，无关内容也可能显得很近。

## 二、为什么非得这么做？因为计算机只会算数

退一步想想：为什么要费这么大劲，把好端端的词变成一串数字？

因为前几章那台"猜下一个词"的机器，**底层全是数字运算**（第1、2章）。它没法直接对"猫"这个字做加减乘除——可一旦把"猫"变成一串数字（坐标）,一切就**可计算**了：

- 想知道两个词意思近不近？→ **算两个坐标的距离**（近 = 意思近）。
- 想给一堆资料"按相关性排序"?→ 把它们都变成坐标，**按离问题的坐标远近排队**。
- 模型内部要判断"这个词该不该接在那个词后面"?→ 同样靠坐标之间的数学关系。

```text
没有坐标:  计算机面对"猫"和"狗" → 两个它不认识的符号,无从下手
有了坐标:  "猫"→一串数字, "狗"→一串数字 → 一算距离,发现很近 → "哦,这俩意思相近"
```

> **为什么需要它？** 嵌入是让文本之间的关系可计算的一种方法，可用于语义搜索，但不是找相关资料的唯一方式；关键词搜索、同义词规则等技术同样有用。

## 三、最有名的直觉：词义能在坐标上做"加减法"

这是 embedding 最让人拍案叫绝的地方，几乎成了它的招牌例子。

既然词变成了坐标（向量）,坐标是能做加减的。神奇的是，**在意思的坐标上做加减，结果居然也符合意思的逻辑**。最经典的一个：

```text
   "国王" 的坐标  −  "男人" 的坐标  +  "女人" 的坐标  ≈  "女王" 的坐标
```

读出来就是：**国王 减去"男性",再加上"女性",得到的坐标，正好落在"女王"附近。**

为什么会这样？因为训练时，模型从海量文本里发现："国王"和"男人"、"女王"和"女人"的搭配方式很像；"国王"和"女王"的差别，跟"男人"和"女人"的差别又是同一种差别（都是"性别"那点不同）。于是这层"性别关系",就被它**编码成了坐标上一个固定的"方向"**——沿着这个方向走，就是"换个性别"。

类似的还有很多：

| 坐标上的加减 | 结果大致落在 | 它捕捉到的关系 |
| --- | --- | --- |
| 巴黎 − 法国 + 日本 | ≈ 东京 | "某国的首都"这层关系 |
| 走 → 走了、跑 → 跑了 | 同一个"方向" | "变成过去式"这层关系 |
| 大 → 更大、小 → 更小 | 同一个"方向" | "程度加深"这层关系 |

> **要点：** 别被"加减法"吓到，它想说的其实很朴素：**词与词之间的"意思关系"（性别、首都、时态……）,在坐标空间里变成了可以计算的"方向和距离"。** 这正说明 embedding 装进去的不是孤立的词，而是**词与词之间成体系的意思关系**。（这里的"≈"是"大约落在附近",不是分毫不差的等号——它是统计出来的近似，会有误差。）

## 四、搜索表示既不是原文档案，也不是隐私保证

这是本章最该破除的误会，务必记牢。

embedding 是用于比较文本的学习得到的数值表示。它**不是带有标准“解压”操作的无损档案**，因此检索系统通常另存原文。

但**不能直接看懂，不等于不可能重建**。embedding 反演研究已在特定条件下恢复出大量原句，有时甚至逐字还原。恢复效果取决于模型、文本、攻击者掌握的信息与方法。embedding **不是加密，也不保证匿名化**；敏感数据的向量同样需要保护。

```text
原文:        "今天我去公园散步,心情很好。"
做成 embedding: [0.12, -0.83, 0.05, 0.41, ……]  ← 几百个数字
能用普通解码器准确还原吗？没有通用保证；但反演攻击仍可能恢复文本。
能干什么?       能算出它和别的句子"意思有多近"。
```

“口味坐标”的比喻有助于理解相似度：测量值接近的两道菜可能味道相近。但比喻也有边界：测量结果可能泄露原料。文本向量也可能泄露来源信息，因此不能把这个比喻当成安全保证。

> **实用规则：** RAG 需要可靠引用时，应**另存原文及出处**，由向量帮助找到相关资料。原文与向量都应有合适的访问控制；把敏感文本转成 embedding，并不自动使它适合公开。

## 五、它有什么用：语义搜索与 RAG

嵌入的重要用途之一是**语义搜索**：即使用词不同，也寻找意思相关的资料。这是 RAG（第20章）常用的一种检索方法。

简单的关键词搜索可能因用词不同而漏掉资料。例如，"让电脑跑快点"与"提升计算机性能"表达相近，却采用不同词语。关键词系统也能使用同义词等匹配技术，不能简单把区别说成"字面与意思"。

embedding 提供了另一种思路：**先把资料表示为向量，再按相似度搜索**：

```text
按意思搜索(embedding)大致流程:
  ① 提前:把资料库里每一段都做成 embedding(各编一个"意思坐标")
  ② 你提问:"怎么让电脑跑快点" → 也做成 embedding(一个坐标)
  ③ 在坐标空间里,找离你这个问题坐标"最近"的几段资料
  ④ 用词不同的段落，也可能因向量相似而排在前面；还要检查实际相关性
```

嵌入搜索可能把"提升计算机性能"的文章排在前面，因为它的向量与查询相似。这是有用的信号，但不保证文章相关或正确。

**RAG（检索增强生成，第20章）**先检索相关资料，再把资料作为上下文交给模型生成回答。检索可以采用**嵌入、关键词，或两者结合**，并不强制使用 embedding。无论哪种方法，都要检查检索段落及来源：检索可减少无依据的回答，也可能漏掉证据或找到误导性材料。

> **实际会怎么遇到：** 当你听到某个产品说"它能理解你的意思来搜索""能从你上传的几百页文档里找到相关段落",背后多半就是 embedding 在干活——把文档和你的问题都变成坐标，按远近匹配。具体某个产品怎么实现、效果如何，**以官方文档为准**;但"先编坐标、再按意思找"这个原理是相通的。

## 六、回扣一个老问题：为什么"换个说法，结果就变"?

学了 embedding,第4章和后面第11章一个常见困惑，这下能解释了。

你大概遇到过：同一个意思，**换几个词**去问 AI,得到的回答**明显不一样**。为什么这么敏感？

措辞变化可能改变分词、内部表示，以及模型对指令的理解。同样的措辞也可能因采样得到不同回答。**语言模型内部的 token 嵌入与搜索用的句子嵌入是相关概念，但不是同一种表示，也不能单独解释完整输出。**

> **要点：** 清晰指令有助于改善结果，但不存在保证答对的单一“正确坐标”。应按任务要求比较输出，不能只从回复不同就推出 embedding 距离（第11章）。

## 七、常见误解，集中纠正

| 误解 | 实际 |
| --- | --- |
| embedding 是能完整恢复的文本档案 | 它是学习得到的表示，不保证通用无损解码；但反演攻击仍可能重建部分文本 |
| 向量能安全隐藏原文 | embedding 不是加密，也不保证匿名化；敏感向量与原始文档都要保护 |
| 两个数字（像经纬度）就够表示词义了 | 词义太复杂，要用**几百上千个数字**才够分，远不止两三维 |
| "国王−男人+女人≈女王"是巧合 | 那是训练把**词与词的意思关系**编成了坐标上的"方向";"≈"是近似，有误差 |
| 语义搜索必须用词完全一样 | 嵌入可以找到相关表达；关键词和混合搜索也有用，检索质量仍要评估 |
| 换个说法结果就变，是 AI 出 bug | 措辞、上下文、模型处理与采样都会影响答案；答案变化本身不能诊断故障 |

## 小结

- **核心想法**:给词和句子安一个"**意思的坐标**"——这串数字就是**向量（vector）**,生成它的过程/结果叫**嵌入（embedding）**;**坐标可以帮助估计语义相似度**。
- **为什么需要它**:计算机只会算数，不认识字；变成坐标后，机器就能**用算距离的方式"感觉到"词义远近**——这是它处理语义的桥梁。
- **招牌直觉**:"国王 − 男人 + 女人 ≈ 女王"——词与词的**意思关系**,在坐标空间里成了**可计算的方向**;"≈"是近似，有误差。
- **核心纠错**：embedding 用于相似度检索，不能替代可靠的原文存储，也不提供隐私保证。特定条件下可以重建文本，所以敏感向量仍需保护。
- **重要用途之一**：语义搜索与 RAG（第20章）。嵌入是一种检索选择，关键词和混合搜索也可以找到有用证据。
- **回扣**：改写提示可能改变结果，但输出差异不能直接度量语义距离。应比较提示是否清晰，并核实答案（第4、11章）。

这一章合上，第一部分关于"模型内功"的核心就齐了：token 与上下文（第3章）、怎么猜下一个词（第4章）、怎么用坐标表示词义（第5章）。接下来（第6章）,我们再看一个让它**会"划重点"**的关键机件——注意力与 Transformer（纯直觉、零公式）。

## 小测验

> 共 6 题，涵盖概念、误区、情景、操作四类。答案与解析在每题下方的引用块里——先自己想，再对照。

1. **[基础·概念题]** 把一个词做成 embedding（嵌入）,最贴切的理解是？ <!-- quiz: q01 revision: 1 -->
   - A. 把这个词翻译成英文
   - B. 给这个词一个数值表示，用来帮助比较语义相似度
   - C. 把这个词存进数据库等着检索
   - D. 给这个词加密
   > **答案 B。** 嵌入是帮助比较文本的数值表示，相似度是近似的，取决于模型与比较方法。A 是翻译；C 描述存储记录，而非构造嵌入；D 错在把嵌入当成加密。

2. **[基础·概念题]** 为什么要把词变成一串数字（向量）,而不是让计算机直接处理文字？ <!-- quiz: q02 revision: 1 -->
   - A. 数字看起来更高级
   - B. 计算机只会算数、不认识字；变成坐标后，机器才能用"算距离"的方式判断意思远近
   - C. 这样能节省硬盘空间
   - D. 文字会让模型变慢
   > **答案 B。** 这是把"意思"翻译成机器唯一懂的语言（数字）的桥梁——有了坐标，"哪两个词意思像"才变得可计算（承接第1、2章：底层全是数字运算）。A、C、D 都没说到要害：关键不是好看或省空间，而是**让语义变得可算**。

3. **[进阶·误区题]** “敏感文本变成 embedding 后，别人不可能还原，因此可以公开。”错在哪？ <!-- quiz: q03 revision: 1 -->
   - A. 没错，任何 embedding 都是安全的加密
   - B. embedding 不是加密；反演攻击可能在特定条件下恢复信息或原文，向量仍需保护
   - C. 每个向量都能用任意模型完整、准确地解码
   - D. 向量里存的是英文翻译
   > **答案 B。** 没有通用无损解码器，不等于保证保密。研究已展示某些模型与条件下的文本重建。A 混淆了向量与加密；C 夸大了恢复能力；D 不是 embedding 的含义。可靠检索需要另存原文，敏感向量仍需保护。

4. **[进阶·概念题]** "国王 − 男人 + 女人 ≈ 女王"这个著名例子，最能说明 embedding 的什么特点？ <!-- quiz: q04 revision: 1 -->
   - A. 模型会做小学算术
   - B. 词与词之间的"意思关系"（如性别）,在坐标空间里变成了可以计算的"方向";关系能在坐标上做加减
   - C. 国王和女王是同义词
   - D. embedding 存了这四个词的原文
   > **答案 B。** 它说明 embedding 装进去的不是孤立的词，而是**成体系的意思关系**——"换性别"被编成了坐标上一个固定方向，所以能做这种加减。A 误以为是普通算术（它算的是"意思坐标",不是数值题）;C、D 都理解偏了。注意"≈"是近似、有误差。

5. **[基础·情景题]** 你在一个支持"按意思搜索"的工具里搜"怎么让电脑跑快点",结果它把一篇标题为《提升计算机性能的方法》、通篇没出现"跑快点"字样的文章排在了最前面。最合理的解释是？ <!-- quiz: q05 revision: 1 -->
   - A. 工具出 bug 了，关键词都没对上
   - B. 它用 embedding 比的是**意思**不是**字面**:两段文字"意思的坐标"很近，所以哪怕用词不同也被捞了出来
   - C. 那篇文章偷偷塞了关键词
   - D. 纯属巧合
   > **答案 B。** 嵌入搜索可以按向量相似度排列段落，即使关键短语不同。这是一种合理解释，并不能证明工具内部一定这样实现：支持同义词的关键词搜索或混合搜索也能找到相关表达。检索到的文章仍要检查实际相关性。

6. **[基础·操作/观察题]** 用“让这段更易读”“润色这段文字”“修正不通顺的句子”三种提示，请同一个模型修改同一段公开文字。记录哪些修改符合预期任务。这个比较能说明什么，又不能证明 embedding 的什么性质？ <!-- quiz: q06 revision: 1 -->
   > **该观察到：** 措辞可能变化，但这个实验不能测出 embedding 距离，也不能单独证明变化的原因：采样、指令与模型整体处理都会影响回答。可以比较哪个提示更清楚地说明了任务。若要直接检验语义相似度，应使用同一个 embedding 模型处理所有例句，再比较相似度分数；不同模型的向量不能直接混比。
