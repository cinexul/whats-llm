詩も書けるし、コードも直せるし、長い文章をきれいに要約もできる。それでも、がっかりする場面に二つほど出くわしたことがあるでしょう。一つは、大まじめに間違えること。存在しない論文を引用し、調べても出てこない「専門家」の名前を挙げ、数字をそれらしく作ってしまいます。もう一つは、あなたを覚えていないこと。昨日伝えたばかりのことも、今日新しい会話を始めると、まったく知らない様子です。

どちらもAIの仕組みから来ていて、「手を抜いている」わけではありません。この章では三つのことを扱います。なぜ間違えるのか（ハルシネーション）、間違いをどう見つけるのか（確認）、そして何をずっと覚えていて、何をすぐ忘れるのか（知識と記憶）です。本書のほかの章で「確認しましょう」と言うときは、この章のやり方のことです。

## 一、ハルシネーション：存在しないものを、本物のように語る

**ハルシネーション**（hallucination）とは、モデルが存在しないことや間違ったことを、本当のことのように話してしまうことです。間違えること自体は珍しくありません。誰でも間違えます。困るのは、間違った内容が正しい内容と同じくらい流暢で自信ありげなので、言い方だけでは見分けにくいことです。

なぜこうなるのでしょう。理由は二つあります。

一つは、生成するときに真偽を調べていないことです。モデルがしているのは、前の文脈からもっともらしい続きを書くことで（第4章）、一つずつ照らし合わせる「事実データベース」は手元にありません。知識が足りないとき、「よく分かりません」と言うこともできますし、実際にそう言うこともあります。でも、話の流れに乗って、いちばん自然に読める答えを続けてしまうこともあります。偽の論文がタイトルも著者も学術誌もそろって本物らしく見えるのは、本物の論文を何千、何万と見てきたからです。嘘をついているのではありません（嘘をつくには、まず本当のことを知っている必要があります）。自信がないときにも、そのまま話を続けてしまうのです。

もう一つは、学習と評価がしばしば「当てずっぽう」を後押しすることです。2025年9月、OpenAIの研究者は論文「Why Language Models Hallucinate」と同時に出した紹介記事で、こう指摘しました。多くの評価は正解かどうかだけで採点し、「分かりません」と答えても間違えても同じ0点になる。間違えても減点されない選択式テストと同じで、空欄にするより何か書いたほうが得です。この基準で最適化されたモデルは、「自信がなくても何か答える」ことを覚えやすくなります。研究者たちは、間違いを「分かりません」より重く減点して、自信がないと正直に言っても損をしないようにしようと提案しています。

では、AIが見せる「自信」は参考になるのでしょうか。少しは参考になりますが、証拠にはなりません。モデルの自信の度合いと正解の可能性には、ある程度の関係があります。AIがはっきり「確信がありません」と言うところは、実際に間違いやすいことが多いので、気にかけておきましょう。逆は成り立ちません。言い切っていて流暢だからといって、正しいとは限りません。

## 二、どう確かめるか：そのまま使える手順

すべての文を確かめる必要はありません。アイデア出し、言い回しの手直し、タイトル案なら、見て良さそうならそれで十分です。ただし、次のものは間違えたときの代償が大きいので、一つずつ確かめます。数字や金額、日付、人名や組織名、引用や出典、リンク、法律・医療・お金に関わる結論、「最近の出来事」、それから実際に動かすコードや計算式です。

確認は四つの手順で進められます。

1. まず、作り話をしにくくする。信頼できる資料を貼り付け、その資料だけをもとに答えるよう頼み、資料にないことは「資料にはありません」と答えるように伝えます。あわせて「確信がなければ、確信がないと言ってください」と書いておきます。これで間違いは少し減りますが、この後の手順の代わりにはなりません。
2. 根拠を出させる。大事な主張ごとに、どの資料のどの文から来ているか、または開けるリンクを示してもらいます。根拠を言えないところ、根拠があいまいなところこそ、しっかり確かめる場所です。
3. 自分で出どころを見に行く。リンクを開いて、ページが実在し、原文に本当にそう書いてあるかを確かめます。タイトルだけで判断しないでください。引用は一字一句照らし合わせ、数字は元の表や報告書に戻って確認します。論文や本は、タイトルで学術検索や出版社のサイトを調べ、DOIの番号があればdoi.orgに入れて開けるか見てみましょう。AIが示した「出典」そのものが作り話のこともあります。
4. 別の独立した情報源でも確かめる。公式サイト、原本の文書、信頼できる参考書などです。計算できるものは電卓や表計算でやり直し、コードは実際に動かしてテストを実行します（第25章）。同じAIに聞き方を変えてもう一度聞いても確認にはなりません。作り話も毎回同じになることがあるからです。別のAIに間違いを探してもらうと怪しいところは見つかりますが、最後は出どころに戻って確かめます。

大事な結論は、出典と確認した日付もついでにメモしておきましょう。次に使うときも、人に聞かれたときも、どこから来た情報か説明できます。一つ目の手順の考え方は「正しく覚えていることに賭けるより、正しい資料を目の前に置く」で、後で扱うRAG（第20章）も同じ考え方です。

## 三、知識と記憶：一枚の表で「覚えている」と「すぐ忘れる」を分ける

AIが「知っている」ものには、実は性質のまったく違う二種類があります。初心者がいちばんよくやる間違いは、この二つを同じものだと思うことです。

- **知識**（knowledge）：学習のときにパラメータに取り込まれた常識や事実。資料を渡さなくても答えられます。「水の沸点」や「唐は宋より前か後か」と聞けば、そのまま答えます。
- **コンテキスト内の記憶**（memory in context）：今回のリクエストのコンテキスト、つまり第3章の「机」の上で使える一時的な情報。伝えた名前や好みは、机の上に残っているか、もう一度置かれたときだけ使えます。ウィンドウを閉じてもチャット履歴が消えるとは限りません。製品が履歴を保存していて、会話を続けるときにその一部をまた渡すこともあります。

並べてみましょう。

| | 知識 | コンテキスト内の記憶 |
| --- | --- | --- |
| どこにあるか | パラメータに取り込まれている（学習時に学んだ） | 今回のリクエストのコンテキストの中だけ |
| どこから来たか | 膨大な学習テキスト | 今回の会話であなたが入れたもの、または製品が代わりに入れたもの |
| どれだけもつか | ずっとある。ただし締め切り日がある（後述） | 今回のコンテキストに入っていなければ使えない。履歴を保存するかは製品しだい |
| 資料なしで答えられるか | はい | いいえ。今回、机の上に何があるかしだい |
| 典型例 | 「パリはフランスの首都」 | 「さっきピーナッツアレルギーだと言ったよね」 |

知識には避けられない制約があります。**知識のカットオフ**（knowledge cutoff）です。学習データには最後の日付があり、それ以降に起きた出来事、出た新バージョン、生まれた新しい言葉を、モデル自身は知りません。それでも聞くと、「分かりません」と言うこともあれば、作り話をすることもあります。たとえば2026年10月時点で、AnthropicはClaude Opus 5.5の信頼できる知識のカットオフを2026年6月としていて、それ以降のことはモデル自身ほとんど知りません。ですから「最近何があったか」を聞くときは、何も調べずに返ってきた答えをうのみにしないでください。ウェブ検索させるか（第19章。検索結果も前の節の手順で確かめます）、最新の資料を貼り付けましょう。

## 四、いちばん解いておきたい誤解：AIは人のように、ずっと自分を覚えているのか？

長く話していると、AIが自分を「知っている」ように感じるのは無理もありません。でも第3章で見たとおり、モデル本体には会話をまたぐ記憶がありません。新しい会話を始めたとき、製品が履歴やメモリ、カスタム指示を渡さなければ、モデルはあなたが前に言ったことを知りません。同じ会話でも長くなってコンテキストの上限に近づくと、製品が要約したり、一部を削ったり、関係する部分だけを探して使ったり、長すぎるリクエストを断ったりして、前のほうの細かいところが抜け落ちることがあります（第3章）。モデル本体には、会話をまたいで何かをしまっておく場所がそもそもないのです。

すぐにこう聞きたくなるでしょう。では、製品の「プロジェクト」や「メモリ」機能はどういうことなのか。好みやプロジェクト全体を覚えているのを見たことがある、と。

答えは、それらの機能がモデルの外側、製品の側に作られているということです。2026年10月時点で、ClaudeやChatGPTなど多くの製品がプロジェクトやメモリのような機能を持っています。ほかにも、コーディングツールのプロジェクト説明ファイル（CLAUDE.mdなど。第28章）、アカウントの個人設定、社内のナレッジベースなどがあります。どれもやっていることは同じで、会話のときに関係する情報を今回のコンテキストに入れ直しています。結局のところ、「記憶のないモデルと、毎回入れ直されるコンテキスト」という組み合わせは変わりません。チャットから覚えておく内容を自動で拾う製品もあり、それが最初からオンになっていることもあります。何をどう覚えるか、どれだけ保存するか、最初からオンかどうか、削除できるかは製品ごとに違い、変わるのも速いので、各製品の公式の説明で確認してください（管理の仕方は第13章、プライバシーに関わる点は第37章）。

| | モデル本体 | 製品レイヤーの「メモリ」 |
| --- | --- | --- |
| 何か | 確率で続きを書く中核 | 製品がモデルの外側に加えた機能 |
| あなたを覚えているか | 過去の会話を自分では保存せず、今回渡された情報だけを見る | 「覚えておくべきこと」を保存しておく |
| どうやっているか | — | 会話のときに、その情報を今回のコンテキストに入れ直す |
| 「覚えている」範囲 | — | 製品が机に戻すと決めた部分だけ。戻されなかったものは、やはり知らない |

この二層を分けて考えれば、こうした機能がどう振る舞うかも予想できます。AIが「覚えている」のは、いつも製品がコンテキストに戻してくれた部分だけです。設定したはずの好みを急に「忘れた」ときは、たいていその情報が今回は机に戻されなかったのでしょう。製品の検索や設定、コンテキストの選び方に原因があるのかもしれませんし、不具合かもしれません。「忘れた」というだけでは、どれなのか分かりません。

## 五、よくある誤解、まとめて正す

| 誤解 | 実際 |
| --- | --- |
| 流暢で自信ありげなほど信頼できる | 流暢さや自信は証拠ではない。「確信がない」と言ったら気にかけ、言い切っていても大事な事実は確かめる |
| AIは決して「分からない」と認めない | 「確信がない」と言うことはでき、そう言ってよいと伝えると役立つことが多い。ただし、毎回自信のなさに気づくとは限らない |
| 間違えるのはたまたま気が散っただけで、注意すれば済む | ハルシネーションは生成の仕方そのものや、当てずっぽうを後押しする学習・評価と関係している。資料を渡す、根拠を求める、出どころで確かめることで防ぐ |
| 同じ質問を何度しても同じ答えなら正しい | 作り話も毎回同じになることがある。独立した情報源で確かめる |
| AIは最近の出来事を知っている | 知識にはカットオフがあり、それ以降のことは知らない。それでも聞くと作り話をすることもある。ウェブ検索させるか資料を渡す |
| 「メモリ」機能があるなら、モデル本体が自分を覚えている | 製品の側が情報をコンテキストに入れ直しているのであって、モデル本体は覚えていない |

## まとめ

- ハルシネーションは、存在しないことや間違ったことを本物のように語ること。原因は、生成するときに真偽を調べていないこと（第4章）と、学習や評価が、不確かさを認めるより当てずっぽうを評価しがちなこと。「確信がない」という言葉は気にかけるべきだが、流暢さや自信は決して証拠にならない。
- 確認の四つの手順：資料を渡して作り話をしにくくする、根拠を出させる、自分で出どころを見に行く、別の独立した情報源でも確かめる。数字、日付、人名、引用、リンク、専門的な結論、最近の出来事は特に確かめる。
- 知識はパラメータに取り込まれていて資料なしでも答えられるが、カットオフがある。コンテキスト内の記憶は今回のリクエストで見える情報に限られ、チャット履歴を保存するかは製品が決める。
- モデル本体には会話をまたぐ記憶がない。プロジェクト、メモリ機能、プロジェクト説明ファイル、アカウント設定、社内ナレッジベースは、どれも製品の側が情報をコンテキストに入れ直したもの。
- つまり、AIには「真実のデータベース」も「長期記憶の倉庫」もなく、あるのはパラメータの中の知識（カットオフつき）と、今回机の上にあるコンテキストだけ。間違えるのも忘れるのも、ここから来ている。

第一部はここまでです。モデルが「何で、どう動くのか」は、だいたいつかめたと思います。次の部からは、AIをどううまく使うかに移ります。初めてのちゃんとした会話から、プロンプトで「何がほしいのか」をはっきり伝える方法までです。

   - B. 何度か聞いてみて、毎回同じ答えが返ってくれば正しいと判断する
   - C. カットオフを疑い、ネットで調べさせるか資料を渡して確認する
   - D. これだけ詳しく具体的に答えるのだから、そのまま信じてよい
   > **答えC。** 「最近起きたこと」はまさに知識のカットオフの盲点で、もっともらしくでっち上げることがあります。ネットで調べさせるか（第19章、調べた結果も再確認する）、公式資料を貼り付けて材料に基づいて答えさせ、要点は自分で確認しましょう。Aは解決にならず、温度を上げると選び方が気ままになるだけです（第8章）。Bも頼りになりません。作り話が毎回同じになることもあります。Dはまさにハルシネーションにだまされる典型で、詳しいことは本当であることを意味しません。

6. **[基礎・操作／観察]** あえて**マイナーで具体的な**事実（あるマイナーな本の出版年、ある法規の具体的な条項など）を尋ね、「出典を示して」と求めてください。次に、手元にある信頼できる資料を貼り付けて、「この資料だけに基づいて」同じ質問に答えさせ、「資料になければ、ないと言って」と伝えます。二回を比べてみましょう。 <!-- quiz: q06 revision: 2 -->
   > **観察できるはず：** 資料を与えないと、もっともらしいのに裏づけのない「出典」を作ることもあれば、正直に「不確かです」と言うこともあります。資料を与えて資料だけに基づいて答えさせると、回答はたいてい確認しやすくなり、でっち上げも減ります。これがまさにRAG（第20章）の核心となる考え方です。正しく覚えていることに賭けるより、正しい資料を目の前に置くほうがよいのです。自分の手で一度比べれば、もっともらしく語ることと根拠があることは別だと、よく分かるはずです。
