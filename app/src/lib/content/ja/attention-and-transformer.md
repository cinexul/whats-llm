第3章では、モデルが文字をトークンに切り分けて「机」の上に広げる話をしました。第4章では、一語ずつ「続きを書いて」いく話をしました。まだ解けていない疑問があります。一つの文には語がたくさん並んでいるのに、次の語を続けるとき、モデルはいったいどの語を見ているのでしょうか。

次の文を読んでみてください。

> 「太郎が本を図書館に返した。なぜならそれがもう期限切れだったからだ。」

「それ」が指すのは本で、図書館ではありません。ひと目で分かるはずです。「期限切れ」になるのは借りた本だからです。「期限切れ」まで読んだとき、私たちは無意識に前へ目を戻し、「本」と「図書館」のうち筋の通るほうを選んでいます。モデルも同じことをしなければなりません。それを支えているのが本章の主役、**注意機構**（attention）です。この章では数式は使わず、直感をつかむことを目指します。

## 一、注意：一文を読むとき、目は語のあいだを行き来する

長い文を読むとき、目は一文字ずつ均等になぞっているわけではありません。ある語を読むと、それに関係する数語を自然と多めに見て、ほかはざっと目を通すだけです。注意機構はこれの機械版です。モデルは一つひとつの位置を処理するたびに、どのトークンから、どれくらいの割合で情報を取り込むかを決めています。

ここで言うのは、すべて「前にある」トークンです。チャットに使う大規模言語モデルはトークンを一つずつ後ろへ書き足していくので（第4章）、各位置は前を振り返ることしかできません。自分とそれより前の内容は参考にできますが、まだ出てきていない後ろの語は見えません。ですから「それ」を読んだ時点では「期限切れ」はまだ出てきておらず、「それ」が何を指すかは決まりません。「期限切れ」まで来たところで、モデルは「期限切れになるのは何か」を前にさかのぼって探し、「それ」と「本」の情報を結びつけます。この先を書くときは「それ」を「あの本」として扱います。

下の図は、本章の例文と、後半だけを変えたもう一つの文で、このことを描いたものです（この二文は第五節でも取り上げます）。線が太いほど、その位置で振り返るときに多く見ていることを表します。

![二つの文の注意の模式図。一つ目の文「太郎が本を図書館に返した。なぜならそれがもう期限切れだったからだ。」では、「期限切れ」から振り返ると「本」への線がいちばん太く、「それ」への線が中くらい、「図書館」への線がいちばん細い。だからこの「それ」は本。二つ目の文「太郎が本を図書館に返した。なぜならそれがもうすぐ閉まるからだ。」では、「閉まる」から振り返ると「図書館」への線がいちばん太く、この「それ」は図書館](/figures/ja/attention.svg)

二つの文は「それ」まで一字一句同じなので、「それ」を読んだ時点でモデルが見ているものはまったく同じです。違いはその後の語にあります。「期限切れ」で振り返ると「本」への注意がいちばん大きく、「閉まる」で振り返ると、いちばん大きいのは「図書館」になります。図の線の太さは説明のためのもので、実際のモデルでは注意が多くの層や多くのヘッド（第三節）に分かれていて、こんなにきれいにはなりません。

このように前だけを振り返る注意を因果的注意（causal attention）と呼び、文章を生成するチャットモデルはこれを使っています。一方、文章を理解するだけで生成はしないモデル（検索や分類に使うエンコーダーなど）には、前後の文脈を同時に見られるものもあります。あなたが一度に送った質問や資料はすべて回答より前に並ぶので、回答を生成するときにはすべて使えます。

## 二、どこを見るかはどう決まるのか

振り返るときにどの語を多く見るかは、あらかじめ書かれた規則ではなく、そのつど計算で決まります。次のように想像してみてください。

- 各トークンは「質問」を出します。いま自分がどんな情報を必要としているか、です。たとえば「期限切れ」の位置が探しているのは、だいたい「期限切れになるのは何か」でしょう。
- 各トークンは「ラベル」も付けています。自分が何を提供できるかの目印です。さらに「中身」、つまり実際に渡す情報も持っています。
- モデルは、いまの位置の質問を、前にある各トークン（自分自身も含む）のラベルと照らし合わせます。よく合うほど、そのトークンの中身が多く渡されます。照らし合わせた結果は、合計がちょうど100%になる割合に換算され、いまの位置はその割合で各トークンの中身を混ぜ合わせ、自分の表現に加えます。

この三つは用語では、クエリ、キー、バリュー（query、key、value）と呼ばれます。質問、ラベル、中身が具体的にどんなものになるかは学習で身につくもので、人が手で書いたものではありません。

この照らし合わせだけではできないことが一つあります。順番の区別です。照らし合わせが見るのは質問とラベルが合うかどうかだけで、どれが前でどれが後ろかは分かりません。位置を別に教えなければ、「犬が人をかんだ」と「人が犬をかんだ」は同じ語の組み合わせになり、この段階ではどちらがかんだのか区別しにくくなります。そこでモデルには、各トークンの位置の情報も渡されます。最初のTransformerは「何番目か」を表す数字の組を各トークンのベクトルに直接足していました。いまの多くの大規模言語モデル（たとえばQwen3）は別の方法を使い、質問とラベルを照らし合わせるときに、二つのトークンがどれだけ離れているかも計算に入れます。

## 三、一度だけではない：複数の視点で、層を重ねて見る

モデルは一つの文を、一組の質問・ラベル・中身だけで見ているのではなく、何組も同時に使っています。その一組一組を注意ヘッド（attention head）と呼びます。たとえるなら、一本の原稿を何人かの編集者に同時に渡し、それぞれが別のところに気を配るようなものです。下の表は理解を助けるための例にすぎません。

| この「視点」が注目しうるもの | 例文では何に気づくか |
| --- | --- |
| 誰が誰を指すか | 「それ」 ↔ 「本」 |
| 誰が誰に何をしたか | 「太郎」 → 「返した」 → 「図書館」 |
| 因果・逆接の関係 | 「なぜなら」が後半と前半をつなぎ留めている |

実際のモデルでは、各ヘッドが何に注目するかは学習の中で自然に形づくられ、こんなにきれいに分担されていないことが多く、言葉で説明できるとも限りません。各ヘッドの結果はまとめられて次の層に渡され、ある層の出力が次の層の入力になります。この層が何十も重なっています。2026年10月時点で、設定が公開されているQwen3-8Bは36層で、各層に32個の注意ヘッドがあります。

## 四、Transformer：いまの主流の大規模言語モデルの「エンジン型式」

注意機構にほかの部品も組み合わせ、層を何段も積み重ねて大きくできるようにした全体の構造が**Transformer**です。2017年の論文「Attention Is All You Need」で提案されました。

いまの主流の大規模言語モデル（Claude、GPT、Geminiなど）は、基本的にTransformerか、その改良版・混合版の上に建っています。車の「エンジン型式」のようなものです。運転するのにエンジンの内部を知る必要はありませんが、「世の中の車はだいたいこの種類のエンジンを使っている」と知っておくと、各社のモデルのクセに共通点が多い理由が分かります。

「改良版・混合版」というのは、ここ一、二年、一部の標準的な注意層を、計算量の少ない線形注意や状態空間（state space）層に置き換え、標準的な注意層と混ぜて使うモデルが出てきていることを指します。たとえば2026年10月時点で、アリババのQwen3-Nextはこの混合構造を採用しています。

Transformerにはほかにも多くの部品や用語があります（「エンコーダー／デコーダー」など。付録Aの用語集にあります）が、分解するとすべて数学になり、「うまく使い、だまされない」という目的にはあまり役立ちません。覚えておくのは三つで十分です。核は注意であること、深く積み重ねて大きくできること、主流の大規模言語モデルの多くがTransformerかその変形の上に建っていること。AIを使っていて「Transformer」という言葉に出会うことはほとんどありませんが、技術ニュースや製品紹介ではよく見かけます。

## 五、いちばん考えておきたい問い：AIは「読んで理解した」のか？

注意機構が「それ」を「本」につなげるのを見ると、「AIはこの文を本当に理解した」と言いたくなります。この問いには「はい」「いいえ」で簡単には答えられないので、二つに分けて考えます。

確かに言えるのは、この例文が実は簡単ではないことです。「ウィノグラード型」（Winograd schema）と呼ばれる種類の文で、一、二語を変えるだけで代名詞の指す先が変わります。上の図の二つ目の文がそうです。文法だけでは区別できず、本には期限がある、図書館は閉まる、といった常識が必要です。モデルがこの種の文を正しく解けるのは、膨大なテキストから有用な規則性を学んでいるということで、その中には多くの常識も含まれている可能性が高いでしょう。

確かに言えないのは、正しく解けたことが、人間のような理解（現実世界での実体験があり、なぜそう判断したかを自覚していること）の証明になるかどうかです。モデルの力は学習データの中の規則性から来ています。学習であまり見なかった文型、わざと仕掛けた罠、学んでいない知識が必要な場面では、つなぎ間違えることがあり、しかも間違えても口調が変わるとは限りません。

| | 人間の読み手 | モデル |
| --- | --- | --- |
| 何に頼るか | 言葉の知識と、現実世界での実体験 | 膨大なテキストから学んだ規則性（多くの常識を含みうる） |
| 「それ＝本」と正しくつなげたら何が分かるか | 読み手は本に期限があると知っている | この種の文を解ける規則性を学んでいる。人間のように理解しているかは、これだけでは証明できない |
| どんなときに間違えやすいか | 不注意、または文そのものがあいまいなとき | 珍しい文型、わざと仕掛けた罠、学習で不足していた知識 |

本書の立場は第1・2章と同じです。AIを、有用な規則性を大量に学んでいるけれど思わぬところで間違えるシステムとして扱います。使い方に落とし込むと、大事な「何を指しているか」や事実は自分でもう一度確かめる、ということです。流暢な回答がなぜ間違うのか、どう確かめるのかは第9章で扱います。

## 六、よくある誤解、まとめて正す

| 誤解 | 実際 |
| --- | --- |
| モデルは文を最初から最後まで均等に一度なぞって読む | 注意によって軽重をつけて見ており、関係する語に多くの重みを割り当てる |
| チャットモデルは各語を処理するとき、前後の文脈をすべて見られる | 文章を生成するモデルは前を振り返ることしかできない。ただし一度に送った内容はすべて回答より前にあるので、回答の生成には使える |
| 注意は中身を照らし合わせるだけなので、語順は関係ない | モデルには位置の情報が別に渡されるので、「犬が人をかんだ」と「人が犬をかんだ」は区別される |
| 「それ＝本」を正しくつなげたのは、人間のように読んで理解した証拠だ | 有用な規則性（常識を含みうる）を学んだことは分かるが、人間のような理解の証明にはならない |
| Transformerはある具体的なAI製品だ | 土台となるアーキテクチャで、主流の大規模言語モデルの多くがTransformerかその変形の上に建っている |
| 注意が強いほど、AIは間違えなくなる | 要点を引けることは、間違えないことではない。珍しくひねくれた文型ではやはりつなぎ間違えうる |

## まとめ

- 注意機構：モデルが各位置を処理するとき、使えるトークンのうちどこから、どれくらいの割合で情報を取り込むかを決める仕組み。つまり要点に線を引けること。文章を生成するチャットモデルは前しか振り返れない。
- 割り振り方：各トークンは「質問」を出し、「ラベル」と「中身」を持つ。ラベルが質問によく合うほど、中身が多く渡される（クエリ、キー、バリュー）。位置の情報は別に渡されるので、語順も区別できる。
- モデルは多くの注意ヘッドと多くの層で、繰り返し見ている。各ヘッドが何に注目するかは学習で形づくられる。
- Transformerは、いまの主流の大規模言語モデルの土台となるアーキテクチャ（またはその改良版・混合版のもと）で、核は注意。
- 「それ」を正しくつなげられるのは、有用な規則性や常識を学んだ表れだが、人間のように理解している証明にはならない。珍しい文型や罠では、やはり間違えうる。

次の章では視点を変えます。要点に線を引き、続きを書けるこのモデルは、そもそもどうやって「教え込まれた」のか。膨大なテキストを読むところから、こちらの言うとおりに動けるようになるまでを見ていきます。

   > **答えC。** 指示関係が込み入っているほど、取り違えは起きやすくなります。当ててもらうことを期待するより、あいまいさを直接なくすほうが確実です（第11章のプロンプトの基本でもあります）。Aはそのまま送り直してもあいまいさは残り、出力にはランダム性もあるので改善するとは限りません（第8章）。Bは一度の取り違えを言語能力の問題に広げすぎで、言語を変えてもあいまいさは消えません。Dのような「おまじない」は、はっきり書くことの代わりになりません。

6. **[基礎・操作／観察]** **あいまいな代名詞**を含む一文を自分で作り、AIに「ここの『それ／彼／この』は何を指していますか、なぜですか」と尋ねてみましょう。文型をいくつか変えて試します。一、二語だけ変えた文の組（「それがもう期限切れだったからだ」と「それがもうすぐ閉まるからだ」など）も試してみてください。どんな文だと安定して答え、どんな文だとつなぎ間違えやすいでしょうか。 <!-- quiz: q06 revision: 2 -->
   > **観察のポイント：** よくある文型では、たいてい素早く安定して答えます。構造がひねくれていたり、珍しい知識が必要だったり、わざと罠を仕掛けた文では、つなぎ間違えやすくなります。文の組を使うと、決め手の語に合わせて答えを変えられるかが見えます。こうした観察は、どんな文なら頼れて、どこで自分で読み直すべきかを判断する助けになりますが、正解か不正解かだけで、人間のように理解しているかどうかは証明できません。
