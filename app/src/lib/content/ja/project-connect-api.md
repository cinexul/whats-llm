ここまで、あなたはAIを「画面を開いて、その中で自分で話す」形で使ってきました。この章では、あなた自身のプログラムにAIを使わせます。あなたのウェブサイトやアプリ、スクリプトが裏で自動的に質問をモデルに送り、答えを受け取って、自分のアプリの中で使うのです。

これは第17章の「四層の地図」の第③層、**API**（アプリケーション・プログラミング・インターフェース。プログラムが呼び出すために開かれた窓口）です。あのたとえを覚えているでしょうか。レストランは店に来たお客さんのためのもので、ほかの店がこの料理人の腕を使いたければ「注文窓口」から注文します。APIはこの窓口で、ただ注文しに来るのが人ではなくプログラムだというだけです。

この章では、まずデータの流れを説明し、それから本当に動く最小のスクリプトを示します。三十数行のJavaScriptで、一文をモデルに送って答えを表示し、鍵は環境変数から読みます。終わったときには、動くスクリプトと、鍵と費用をきちんと管理する習慣が手元に残ります。

## 一、準備

- 本当にAPIが必要なのか、会員登録で足りるのかを先に確かめる。あなた一人がときどき文章を直してもらうだけなら、出来合いのチャット製品で十分です（第17、18章）。自分のシステムから自動でAIを呼びたいとき、たとえば公式サイトのサポートに自動で返事をさせる、プログラムで大量のデータを処理する、といったときにAPIが必要になります。
- **APIキー**（API key）を一本。プラットフォームで発行してもらう文字列で、「注文しているのはあなただ」と証明するためのものです。プラットフォームはこれをもとにトークン単位で課金します（第3、38章）。漏れれば、他人があなたのアカウントで注文し、あなたの請求に付けられます。だから第二節のステップ0で、まずこれの管理を扱います。
- データの流れを考えておく。質問が出ていき、答えが戻り、それを使う。この線を頭の中ではっきり描いておけば、コードを書くのはそれを形にするだけです。
- 手を動かすときに必要なもの：Node.js（ステップ4で入れます）、プログラミングエージェント（任意。第28、29章）、新しい空のフォルダ。第26章に沿ってGitで始めます。

## 二、一歩ずつ進める

### ステップ0：まず鍵の置き場所を決める（どの機能を書くよりも前に）

| どうするか | なぜか |
| --- | --- |
| 鍵は環境変数か`.env`ファイルに置き、コードに書かない | コードに書けば、鍵はコードと一緒にあちこちへ渡り、いつ漏れてもおかしくない |
| `.env`を`.gitignore`に書き、リポジトリ（特に公開のGitHub）には決してコミットしない | 公開リポジトリの鍵は自動スキャンのプログラムにすぐ拾われる。あとで消してもGitの履歴に残る |
| 鍵は自分で設定し、どんな会話にも貼らない | プログラミングエージェントとの会話も含む。貼れば渡したのと同じ（第37章） |
| 管理画面で利用上限を設定する | 鍵が漏れたり、プログラムが無限ループで呼び続けたりしても、上限が損失を食い止める（第38章） |

いくつか言葉を説明しておきます。**環境変数**は、プログラムの外に置いておき、実行するときに読み込む設定で、鍵をコードにむき出しで書かずに済みます。`.env`はプロジェクトのフォルダに置く、こうした設定を入れておくためのテキストファイルです。`.gitignore`はGitに「これらのファイルは記録しないで」と伝える一覧で、`.env`を書いておけばコミットされません。

プログラミングエージェントは、プロジェクトのファイルを読むことがあり、`.env`も例外ではありません。だから鍵はあなたが自分で設定し、ツールが許す範囲でこのファイルを読めないようにします。2026年10月時点では、Claude Codeなら設定ファイルの`permissions.deny`に`Read(./.env)`と書けます。Codexなら`config.toml`の権限設定で`.env`を`deny`にできます（この機能はまだBetaと表示されています）。こうしたルールがあらゆる読み方を止められるとは限りません。たとえばAIが実行したスクリプトが自分でファイルを読むこともあるので、あくまで一層の上乗せです。鍵が漏れたかもしれないと思ったら、すぐ管理画面で無効にして新しい鍵に替えましょう（第40章）。

### ステップ1：プログラムに代わりに「一言聞かせる」

最小限で動かすための核心は一つだけです。あなたのプログラムが、質問を一つAPI経由でモデルに送ること。このリクエストを話し言葉で書くとこうなります。

```text
（あなたのプログラムが、裏で自動的にこれをする）
モデルに言う：「次のレビューが高評価か低評価かを判定して、
          『高評価』か『低評価』だけで答えて。レビュー：……」
```

チャット欄に打ち込むのと本質は同じで、どちらも文章をモデルに送っています。違うのは、いまはプログラムが代わりに送り、一日に一万回でも送れることです。何を送るかは、第11章と同じ心得で、要望をはっきり書き、形式を固定します。

### ステップ2：モデルの答えを受け取って戻す

モデルが処理を終えると、答えがあなたのプログラムに戻ってきます。ふつうは構造を持ったデータで、答えの文章と今回の使用量が入っています。

初心者がよく陥るのは、モデルが毎回おとなしく形式どおりに答えると思い込むことです。「高評価」か「低評価」だけで答えてと頼んでも、ときどき一文まるごと説明を返してきますし、ハルシネーションも同じように起きます（第9章）。だからプログラムは返ってきた中身を確かめ、形式に合わなければ代わりの処理に回します。

### ステップ3：答えを「使って」、自分のアプリに埋め込む

答えを受け取ったあとは、あなた自身のアプリの仕事です。「高評価/低評価」をデータベースに保存する、ページに表示する、通知メールを送る。どれもあなたのプログラムが決めます。データの流れ全体をつなぐとこうなります。

```text
 ユーザー/あなたのデータ
      │
      ▼
 自分のプログラム ──(API経由、鍵を携えて)──→ モデル
      ▲                                     │
      │                                     ▼
      └──────── モデルが答えを送り返す ────────┘
      │
      ▼
 自分のプログラムが答えを使う（保存 / 表示 / 次の処理）
```

真ん中のモデルは借りてくる能力で、あなたはトークン単位で代金を払います。

### ステップ4：最小限で動かす道筋――本当に動くスクリプト

以下の書き方は、2026年10月29日時点のAnthropic公式クイックスタート（Get started with Claude）とAPIバージョンの説明で確認しました。

ここではJavaScriptを使い、Node.js（JavaScriptをパソコン上で直接動かすプログラム）で実行します。Pythonではなくこちらを選んだのは、このスクリプトならNode.jsに追加のパッケージを何も入れずに済むからです。リクエストを送るのはNode.jsに組み込みの`fetch`、`.env`を読むのは組み込みの`--env-file`オプションです。公式クイックスタートのPython版では、まずSDK（提供元が用意するコードのライブラリ）を入れる必要があり、`.env`を読むにはふつう別のパッケージも要ります。直接リクエストを送るもう一つの利点は、ステップ1～3で説明したデータの流れ、つまりどこへ送り、何を付け、何が戻るかがコードの中に全部見えることです。

1. Node.jsを入れる：`nodejs.org`からLTS（長期サポート）と表示された版をダウンロードしてインストールします。入れたらターミナルで`node --version`と入力し、バージョン番号が出れば大丈夫です。
2. プロジェクトのフォルダ`api-hello`を作り、第26章に沿ってGitで始めます。
3. `.gitignore`を作り、`.env`と一行書きます。プログラミングエージェントに作らせてもかまいませんが、できたら自分で開いて確かめます。
4. 鍵は自分で設定する：Claude Console（`platform.claude.com`）でAPIキーを作り、第38章に沿って利用上限を設定します。テキストエディタでプロジェクトのフォルダに`.env`を新しく作り、`ANTHROPIC_API_KEY=あなたの鍵`と一行書きます。この作業は最初から最後までAIを通さず、鍵をどの会話にも貼りません。
5. 使っているプログラミングエージェントで、`.env`を読めないようにします（ステップ0参照）。
6. `hello-api.mjs`を新しく作り、中身は次のとおりにします。自分で貼り付けても、プログラミングエージェントにそのまま写させてもかまいません。そのあと自分で開いて確かめます。

```javascript
// hello-api.mjs：レビューを一件Claudeに送り、判定を表示する
const apiKey = process.env.ANTHROPIC_API_KEY;
if (!apiKey) {
  console.error("ANTHROPIC_API_KEYが見つかりません。.envファイルを確認してください");
  process.exit(1);
}

const review = "配送が早く、梱包も丁寧でした。";

const response = await fetch("https://api.anthropic.com/v1/messages", {
  method: "POST",
  headers: {
    "content-type": "application/json",
    "x-api-key": apiKey,
    "anthropic-version": "2026-10-21",
  },
  body: JSON.stringify({
    model: "claude-opus-5-5",
    max_tokens: 1000,
    messages: [
      {
        role: "user",
        content: `次のレビューが高評価か低評価かを判定し、「高評価」か「低評価」だけで答えてください。レビュー：${review}`,
      },
    ],
  }),
});

const data = await response.json();
if (!response.ok) {
  console.error("リクエスト失敗：", response.status, data.error?.message);
  process.exit(1);
}

const text = (data.content.find((block) => block.type === "text")?.text ?? "").trim().replace(/[。.]$/, "");
console.log(text === "高評価" || text === "低評価" ? text : `判定できません（モデルの答え：${text}）`);
console.log("今回の使用量（トークン）：入力", data.usage.input_tokens, "出力", data.usage.output_tokens);
```

7. ターミナルでこのフォルダに入り、次のように実行します。

```bash
node --env-file=.env hello-api.mjs
```

このコマンドは、「Node.jsで`hello-api.mjs`を実行する。その前に`.env`の行を読み込んで環境変数にしておく」という意味です。スクリプトの`process.env.ANTHROPIC_API_KEY`は、そこから鍵を受け取っています。コードの中に鍵そのものは出てきません。うまくいけば「高評価」と使用量の行が表示されます。鍵を間違えていれば`リクエスト失敗： 401 invalid x-api-key`と表示されます。

ステップ1～3と照らし合わせると、このスクリプトがしていることは次のとおりです。

- どこへ送るか：`https://api.anthropic.com/v1/messages`。AnthropicのメッセージのAPI（Messages API）です。
- 付けるリクエストヘッダーは三つ：`x-api-key`に鍵を入れます。`anthropic-version`にはAPIのバージョンの日付を書き、2026年10月時点の最新は`2026-10-21`です（公式クイックスタートの例はまだ`2023-06-01`ですが、このいちばん簡単なリクエストではどちらでも結果は同じです）。`content-type`は送る中身がJSONだと伝えます。
- 何を送るか：`model`はモデル名で、ここではクイックスタートと同じ`claude-opus-5-5`です。`max_tokens`は今回の答えで最大何トークンまで生成するか、`messages`は会話の中身です。
- 何が戻るか：JSON（波かっこや角かっこでデータを組み立てるテキスト形式）が戻ります。`content`は一覧で、種類が`text`の部分が答えの文章です。一覧にはモデルの思考の過程が残した部分など別の種類が入ることもあるので、スクリプトは種類で探しています。`stop_reason`はなぜ止まったかを示し、`end_turn`は普通に言い終えたという意味です。`usage`の`input_tokens`と`output_tokens`が、今回課金されるトークン数です。
- 代わりの処理：前後の空白と文末の句点を取り除いても答えが「高評価」でも「低評価」でもなければ、「判定できません」とモデルの答えを表示し、プログラムは落ちません。

もっと節約したければ、`model`を`claude-haiku-5-5`に替えられます。2026年10月時点で、入力の価格は100万トークンあたり0.10ドルからで、`claude-opus-5-5`は4ドルです（ほかの価格は付録E）。OpenAIのAPIも考え方は同じで、送り先、ヘッダー、項目名が違うだけなので、そちらのクイックスタートに沿って書き換えれば動きます。

### 結果を見る/最終チェックする

1. 安定して「送り出し、受け取れる」か。`review`を本物のレビュー二、三件に替えて、一件ずつ走らせます。
2. 鍵は安全か。鍵が`.env`の中だけにあり、コードに書かれず、リポジトリにコミットされず、会話にも出ておらず、管理画面で利用上限が設定されているか。これは何度でも確かめます。
3. 代わりの処理は効くか。`review`を評価と無関係な一文、たとえば「明日の会議は何時から？」に替えると、プログラムは落ちずに「判定できません」と表示するはずです。
4. いくらかかったか。スクリプトが表示したトークン数と見比べながら、管理画面で今回の使用量と費用を見て、「一回呼ぶとだいたいいくらか」の感覚をつかみます（第38章）。

### 完了の基準

次がすべてそろえば、このプロジェクトは完了です。

- `node --env-file=.env hello-api.mjs`を実行すると、「高評価」か「低評価」と使用量の行が表示される。
- コードのファイルを検索しても鍵が出てこない。`git status`に`.env`が出てこない（`.gitignore`で除外されている）。
- 鍵をどの会話にも貼っていない。ツールで`.env`の読み取りを禁止できるところは設定した。
- 管理画面で利用上限を設定し、今回のテストでいくらかかったかも見た。
- ひねった入力を与えても、プログラムは「判定できません」と表示し、落ちない。

## 三、よくあるつまずき

| つまずき | 何が起きるか / どう避けるか |
| --- | --- |
| 「APIをつなぐ = 会員登録」と思い込む | 会員登録は人が製品を使うためのもの。APIはプログラムが窓口を使うためのもので、鍵の発行とトークン単位の課金が要る（第17章） |
| 鍵をコードに書く / 公開リポジトリにコミットする | 家の鍵を玄関に貼っておくようなもの。鍵は`.env`へ、`.env`は`.gitignore`へ。最初の一行を書く前にやっておく |
| 鍵をプログラミングエージェントに貼って「設定しておいて」と頼む | 会話に貼れば渡したのと同じ。鍵は自分で設定し、「環境変数から読む」コードを書かせれば十分 |
| 利用上限を設定せず、乱用や無限ループで使い果たす | プログラムのバグ一つで、一秒に何百回も呼ぶことがある。先に上限を設定する（第38章） |
| モデルが毎回形式どおりに答えると思い込む | 間違えるし、脱線もする（第9章）。返ってきた値を確かめ、合わなければ代わりの処理に回す |
| ユーザーの個人情報をそのままAPIに送る | 送ったものは渡したのと同じ。機密情報は先に匿名化する（第37章） |
| ネットで見つけた古いコードをそのまま写す | 各社のAPIは更新され、モデル名もバージョンも変わる。公式クイックスタートのいまの書き方に従う。この章の書き方も同じ |

## 四、もう一歩進める

どの一歩でも、鍵と費用のことを忘れずに。

- プロンプトを磨く：モデルに送る文章が答えの質を直接決めます。第11、12章のテクニックを使いましょう。
- もっと整った出力を求める：決まった構造で返させれば、プログラムがそのまま使えます。AnthropicもOpenAIも「構造化出力」に対応しているので、それぞれのドキュメントの書き方に従います。
- トークンを節約する：まとめて呼び出すとき、トークンはお金そのものです。関係のない長文を毎回のリクエストに詰め込まないようにします（第38章）。
- プログラムに「自分で複数ステップ進め、ツールを呼ぶ」ようにさせる：それはもうエージェントを作っているということです（第19、34章）。第34章のブレーキの規律が必要になります。お金を使う、データを消す、外部に送るは、引き続き人の確認が要ります。
- 社内の資料や外部ツールをつなぐ：それは第22、36章のSkillsとMCPの話です。新しい情報源を一つつなぐたびに、新しいリスクの入口が一つ増えます。

## まとめ

- 「既存のプログラムにAIをつなぐ」とは、API（第17章の第③層）を使うこと。あなたのプログラムが裏で自動的に質問をモデルに送り、答えを受け取り、自分のアプリで使う。
- データの流れは一本の線：自分のプログラム →（鍵を携えて）→ モデル → 答えが戻る → プログラムが使う。最小のスクリプトは三十数行で、`https://api.anthropic.com/v1/messages`に送り、`x-api-key`、`anthropic-version`、`content-type`の三つのヘッダーを付け、戻ってきた`content`から文章を取り出す。`usage`には課金されるトークン数が入っている。
- 最大の誤解は「APIをつなぐ = 会員登録」。会員登録は人が製品を使うためのもの、APIはプログラムが窓口を使うためのもので、トークン単位で課金される。
- 鍵と費用は最初の一行から管理する。`.env`に置いて`.gitignore`に書き、コードに書かず、会話に貼らず、利用上限を設定し、プログラミングエージェントに`.env`を読ませない（第37、38、40章）。
- モデルが返す中身は間違えることも形式を外れることもある（第9章）ので、プログラムで確かめて代わりの処理を用意する。送ったデータは渡したのと同じなので、機密情報は先に匿名化する（第37章）。

次章では、第22章の二つの概念、SkillsとMCPを本当に形にして、AIにデータを読み、ツールを使う新しい能力を持たせます。

1. **[基礎・概念問題]** 「既存のプログラムにAIをつなぐ」とは、本質的に四層の地図（第17章）のどの層を使っているのか？ <!-- quiz: q01 revision: 2 -->
   - A. 製品層：人が開いてすぐ使えるチャット画面
   - B. Agent層：自分で何ステップも動くエージェント
   - C. API層：プログラムが呼び出すための窓口
   - D. モデル層：学習によってできたモデルそのもの
   > **答えC。** **プログラム**に裏側で自動的にモデルを呼び出させるなら、通るのはAPIです（第17章第③層のあの「注文受付の窓口」）。Aは**人**が開いて話すためのものです。Dのモデルそのものには、あなたのプログラムは直接触れられず、窓口を通して使います。Bは別の話で、プログラムがAPIを呼んでAgentを組むことはできますが、「APIを一回呼んで答えをもらう」こと自体はAgentではありません。

2. **[基礎・誤解問題]** 「自分たちのシステムにAIを組み込みたいから、ChatGPTの会員になろう」――どこが間違いか？ <!-- quiz: q02 revision: 2 -->
   - A. APIを使うべきで、鍵を申請し、使用量で課金される
   - B. 会員のプランが足りず、チーム版でないと組み込めない
   - C. 間違っていない。会員になればシステムから直接呼べる
   - D. まず自分専用のモデルを一から学習させるべきだった
   > **答えA。** これがこの章の最大の誤解です。「人が画面の中で使う」ことと「プログラムが裏側で自動的に呼び出す」ことは、別の二つの道です。前者は製品を使い（会員になる）、後者はAPIを使います（第17章）。BとCは会員を組み込みの手段だと思っていますが、どんなに上のプランでも人が使うためのものです。Dは的外れで、APIで使うのは各社の出来合いのモデルなので、自分で学習させる必要はありません。

3. **[基礎・概念問題]** APIを使うときのあの「鍵（API key）」は何のためのものか？ <!-- quiz: q03 revision: 2 -->
   - A. 会員証の一種で、チャット製品が回数無制限になる
   - B. モデルの計算を速くする通行証で、高いほど速い
   - C. 自分のアカウントに関する質問だけに答えさせるスイッチ
   - D. 呼び出しているのが自分だと証明し、使用量で課金する
   > **答えD。** 鍵は、あなたの「注文の証明 + 請求の根拠」に当たります。一方の端があなたの請求につながっているからこそ、**漏れたら他人があなたのアカウントで使い放題にできる**のです。だから環境変数か`.env`に入れ、コミットせず、会話に貼らず、利用上限を設けます（第37・38章）。Aは会員と混同しています。BとCの速度や答える範囲は、鍵とは関係ありません。

4. **[応用・誤解問題]** 手間を省こうとして、鍵をコードのファイルに直接書き、しかも公開のGitHubリポジトリにプッシュしてしまった。最も起こりうることは？ <!-- quiz: q04 revision: 2 -->
   - A. 大丈夫。公開リポジトリはコードが多すぎて誰も気づかない
   - B. スキャンのプログラムにすぐ拾われて盗用され、請求が来る
   - C. GitHubが鍵を自動で暗号化するので、他人には見えない
   - D. あとでその一行を消せば、漏れたことは取り消せる
   > **答えB。** 公開リポジトリは専用のスキャンプログラムに見張られていて、平文の鍵はたいていすぐに拾われてしまいます。正しいやり方は、**鍵を環境変数か`.env`に入れ、`.env`を`.gitignore`に書き、決してコミットせず、利用上限で歯止めをかける**ことです（第37・38章）。Aは自動スキャンを甘く見ています。Cは成り立たず、書いた鍵は平文のままです。Dもだめで、一行を消してもそのコミットはGitの履歴に残ります。漏れた鍵は管理画面で無効にし、新しいものに替える必要があります。

5. **[基礎・場面問題]** あなたのプログラムがAPIでモデルに「『高評価』か『低評価』だけで答えて」と頼んだのに、たまに一文の説明を返してくる。どうするのが最もよいか？ <!-- quiz: q05 revision: 2 -->
   - A. 鍵を新しくする。古い鍵に問題があるかもしれない
   - B. APIが壊れたと判断し、チャット画面で手作業に戻す
   - C. 返り値を検査し、形式外ならフォールバックする
   - D. 形式どおりに答えるまで、自動で再試行を続けさせる
   > **答えC。** モデルが返す内容は依然として間違ったり、形式に従わなかったりします（ハルシネーションは相変わらず起きます、第9章）。堅牢なプログラムは「言うことを聞かないかもしれない」と前提し、返り値を検査してフォールバックを用意します。AとBは普通に起きることを故障と取り違えています。Dは上限なしに再試行するので、いつまでも成功しないかもしれず、お金も無駄に消えていきます（第38章）。

6. **[基礎・操作/観察問題]** まず紙の上に「APIをつなぐ」データの流れを描いてみましょう。「自分のプログラムが質問を送り出す（鍵を携えて）」から、「モデルが答えを送り返す」、そして「自分のプログラムが答えを使う」まで。図の上に、お金と安全に関わる三か所――鍵をどこに置くか、どこで課金されるか、どこで上限を設けるか――を書き込みます。できれば、ステップ4のスクリプトで実際に一度動かし、「完了の基準」と照らし合わせてください。 <!-- quiz: q06 revision: 3 -->
   > **観察できるはず：** この線は実はとても短い――送り出す、受け取る、使う、の三ステップだけで、これが「AIをつなぐ」ことの考え方のすべてです。けれど書き込んだ三か所（鍵は環境変数か`.env`、トークン単位で課金、管理画面で利用上限）こそが本当に事故が起きやすく、初日から管理しなければならないところです（第37・38章）。実際に動かしてみると、鍵が最初から最後までAIを通らなくても、コードはちゃんと動くことも分かるはずです。
