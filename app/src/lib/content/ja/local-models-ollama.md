モデルはサービス提供者のサーバーでも、自分のパソコンでも動かせます。ローカル処理は、オフライン作業、データの流れの管理、ローカル推論ごとのクラウド料金を避ける用途に役立ちます。その一方で、ハードウェアを管理し、作業全体のどこまでが本当にローカルかを確かめる必要があります。

## 一、なぜ自分のパソコンでモデルを動かしたい人がいるのか

ダウンロード済みのモデルが、保存済み文書をパソコン内だけで処理するなら、その文書をモデル提供者に送る必要はありません。必要なソフトウェアとモデルファイルがそろえば、そのタスクはインターネットなしでも動きます。

ただし、この利点は**経路全体**に依存します。ローカルのチャット画面が、クラウドモデルを使い、ウェブ検索語を送り、遠隔の文書解析を呼び、会話履歴を同期する場合もあります。「ここにインストールした」と「ここで処理する」は別のことです。

## 二、ローカル vs クラウド：一つの表で取捨選択を整理する

| 問い | クラウドでの推論 | 完全にローカルの推論 |
| --- | --- | --- |
| モデルはどこで処理する？ | サービスのサーバー | 自分のマシン |
| 入力は外へ出る？ | サービスに送る入力は外へ出る | 周囲の処理もローカルなら、外へ出す必要はない |
| オフラインで動く？ | 遠隔推論には接続が必要 | 必要なダウンロード後、遠隔依存のない操作なら動く |
| 費用は？ | 無料枠、定額、従量課金など | ハードウェア、電力、保存容量、保守。ローカル計算自体のクラウド推論料金はない |
| 品質を決めるものは？ | 具体的なモデル、ツール、設定 | ハードウェア制約内の具体的なモデル、ツール、設定 |
| 設定や更新は誰が扱う？ | 主に提供者 | 主に利用者や使用ツール |

小さなローカルモデルが限定的な仕事をうまくこなす場合もあります。クラウドでは大型モデルや管理されたツールを利用できます。「ローカル」だけで、賢い、弱い、速い、総費用がゼロとは言えません。実際に使える候補で、同じ代表的なタスクを試します。

## 三、ダウンロード前に確認：パソコンは対応できるか

**ダウンロード容量は、実行時に必要な総メモリ量ではありません。** モデルの重み、作業用メモリ、文脈のキャッシュ、OS、ほかのアプリの分も必要です。長い文脈や同時処理は、メモリをさらに使う場合があります。

- **RAM** はシステムのメモリです。CPU と RAM で動くモデルもありますが、遅くなる場合があります。
- **VRAM** は独立した GPU のメモリです。実行ソフトウェアと機器によって、GPU だけで動かす場合も、CPU と GPU に分担する場合もあります。
- **ユニファイドメモリ**は、一部のコンピューターで CPU と GPU が共有するメモリです。同じ物理メモリを、別々の RAM と VRAM として二重に数えないようにします。

概算の例として、80億個のパラメータを各4ビットで保存すると、その重みだけで約**40億バイト**です。80億 × 4 ÷ 8 で計算できます。実際の形式には追加情報があり、実行時にはさらに容量が必要です。これは算数の例であり、「8B・4ビット」のモデルが4 GBのマシンに収まり快適に動くという保証ではありません。

モデル形式、実行ソフトウェアとの互換性、対応ハードウェア、空きメモリを確認します。まず控えめなモデルと短い文脈で始め、自分の作業を測りましょう。メモリに収まることは、速度が十分であることを保証しません。

## 四、量子化：大きなモデルを少し「軽く」して載せやすくする

量子化は、モデル内の一部の数値を少ないビット数で表す方法です。保存容量やメモリを減らせますが、品質と性能の変化は方法、モデル、タスクによります。ビット数を減らしても、精度の損失が必ず一定で小さいとは限りません。

**パラメータ数**と**量子化**は区別します。8B と14Bはパラメータ数の違いです。同じ8Bモデルの異なる量子化版は、数値の表現方法が違います。別の派生版では、学習、対応文脈長、機能が変わることもあります。小さいダウンロードがすべて同じモデルの圧縮版だと思わず、説明を読みましょう。

## 五、Ollama と LM Studio：モデルを動かすための道具

Ollama と LM Studio は対応モデルを使うアプリや実行ソフトウェアであり、モデル群の名前ではありません。対応形式やハードウェアも異なります。ダウンロード可能な**オープンウェイトモデル**によりローカル利用ができますが、ライセンス、商用利用、再配布の条件はモデルごとに違います。重みの公開は、学習過程や学習データまで全部公開されているという意味ではありません。

Ollama の公式文書は、**ローカルモデルとクラウドモデルの両方**を説明しています。また、クラウドモデルやウェブ検索などのクラウド機能を無効にするローカル専用設定もあります。したがって、Ollama をインストールしただけでは、すべての要求がローカルに留まる証拠にはなりません。選択中のモデルと実行経路を確認し、ローカル運用が目的なら現在の設定手順を参照します。

LM Studio のオフライン文書は、モデルのダウンロード後に、ローカルでのチャット、文書処理、ローカルサーバーがネット接続なしで動くと説明しています。モデルを探したりダウンロードしたりする際は接続が必要です。追加の連携については、別途データ経路を確認します。

初回は、パソコンにある機密性のない文書で試しましょう。対応するローカルモデルをダウンロードし、ローカルモードを確認して、ネット接続を切って文書を要約します。この試験は、その操作がオフラインで動くことを確かめます。接続機能すべてや、今後の全セッションがローカルに留まる証明ではありません。検索、プラグイン、同期、遠隔サービスの設定は別々に確認します。

## 六、よくある誤解、まとめて訂正

| 誤解 | 訂正 |
| --- | --- |
| Ollama は必ずオフラインだ | ローカルとクラウドの実行に対応する。選択した経路を見る |
| 5 GBのダウンロードならメモリも5 GBで足りる | 実行時と文脈用のメモリも必要 |
| RAM が足りれば速い | CPU、GPU、メモリ帯域、設定も影響する |
| 小さな派生版は圧縮率だけが違う | パラメータ数、学習、機能も違う場合がある |
| ローカルなら正答が保証される | ローカルモデルもハルシネーションを起こす |

## まとめ

自分のタスクと制約に合うときにローカル処理を選びましょう。実際のデータ経路を追い、メモリに余裕を持たせ、品質と速度を試し、モデルのライセンスを読みます。「ローカル」「クラウド」を品質の順位とみなすより有用な確認です。
