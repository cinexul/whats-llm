第4章では、モデルが「次の語を当てる」ことで言葉をつないでいく様子を見ました。でも、コンピューターは数字しか扱えず、「猫」「犬」「うれしい」といった文字をそもそも知りません。では、どうやって「猫」と「犬」は意味が近く、「猫」と「鉄筋」はまるで縁遠いと分かるのでしょうか？

やり方は、一つひとつの語や文に「座標」を割り当てることです。よく学習された埋め込みモデルでは、意味の関連する文章ほど座標も近くなりやすいのです。この章では、この座標（ベクトル）と、文章を座標に変える方法（埋め込み）を扱います。この先の「言い換えると結果が変わる」（第11章）や、RAGが意味で資料を探す仕組み（第20章）も、この章の話が土台になります。

## 一、核心の発想：「意味」を「座標」に変える

まず地図を思い浮かべてください。都市は経度と緯度の二つの数字で位置を特定できます。

- 北京はおよそ`(116, 40)`、天津は`(117, 39)`。二組の数字がとても近いのは、二つの都市が近いからです。
- 上海は`(121, 31)`で、北京の数字とは少し離れています。

コンピューターは都市を「知っている」必要はなく、二組の数字の距離を計算するだけで、どこがどこに近いか分かります。embeddingは同じやり方を語の意味に持ち込みます。座標が表すのは地理的な位置ではなく、意味です。

```text
地図:    (経度, 緯度) で「地理的位置」を表す  →  距離を計算 = 地理的にどれだけ近いか
意味の図: (長い数字の連なり) で「意味」を表す   →  距離を計算 = 意味的にどれだけ近いか
```

- **ベクトル**（vector）は、この長い数字の連なりのことで、ある語や文の「座標」にあたります。
- **埋め込み**（embedding）は、文章をこの種の座標に変換する作業、またはその結果を指します。文章を座標の空間に「埋め込み」、それぞれに落ち着き場所を与える、という意味の名前です。

下の図は、この発想を平面の地図にしたものです。動物、果物、感情がそれぞれ一つの塊になり、同じ塊の語は近く、違う塊の語は遠くにあります。

![模式図：平面上に三つの語の塊がある。猫・犬・ウサギ、リンゴ・バナナ・ブドウ、うれしい・悲しい・怒りがそれぞれまとまっている。猫と犬を結ぶ短い点線は距離が近く意味も近いこと、犬とリンゴを結ぶ長い点線は距離が遠く意味も離れていることを表す](/figures/ja/embedding-map.svg)

この図は押しつぶした模式図です。実際のembeddingは数百〜数千次元、つまり数百〜数千個の数字でできています。2026年10月時点で、OpenAIのtext-embedding-3-smallは標準で1536個、text-embedding-3-largeは3072個の数字を出力します。大規模言語モデルが内部で各トークンに使うベクトルも同じくらいの規模で、たとえばQwen3-8Bでは4096個です。意味は地理的な位置よりはるかに複雑で、二つ三つの数字では区別しきれません。また、それぞれの数字に「動物の軸」「果物の軸」のような決まった意味があるわけではなく、全体としての近さで比べます。

もう一つ知っておきたいのは、embeddingはデータから学んだ近似であり、意味の完全な地図ではないことです。近さはどの埋め込みモデルを使い、どう比べるかで変わります。関連する文章が遠くに置かれたり、無関係な文章が近く見えたりすることもあります。

## 二、なぜわざわざこうするのか：コンピューターは計算しかできないから

前の章で見た「次の語を当てる」機械は、土台がすべて数値の計算です（第1章・第2章）。「猫」という字に足し算や掛け算はできませんが、「猫」を数字の連なりに変えれば、いろいろなことが計算できるようになります。

- 二つの語の意味が近いか？ 二つの座標の距離を計算し、近ければ意味も近い。
- たくさんの資料を関連度で並べるには？ すべて座標に変え、質問からの近さ順に並べる。
- モデルが次にどの語を続けるか判断するときも、こうした数字の上で計算しています。

これは文章どうしの関係を計算できるようにする方法の一つですが、唯一の方法ではありません。資料探しに限っても、キーワード検索や同義語の辞書も役に立ちます。

## 三、いちばん有名な直感：意味を座標の上で「足し引き」できる

embeddingの説明でいちばんよく持ち出されるのが、次の例です。

```text
   "国王" の座標  −  "男性" の座標  +  "女性" の座標  ≈  "女王" の座標
```

「国王」から「男性」の分を引き、「女性」を足すと、行き着く先が「女王」の近くになる、という意味です。

学習に使う膨大なテキストの中では、「国王」と「女王」の違いが、「男性」と「女性」の違いと同じ種類の違いになっています。そのため「性別を入れ替える」という関係が、座標の中でおおむね決まった一つの方向になり、その方向に進むとだいたい性別が入れ替わるのです。似た例はほかにもあり、どれもおおよそ成り立つ程度です。

| 座標上の足し算引き算 | 結果がだいたい落ちる先 | 捉えている関係 |
| --- | --- | --- |
| パリ − フランス + 日本 | ≈ 東京 | ある国の首都 |
| 歩く → 歩いた、走る → 走った | 同じ一つの「方向」 | 過去形になる |
| 大きい → もっと大きい、小さい → もっと小さい | 同じ一つの「方向」 | 程度が強まる |

言いたいことはとても素朴です。語と語の関係（性別、首都、時制など）が、座標の中ではおおまかな方向と距離として表れることがある。ここの「≈」は「近くに落ちる」という意味で、等号ではありません。

この例には出どころと限界もあります。もとは2013年ごろの静的な単語ベクトルの研究です（静的とは、各語が文脈に関係なく一つの固定した座標を持つこと。word2vecもこの時期に広まりました）。当時でさえ、この足し引きが成り立つのは一部の例だけでした。この例を最初に報告した論文でも、文法的な類推問題の正答率は4割弱で、語の組み合わせを変えるとうまくいかないこともよくあります。今の大規模言語モデルでは、同じ語でも文脈によって表現が変わるので、なおさら単純な足し算は期待できません。「関係も方向として表せる」という直感として受け取り、法則だとは考えないでください。

## 四、ベクトルは原文でも暗号でもない

embeddingは文章どうしを比べるための数字の並びで、原文に「解凍」して戻す決まった手順はありません。だから検索の仕組みでは、ふつう原文を別に取っておき、引用するときはそちらを使います。

ただし、「直接読めない」からといって「元に戻せない」わけではありません。ベクトルから原文を逆算する研究（embeddingの反転と呼ばれます）では、条件がそろえば文の大部分を、ときには一字一句そのまま取り戻せています。どこまで戻せるかは、モデルや文章、相手がどれだけ情報を持っているかしだいです。つまりembeddingは暗号化ではなく、匿名化したことにもなりません。

```text
原文:              "今日、私は公園を散歩して、とても良い気分だった。"
embedding に変換:  [0.12, -0.83, 0.05, 0.41, ……]  ← 千個以上の数字
原文を直接読める?  直接は読めない。ただし反転攻撃で条件次第では復元されうる
何ができる?        他の文と「意味的にどれだけ近いか」を計算できる
```

実際には、原文と出典を別に保存し、ベクトルは資料を見つける役割にとどめます。機密資料の原文にもベクトルにもアクセス制限をかけましょう。ベクトルに変えたからといって公開してよくなるわけではありません。そもそもAIツールに渡すべきでない資料については第37章を参照してください。

## 五、embeddingは何の役に立つのか：意味検索とRAG

埋め込みの代表的な用途は**意味検索**です。言葉が違っていても、意味の関連する資料を探せます。

たとえば「パソコンを速く動かすには」と検索したとき、《コンピューターの性能を上げる方法》という記事には「速く動かす」という語が一度も出てきません。文字どおりのキーワード検索では見逃すかもしれませんが、同義語の辞書を持つキーワード検索なら見つけられることもあります。意味で検索する流れはおおよそ次のとおりです。

```text
① 事前に:資料を一段ずつすべて embedding に変える(それぞれに「意味の座標」をつける)
② あなたが質問:「パソコンを速く動かすには」 → これも embedding に変える
③ 座標空間の中で、質問の座標に最も近い数段を見つける
④ 言葉が違う段落でも、意味が近ければ上位に来ることがある
```

上位に来たのはベクトルが近かったというだけで、記事が本当に関連しているか、内容が正しいかの保証にはならないので、自分で中身を確かめます。製品が「意図を理解して検索できる」「アップロードした数百ページの文書から関連する段落を見つけられる」とうたっていたら、裏側ではたいていこの仕組みが働いています。

RAG（検索拡張生成、第20章）は、まず資料を検索し、それをコンテキストに入れてモデルに答えさせる仕組みです。検索には埋め込み、キーワード、または両者の組み合わせを使えて、embeddingは必須ではありません。検索を挟むと根拠のない回答は減りますが、大事な資料を見落としたり、紛らわしい資料を拾ってきたりもするので、答えはやはり確かめる必要があります（方法は第9章）。

## 六、ある古い問いに立ち返る：なぜ「言い換えると、結果が変わる」のか

同じ意味でも、いくつか語を換えてAIに尋ねると、回答がはっきり変わることがあります。理由は一つではなく、言い回しが変わると、トークンへの分け方、モデル内部の表現、指示の受け取り方が変わる場合があります。一字も変えなくても、サンプリングによって答えが変わることもあります（第4章）。

モデルが内部で各トークンに使うベクトルと、検索に使う文のembeddingは、関係はあっても別物で、どちらも単独では回答全体を説明できません。なので、答えが違ったからといって、二つの文のembeddingが離れているとは言えません。指示をはっきり書くのは効果がありますが、これなら必ず正解するという言い方はありません。何回か試して、自分の求める条件にいちばん合う出力を選ぶのが現実的です（第11章）。

## 七、よくある誤解、まとめて訂正

| 誤解 | 実際 |
| --- | --- |
| embeddingは原文を完全に復元できるアーカイブだ | 学習された表現で、一般的な可逆の復元方法はない。ただし反転攻撃で文章の一部が復元されることはある |
| ベクトルは原文を安全に隠す | embeddingは暗号化でも匿名化の保証でもない。機密ベクトルも原文も保護が必要 |
| 「国王−男性+女性≈女王」は、語義を算数のように正確に足し引きできる証拠だ | 2013年ごろの静的な単語ベクトルの例で、おおよそ成り立つのは一部の語だけ。現代の大規模言語モデルではなおさら単純に足し引きできない |
| 意味検索には同じ語が必要 | 埋め込みは言い回しの違う関連文章も見つけられる。キーワード検索やハイブリッド検索も有用で、どの結果も確認が要る |

## まとめ

- ベクトルは「意味の座標」を表す数字の連なりで、embeddingは文章をその座標に変える作業と結果。座標があれば、コンピューターは意味の近さを距離として見積もれる。ただしあくまで近似。
- 実際の座標は数百〜数千次元で、二次元の地図は模式図にすぎない。
- 「国王 − 男性 + 女性 ≈ 女王」は、語と語の関係の一部が座標上の方向として表れることを示す。ただし2013年ごろの静的な単語ベクトルの例で、一部の例でしか成り立たない。
- embeddingは原文アーカイブでも暗号化でもない。原文は別に保存し、機密ベクトルも保護する。
- 意味検索とRAG（第20章）ではembeddingがよく使われるが、キーワード検索やハイブリッド検索も有用。取得した資料は自分で確認する。
- 言い換えると結果が変わる理由は一つではなく、回答の違いでembeddingの距離は測れない（第11章）。

これで、第一部で扱うモデル内部の土台がそろいました。トークンとコンテキスト（第3章）、次の語の当て方（第4章）、座標による意味の表し方（第5章）です。第6章では、もう一つの重要な仕組みである注意（アテンション）とTransformerを見ます。モデルが文を読むとき、どこに目を向けるかを決める仕組みです。

   - C. 意味の類似度で並べると、言葉が違っても関連する記事が上位に来ることがある
   - D. 一番上に来たのだから最も関連が深い。中身を読まずにそのまま使ってよい
   > **答えC。** 埋め込み検索はベクトルの類似度で段落を並べるので、キーワードが違っても意味の近い記事が上位に来ることがあります。妥当な説明ですが、ツールの内部が必ずそうなっている証明にはなりません。同義語に対応したキーワード検索やハイブリッド検索でも見つけられます。Aは「意味で検索」を文字どおりの一致しかできないものと誤解しています。Bには根拠がありません。Dは逆に信じすぎで、類似度が高いのは一つの手がかりにすぎず、本当に関連があるか、内容が正しいかは自分で確かめる必要があります。

6. **[基礎・操作/観察問題]** 同じモデルで、同じ公開文章を「読みやすくして」「推敲して」「不自然な文を直して」という三つの指示で編集してください。目的に合う修正を記録しましょう。この比較から分かることと、embeddingについて証明できないことは何でしょうか。 <!-- quiz: q06 revision: 2 -->
   > **観察のポイント：** 言い回しは変わるかもしれませんが、この実験だけではembeddingの距離や変化の原因を特定できません。サンプリング、指示、モデル全体の処理も影響します。どのプロンプトが課題を明確に伝えるか比較しましょう。意味の類似度を直接調べるには、同じembeddingモデルですべての例文を処理し、類似度スコアを比較します。異なるモデルのベクトルを混ぜて比較しないでください。
