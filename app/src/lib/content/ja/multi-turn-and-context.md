こんな体験をしたことがあるはずです。ある件で話していて、最初の数ターンは速く正確なのに、進むほどモデルが「頑固」になっていく。早くに決めた要件を忘れ、前後で言うことが食い違い、回答はくどくなり、しまいには堂々巡りを始める。「話すほど鈍くなる」とぼやいて、疲れたのかと思う人も多いでしょう。

モデルは疲れません。長い対話がなぜ要点を見失いやすいのかは第3章で見ました。この章では実践だけを扱います。対話をどう分けるか、**いつ思い切って新しい対話を開くべきか**、そして製品の機能を使って**長期的な好み**をどう「覚えさせる」か。どれも地味な習慣ですが、AIをうまく使ううえで最も値打ちのある基本技の一つです。

## 一、なぜ「話すほど鈍くなる」のか：簡単なおさらい

原因は第3章で「机」のたとえと表を使って説明したので、ここでは結論だけにします。各ターンでモデルが目にするのは、そのリクエストのために製品が用意したコンテキストです。履歴の全文のこともあれば、選別・省略・要約された版のこともあります。対話が長くなるほど、机の上には**いまの用件と無関係な内容、却下した古い案、要約されて細部が抜けたメモ**が混ざりやすくなります。

机がいっぱいなこと自体が悪いとは限らず、役に立つ内容はむしろ回答を正確にします。困るのは、無関係な内容や食い違う内容がモデルの気を散らし、最初に決めた要件まで埋もれてしまうことです。だから対処法は単純です。散らかった机の上で探し続けるより、きれいな机に取り替える。次の二つの習慣がそのためのものです。

## 二、コア習慣その一：一つの話題に、一つの対話

最も手間のかからない決まり：**一つのまともな用件に、専用の対話を一つ。用件が済んだら、あるいは話題が変わったら、別に新しく開く。**

多くの人は**同じ対話の中で**朝から晩まで話す習慣があります。まずレシピを聞き、次に履歴書の修正に移り、それから概念の説明をさせ、また戻って履歴書を直す。これは、まったく無関係な資料を全部一つの机に積み上げるようなものです。

```text
❌ 一つの対話で何でも話す：
   [レシピ] → [履歴書修正] → [相対論の説明] → [また履歴書修正に戻る] → [航空券の助言] ……
   机がどんどん雑然 → 無関係な内容に気を散らされ、履歴書の要件はとっくに一番下に

✅ 一つの話題に一つの対話：
   対話A：履歴書の修正に集中
   対話B：レシピを聞く
   対話C：相対論の説明
   どの机もきれい、モデルは毎回「集中」できる
```

> **実際によくある場面：** 話題が雑多になると、前後の話が混ざりやすくなります。履歴書を「もっとかしこまった文体に」直させた直後に別の話をして戻ると、「かしこまった文体で」という指定を忘れていたり、なぜか先ほどの雑談の口調を帯びていたりします。無関係な用件を別々の対話に分け、どの机にも一件分の資料だけを置けば、モデルの振る舞いはずっと安定します。対話が短いほうがたいてい速く、使用量も抑えられますが、実際の費用は製品のキャッシュや料金プランのルール次第です（第3章、第38章）。

## 三、コア習慣その二：この信号を見たら、新しい対話を開く

では、同じ用件で話していて、**いつ思い切ってこの対話を捨て、開き直すべきか？** 次の信号のどれか一つでも見えたら、粘らないことです。

| 信号 | 具体的な現れ | 机の上で起きていそうなこと |
| --- | --- | --- |
| **自己矛盾し始める** | このターンの発言が前のターンと合わない、前後で食い違う | 矛盾する古い内容が机に積もり、引っ張り回している |
| **要件を繰り返し忘れる** | こちらが決めた取り決め（口調・長さ・形式）を何度も無視し、注意しても効かない | 重要な要件が新しい内容に埋もれている |
| **どんどんくどい/堂々巡り** | 回答がどんどん長く、同じ話を繰り返し、却下済みの案を蒸し返す | 長い試行錯誤のノイズが信号を覆っている |
| **明らかな「物忘れ」** | 早くに伝えた具体的な情報を混同したり落としたりする | 古い内容が切り詰められたか、要約されたか、埋もれた |

これらを見たら、**元の対話の中で粘らない**こと。注意し直したり直し直したりするのは、たいてい満杯の机にさらに紙を足すだけです。正しい動作は、新しい対話を開いて、まだ必要な情報をきれいに伝え直すことです。

```text
机を取り替えどきの定石：
  1) 新しい対話を開く(= きれいな机)
  2) 一言二言で明確に伝える：背景 + いま何をさせたいか + 重要な要件
     (これがまさに第11章の「明確に言う」技術)
  3) 必要なら、前のターンの「役に立つ中間成果」を貼って持ってくる。廃案は持ち込まない
```

> **ポイント：** 初心者がいちばんやりがちなのは、散らかった同じ対話の中で必死に直し続けて、かえってこじらせることです。ルールは単純です。**まず新しい対話で試す。** きれいな新しい対話で問題が消えたなら、原因はたいてい長い対話です。新しい対話でも同じ問題が再現するなら、そこで初めて設定（カスタム指示や、記憶に残った古い好みなど）を確認するか、製品にバグとして報告します。開き直すかどうかの目安も簡単で、説明し直す手間が開き直す手間を上回ったと感じたら、開き直しましょう。

## 四、長期的な好みをどう「覚えさせる」か

毎回きれいな机からやり直すなら、**毎回伝えなければならない長期的な好み**（「日本語で答えて」「口調は専門的に」「私は教育関係の仕事をしている」）はどうすればいいのでしょう？ 新しい対話のたびに言い直すしかないのでしょうか。

まず本書全体のルールを確認しておきます。モデル本体には会話をまたいだ記憶がありません。新しい対話でモデルが知りうるのは、今回コンテキストに入ったものだけ、つまりあなたが言ったことと、製品が代わりに持ち込んだ情報です（第3章）。

製品が情報を持ち込むのは、モデルの外側にある製品レイヤーの機能によるものです。2026年10月時点で、Claude、ChatGPTなどの製品はおおむね次のような機能を提供しています。

| 機能の種類 | おおまかな働き | 向いている内容 |
| --- | --- | --- |
| **カスタム指示 / 個人設定** | あらかじめ書いておいた説明を、製品が対話に自動で添える | 言語、口調、立場といった長期的な好み |
| **プロジェクト** | 資料と指示をひとまとめにし、その中の対話で共通して使う | 続いている一つの用件。別の用件は別のプロジェクトに |
| **記憶（メモリ）** | 話した要点を製品が保存し、後の対話で入れ直す | 製品によっては**会話から自動で抜き出し**、しかも初期設定でオンのことがある |

呼び名、範囲、初期設定は製品ごとに違うので、詳細は公式ドキュメントを確認してください。使うときは次の点に気をつけましょう。

- 長く効かせたい好みは、カスタム指示やプロジェクトの説明に書いておくほうが、「自然に覚えてくれる」のを期待するより確実です。
- 覚えられたくない内容は、一時チャット（製品によってはシークレットチャット）を使うか、記憶をオフにしてから話します。
- ときどき設定画面で保存された記憶を確認し、古いものや間違ったものは削除します。製品によっては、会話を削除しても、そこから抜き出された記憶は消えないので、別に削除が必要です。
- パスワードや身分証番号、社外秘の情報などを好みとして保存しないこと（第37章）。

> **ポイント：** モデルが「覚えている」のは、製品が今回コンテキストに入れ直した部分だけです。設定した好みがたまに効かないときも、第三節のルールどおり、まず新しい対話で試します。新しい対話でも効かなければ、設定を確認するか製品に報告しましょう。

## 五、一通りつないだ実践の流れ

この章と前の二章をつなげると、日常で使いやすい一連の流れになります。

```text
1) まともな用件一つ → 専用の対話を一つ開く(習慣その一)
2) 最初の一文で要件を明確に伝える(第11章：背景―タスク―制約―形式)
3) 長い資料？ 分割して与え、材料だけに基づいて答えさせる(第12章)
4) 行ったり来たり磨く。自己矛盾/要件を繰り返し忘れる/くどくなる → 新しい対話でやり直す(習慣その二)
5) 毎回必要な長期的な好み → 製品のカスタム指示、プロジェクト、記憶に任せる(第四節)
```

> **実際によくある場面：** たとえば一本の原稿をやり取りしながら磨いていくと、そのうち新しい要件を無視したり、却下した書き方を蒸し返したりし始めます。そうなったら元の対話で粘らず、新しい対話を開いて「いちばん満足している版」を貼り、「この版をもとに、XXだけ直して」と一言添えましょう。良い中間成果はきれいな机に持っていき、廃案は古い対話に置いていく。この一手は何度も使うことになります。

## 六、よくある誤解、まとめて訂正

| 誤解 | 実際 |
| --- | --- |
| 「話すほど鈍くなる」のは疲れたか壊れたからだ | たいていは長い対話の中の無関係・矛盾した内容に気を散らされている（第3章）。まず新しい対話で試し、そこでも問題が出るなら設定を確認するか報告する |
| ずれたら、元の対話で何度も注意すれば直る | 満杯の机に紙を足すとかえってこじれやすい。**新しい対話を開き**、きれいにやり直す |
| 何でも一つの対話で話すのがいちばん楽 | 話題が雑多になると話が混ざる。**一つの話題に一つの対話**、どの机にも一件だけ |
| 「記憶/好み」を設定したら、モデル本体が覚えたということだ | 製品レイヤーが保存した情報をコンテキストに入れ直しているのであって、モデル本体が覚えているのではない |
| 記憶機能は、自分が覚えてと頼んだものしか保存しない | 会話から自動で記憶を抜き出す製品もあり、初期設定でオンのこともある。覚えられたくないものは一時チャットで扱い、定期的に確認・削除する |
| 長期的な好みは毎回手で言い直すしかない | カスタム指示、プロジェクト、記憶に書いておけば、製品が対話に添えてくれる（公式ドキュメントを確認） |

## まとめ

- 「話すほど鈍くなる」のは、たいてい長い対話の中の無関係・矛盾した内容が気を散らし、早くに決めた要件まで埋もれてしまうから（第3章）。モデルは疲れない。
- 習慣その一：**一つの話題に一つの対話**。無関係な用件を一つの机に積まず、話が混ざらないようにする。
- 習慣その二：**自己矛盾、要件を繰り返し忘れる、くどくなる、明らかな物忘れ**が見えたら、思い切って**新しい対話を開き**、第11章の技術で必要な情報をきれいに伝え直す。良い中間成果は持っていき、廃案は置いていく。
- おかしな問題が出たら、まず新しい対話で試す。そこでも再現するなら設定を確認するかバグとして報告する。説明し直す手間が開き直す手間を上回ったら開き直す。
- 長期的な好み：モデル**本体には会話をまたいだ記憶がない**。「覚えさせ」たいなら、製品レイヤーのカスタム指示、プロジェクト、記憶を使う。これらは情報をコンテキストに入れ直すしくみ（公式ドキュメントを確認）。
- 記憶は自動で抜き出され、初期設定でオンのこともある。覚えられたくないものは一時チャットか記憶オフで扱い、定期的に確認・削除する。**機密情報を好みとして保存しない**（第37章）。

第2部の「対話の基本技」はここで出揃いました。次章ではさらに一歩進み、「一問一答」から**一つのタスクを継続的に進める**形へ――すなわちAIワークフロー（第14章）を扱います。
