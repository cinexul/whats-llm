長い AI タスクでは、お金、プランの利用枠、実行時間、コンテキスト容量を消費することがあります。互いに関係していますが、**同じメーターではありません。** 節約する前に、実際のアカウントで何に課金され、何が制限されるかを確認しましょう。

## 一、最初に課金経路を確認する

| 経路 | 主に支払うもの | 確認すること |
| --- | --- | --- |
| 個人・チーム向けの購読 | 規則に従った利用枠を含む定期プラン | 残りの枠、リセット期間、プラン固有の制限 |
| API アカウント | 通常は入出力トークンなどの従量料金 | モデル価格、キャッシュ入力価格、ツール料金、実際の使用量 |
| 追加機能 | クレジット、有料モード、接続サービス、基盤 | 有効かどうか、請求先、支出上限 |
| ローカルモデル | ハードウェアや借りた計算資源、電力 | 容量、稼働時間、別途使う外部サービス |

購読の利用枠を多く使っても、トークンごとの追加料金が発生するとは限りません。チャットの購読料が API リクエストを自動的に賄うわけでもありません。同じコーディングツールが購読ログインと API 認証の両方に対応する場合もあるので、製品名だけでなく**現在のアカウントの経路**を確認します。

通知と強制的な上限も別です。予算設定が通知だけなのか、新規リクエストを止めるのか、一つのプロジェクトだけを対象とするのかを確認してください。追加クレジットや有料の超過利用は、課金方法を理解してから有効にします。

## 二、トークン料金を理解し、一般化しすぎない

テキスト API の料金を単純化すると、次のようになります。

```text
料金 = キャッシュされない入力トークン × 入力単価
     + キャッシュ入力トークン × キャッシュ入力単価
     + 出力トークン × 出力単価
     + 該当するツールなどの料金
```

単位をそろえます。100万トークン当たりの価格なら、トークン数を100万で割ります。API によってはキャッシュ書き込み、画像などの処理、課金対象の推論トークンといった区分もあります。実際の使用量フィールドと料金規則に従ってください。

次は**計算用の架空の例で、現在のサービス価格ではありません。** 100万トークン当たり、通常入力が2ドル、キャッシュ入力が0.20ドル、出力が10ドルとします。キャッシュされない入力20,000、キャッシュ入力10,000、出力1,000トークンなら、次の計算です。

```text
20,000 / 1,000,000 × $2    = $0.040
10,000 / 1,000,000 × $0.20 = $0.002
 1,000 / 1,000,000 × $10   = $0.010
合計                     = $0.052
```

一つのエージェントタスクが、このようなリクエストやツール呼び出しを何度も行う場合があります。最後のメッセージの長さは総作業量の指標にはなりません。短い結論の前に、大量の検索、中間出力、委譲した処理があったかもしれません。

## 三、コンテキストは選ばれ、キャッシュされ、ときに要約される

回答には関連するコンテキストが必要です。指示、過去のメッセージ、ファイルの抜粋、ツール結果、保存されたノートなどが含まれます。**すべての製品が毎回、全履歴をそのまま送信するとは限りません。** アプリは履歴の選択、資料検索、古い会話の圧縮、サーバー側の状態保持などを行えます。

プロンプトキャッシュは、条件に合う繰り返し入力の料金や処理時間を減らす場合があります。ただし、その内容がコンテキスト内で無意味になったり、場所を取らなくなったりするわけではありません。要約は短くできますが、重要な細部を落とすことがあります。新しいチャットは雑音を減らせる一方、ファイルの再読やキャッシュ再利用の喪失も起こり得ます。

コンテキストが多いこと自体が悪いわけではありません。必要な証拠は難しい問いを助け、無関係または矛盾する資料は要件を埋もれさせます。長い入力は処理量を増やしがちですが、遅延にはモデル、推論設定、ツール、ネットワーク、サービス負荷も影響します。「遅い」だけで会話の詰め込みすぎと診断はできません。

## 四、四種類の制限を区別する

| 制限 | 対象 | 有用な対応 |
| --- | --- | --- |
| 利用枠・クォータ | プラン所定の期間内の利用量 | 残量とリセット規則を確認する |
| レート制限 | 短い期間のリクエスト数やトークン数 | 並行数を減らし、指示された時間の後に再試行する |
| コンテキストウィンドウ | 一回のリクエストで扱える内容 | 必要箇所を取得・要約し、要件を保持して分割する |
| 支出・残高の制限 | アカウントが使える金額や残高 | 増額前に請求設定と実使用量を調べる |

新しい会話を開いても購読の利用枠はリセットされません。多く支払ってもコンテキスト制限がなくなるとは限りません。直ちに何度も再試行するとレート制限を悪化させる場合があります。実際のエラーを読み、何でも「AI のメモリ不足」と呼ばないようにします。

## 五、証拠を保ちながら費用を抑える

最初に成果物と受け入れ条件を明確にします。ディレクトリ全体を読む前に、関連ファイルを探してもらいます。必要な要件、決定、出典は残し、重複ログや無効になった試行を整理します。

適したタスクでは小さく速いモデルを使い、難しい問題では必要に応じて推論を増やします。出力は役立つ長さにします。並行エージェントや繰り返しの再試行は、待ち時間を短縮しても総使用量を増やす場合があります。

詰まったときは全体を再実行する前に、一つの失敗コマンドや仮定を確認します。絞った修正は、広い範囲のやり直しより安く確実な場合が多いです。新しいセッションには、目標、現状、確認済みの事実、未解決の問題を引き継ぎます。

アカウントの使用量と結果の品質を合わせて比較してください。一回速く返ってきただけでは、低料金や高精度の証明にはなりません。キャッシュ、モデル、負荷が変わった可能性もあります。目標は**費用や利用枠当たりの有用な完成作業を増やすこと**であり、何を犠牲にしてもトークンを最少にすることではありません。

## 小テスト

1. **[基礎・概念問題]** AI の料金について正しい説明は？ <!-- quiz: q01 revision: 1 -->
   - A. 全製品がトークンごとに別料金を請求する
   - B. 購読に全 API リクエストが自動的に含まれる
   - C. 購読の利用枠、API 課金、追加機能を分けて確認する
   - D. トークンは購読の利用枠に絶対に影響しない
   > **答え C。** 経路ごとに課金と制限の規則が異なります。利用が増えて枠を消費しても、別のトークン請求が生じるとは限りません。

2. **[基礎・計算問題]** 架空の例で、入力 $0.040、キャッシュ入力 $0.002、出力 $0.010 の合計は？ <!-- quiz: q02 revision: 1 -->
   - A. $0.052
   - B. $0.52
   - C. $5.20
   - D. $0.042
   > **答え A。** 三つを足します。単位をそろえ、実際の請求では該当するツール料金なども加えます。

3. **[応用・誤解問題]** 「全製品が毎回すべての会話をそのまま再送し、通常入力料金で請求する」が不正確なのはなぜ？ <!-- quiz: q03 revision: 1 -->
   - A. 過去のコンテキストは一切関係しないから
   - B. 全チャットが無料だから
   - C. 出力だけが計算対象だから
   - D. 履歴の選択、圧縮、サーバーの状態、キャッシュで処理と料金が変わり得るから
   > **答え D。** アプリが実際のコンテキストを管理し、提供元が料金規則を決めます。画面上の全履歴は普遍的な課金式ではありません。

4. **[基礎・場面問題]** 購読の利用上限に達しました。新しいチャットでリセットされる？ <!-- quiz: q04 revision: 1 -->
   - A. 必ずされる
   - B. されない。アカウントの利用枠とリセット規則を確認する
   - C. 古いチャットを削除すればされる
   - D. 次の質問を短くすればされる
   > **答え B。** 会話のコンテキストとアカウントの利用枠は別の制限です。

5. **[応用・場面問題]** リクエストが遅くなりました。有用な対応は？ <!-- quiz: q05 revision: 1 -->
   - A. 必要な証拠をすべて削除する
   - B. 必ずコンテキストが原因だと決める
   - C. コンテキスト量、モデル設定、ツールの動作、サービス状態を調べる
   - D. 何も調べず上位プランへ変える
   > **答え C。** 複数の層が遅延に影響します。必要な証拠を保ち、実際の原因を調べます。

6. **[基礎・操作問題]** 次のタスクの前に、アカウントの経路、利用制限、有料追加機能の有無を記録してください。完了後は使用量と成果の品質を比較します。 <!-- quiz: q06 revision: 1 -->
   > **観察できるはず：** 予算管理は実際のメーターを知ることから始まります。重複作業を省くのは有用ですが、間違いを防ぐ証拠を削ると全体の費用が増えることがあります。
