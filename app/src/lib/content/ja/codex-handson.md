CodexはOpenAIのコーディングエージェントです。プロジェクトを調べ、ファイルを編集し、コマンドを実行し、変更のレビューを支援します。本章では、第24章の「調査、計画、実行、確認」を、実際に完了できる小さな作業に落とし込みます。

インストール方法とプランの情報は**2026-10-27**、その他の例は**2026-10-22**に公式資料と照合しました。インストール済みのバージョンや組織の設定によって違いがあるため、まずバージョンと利用できるコマンドを確認してください。

## 一、作業する場所を選ぶ

| 形態 | 作業の入口 | 最初に確認すること |
| --- | --- | --- |
| CLI | ターミナル。通常はローカルのプロジェクトを操作 | 現在のディレクトリ、Gitの状態、コマンドの権限 |
| IDE拡張機能 | 対応するコードエディター | 開いているプロジェクト、変更予定のファイル |
| デスクトップアプリ | 専用アプリ | タスクが使うプロジェクトと実行環境 |
| Web／クラウドタスク | ブラウザー。設定済みの環境で処理を実行 | リポジトリ、ブランチ、準備手順、ネットワーク、シークレット |

ローカルCLIを使っても、モデルがオフラインで動くとは限りません。クライアントはタスクのコンテキストをサービスへ送信できます。クラウドタスクには、自分のPCの依存関係、未コミットのファイル、認証情報が自動的に引き継がれるわけでもありません。

最初は既存の小さなGitプロジェクトで試しましょう（Gitのインストールと基本は第26章「Gitの最小限の始め方」を参照）。作業ツリーがクリーンか確認し、途中の変更は別途保存します。新しいブランチを作るだけでは、未コミットの作業のバックアップにはなりません。

## 二、インストール、ログイン、状態確認

2026年10月時点の公式ドキュメントでは、単体のインストーラーが最初に案内されており、Node.jsを先に入れる必要はありません。macOSまたはLinuxでは次のとおりです。

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

WindowsのPowerShellでは次のとおりです。

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

どちらもインストールスクリプトを取得して実行するコマンドです。公式のアドレスであることを確かめ、組織のインストール規則に従ってください。Homebrewを使っているなら`brew install --cask codex`、Node.jsとnpmが入っているなら`npm install -g @openai/codex`も選べます。公式READMEには各プラットフォームの実行ファイルも案内されています。インストール方法は一つ選べば十分です。入れたら次で確認します。

```bash
codex --version
codex --help
```

既存のプロジェクトに移動します。例のパスは実際のディレクトリに置き換えてください。以下の`git`コマンドにはGitが必要です。まだGitで管理していないプロジェクトなら、先に第26章の手順で出発点を保存してください。

```bash
cd /path/to/your/project
git status
git switch -c practice/codex-first-task
codex
```

初めて`codex`を実行すると、**Sign in with ChatGPT**を選べます。2026年10月時点の公式料金ページでは、ChatGPTのFree、Go、Plus、Pro、Business、Edu、EnterpriseのどのプランにもCodexが含まれるとされていますが、利用枠はプランによって大きく違い、無料プランは試用や手早い小さな作業向けという位置づけです。公式READMEはPlus、Pro、Business、Edu、Enterpriseでのログインを勧めています。実際の利用可否と利用枠はアカウントで確認します。APIキーは**別の認証・課金経路**であり、全ユーザーに必須ではありません。キーを会話に貼り付けないでください。

対話型CLIの中では、`/status`でセッション設定とトークン使用量、`/permissions`で許可される操作、`/diff`で変更を確認できます。`/`を入力すると、そのバージョンのコマンドを探せます。シェルの`codex --help`と、セッション内の`/`メニューは別の入口です。

## 三、一つの小さな作業を完了する

まず範囲を限定して依頼します。

```text
プロジェクトの指示と README を読んでください。文書に記載された
確認方法を特定してください。まだ編集せず、README の小さな改善を
一つ提案し、どう確認するかを説明してください。
```

提案を理解できたら、変更を許可します。

```text
提案した README の改善だけを実施してください。無関係な既存の変更は
保持してください。diff と関連するリンクやコマンドを確認し、変更内容、
実際に確認したこと、未確認の点を報告してください。
この練習では公開、push、デプロイはしないでください。
```

二段階にしているのは、操作に慣れるためです。慣れたら明確な依頼で実装と検証をまとめて許可でき、無害な細かい手順を毎回承認する必要はありません。

完了後は`/diff`、またはターミナルで次を確認します。

```bash
git diff --stat
git diff
git status --short
```

文書の変更なら文章とリンクを確認します。動作の変更なら関連テストを実行し、実際の動作も試します。「エージェントが成功と言った」ことより、コマンドの実行結果と再現できる動作のほうが強い証拠です。

## 四、プロジェクトの指示を残す

Codexはプロジェクトの指示に`AGENTS.md`を使えます。`/init`は作成を支援しますが、内容を確認してから使います。たとえば次のように書けます。

```markdown
# このプロジェクトの作業ルール
- 編集前に README を読む。
- 変更は依頼された目的に絞る。
- リポジトリで指定されたパッケージ管理と確認コマンドを使う。
- 例に認証情報や実際の顧客データを含めない。
- 検証結果と実行できなかった確認を報告する。
```

実際のコマンドを確かめたら、一般的な表現を具体的なコマンドに置き換えます。長い参考資料は別ファイルへのリンクにします。指示はコンテキストに読み込まれるもので、モデルを再学習させたり、すべての規則の遵守を保証したりするものではありません。スキルは手順をまとめ、保存されたメモリはノートを保持します。どちらも明示的なプロジェクト指示や、実際に強制される権限制御の代わりにはなりません。

## 五、権限、クラウド、費用を確認する

**サンドボックス**は実行環境がアクセスできる範囲を制限します。**承認ポリシー**は操作に承認が必要かを決めます。組み合わせによって、操作がすでに許可されている、確認が必要、禁止されている、といった違いが生じます。影響のあるコマンドの前には必ず確認画面が出る、とは考えないでください。

クラウドでは対象のリポジトリとブランチを確認し、環境の準備手順で依存関係を入れ、利用できるネットワーク接続先やシークレットを把握します。マージ前にdiffと検証結果を確認しましょう。ブランチはコードを戻す助けになりますが、送信済みメールや外部データベースの変更は戻せません。

料金は次の経路を区別します。

- **ChatGPTプラン：** 含まれるCodex利用はプランの規則に従って利用枠を消費します。大きなタスクが多くの枠を使っても、別途トークンごとの請求が発生するとは限りません。
- **API認証：**APIの価格とアカウントの制限に従います。ChatGPTの購読料でAPI利用が自動的に賄われるわけではありません。
- **追加購入やサービス：** 追加クレジット、接続サービス、クラウド基盤などは、有効にすると別の料金がかかる場合があります。

実際のアカウント、使用量画面、有効な追加機能を確認してください。作業範囲と資料を絞ることは有用ですが、「月額だから無制限」「トークンが増えれば購読料に必ず加算」とも限りません。

1. **[基礎・概念問題]** Codexの説明として正しいものは？ <!-- quiz: q01 revision: 2 -->
   - A. Webページでしか使えず、手元のPCには入れられない
   - B. OpenAIのコーディングエージェント。入口が複数ある
   - C. CLIを使うと、モデルは自分のPC上でオフラインで動く
   - D. どのプランでも、まずAPIキーを用意する必要がある
   > **答えB。** CLI、エディター拡張、デスクトップアプリ、Web／クラウドの入口があり、実行環境が異なる場合があるので、Aは誤りです。CLIをローカルで動かしてもオフライン推論にはならず、クライアントはタスクのコンテキストをサービスへ送ります（C）。ChatGPTアカウントでログインすれば使え、APIキーは別の経路です（D）。

2. **[基礎・場面問題]** 対象のChatGPTプランを契約しています。Codex用にAPIクレジットを購入する前に何を確認する？ <!-- quiz: q02 revision: 2 -->
   - A. 購読にCodexは含まれないと決めて、APIを買うのが早い

3. **[基礎・概念問題]** `AGENTS.md`が提供するものは？ <!-- quiz: q03 revision: 2 -->
   - A. コンテキストに読み込まれるプロジェクトの指示
   - B. ファイルへのアクセスを制限するセキュリティ設定
   - C. 書いたルールをモデルに学習させるための仕組み
   - D. Codexにすべての規則を必ず守らせる保証
   > **答えA。** プロジェクトの約束事を明文化し、作業時にコンテキストへ読み込まれます。ファイルへのアクセスを実際に制限するのはサンドボックスと権限設定です（B）。モデルの重みは変わりません（C）。コンテキストに入った規則でも、すべてが守られる保証はありません（D）。

4. **[応用・誤解問題]** 「危険なコマンドならCodexは必ず先に聞く」という説明に足りないものは？ <!-- quiz: q04 revision: 2 -->
   - A. 足りないものはない。危険なら必ず確認画面が出る
   - B. Gitの視点。Gitが外部への操作を自動で防いでくれる
   - C. モデルの視点。より強いモデルに替えれば先に聞く
   - D. 動作は、サンドボックス・承認ポリシー・権限で決まる
   > **答えD。** 操作は許可済み、承認待ち、禁止のいずれにもなり得るので、「毎回聞かれる」は当てになりません（A）。Gitが扱うのは記録したファイルで、外部への操作は防げません（B）。モデルを替えても承認の設定は変わりません（C）。実際の設定を確認し、承認をスキップするオプションは使わないでください（第26章）。

5. **[基礎・場面問題]** クラウドタスクが依存関係不足で失敗しました。次の一手は？ <!-- quiz: q05 revision: 2 -->

   - B. 環境の準備手順を確認し、その環境に依存関係を入れる
   - C. ネットワークとファイルの制限を外して、自分で入れさせる
   - D. 足りない依存関係を避けるように、コードを書き換えさせる
