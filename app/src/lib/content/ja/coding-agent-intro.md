第19章で、Agent（エージェント）を知りました。ひと言答えるだけでなく、自分で目標を分解し、ツールを呼び出し、何ステップも続けて進められるAIです。本章では、Agentの中でもいちばん成熟していて、一般の人にも関わりの深い種類、コーディングエージェント（coding agent）を取り上げます。代表は、名前を聞いたことがあるかもしれないClaude CodeとCodexです。

本章は、コードを書けることを前提にしません。はっきりさせたいのは、これが何で、どこまでできて、何を期待してはいけないか、そして最後に誰が責任を負うのか、です。ここが腑に落ちていれば、この先の章で出てくるdiffを見る、テストを走らせる、巻き戻す、計画を見るといった動作が、それぞれ何を防いでいるのかが分かります。

## 一、Agentの一種：「コードが書ける」だけでなく「仕事ができる」

「プログラミングAI」と聞いて、Webチャットを思い浮かべる人は多いでしょう。「ソート関数はどう書く？」と聞くとコードをくれて、それをコピーして使う（第17章でモデル・製品・Agentのレイヤーを扱いました）。コーディングエージェントはその一段上です。コードを書くことを手段にして、一つの仕事を片づけます。

| | 「コードが書ける」（チャットレイヤー） | 「仕事ができる」（エージェントレイヤー） |
| --- | --- | --- |
| 何を渡すか | 具体的な小さい質問 | 目標（「このサイトに検索ボックスを足して」） |
| 何が返ってくるか | 文章。使うのは自分 | 自分でファイルを読み、コードを変え、コマンドを実行して片づける |
| どれだけ知っているか | 貼り付けた数行だけ | 自分でプロジェクト全体を見て回り、現状をつかむ |
| 進め方 | 一問一答 | 目標に向かって何歩も進む：見る、直す、試す、また直す |

これは第19章のAgentのループが、プログラミングに当てはまった姿です。プロジェクトを読む（知覚）→ 案を考える（判断）→ ファイルを変え、コマンドを実行する（行動）→ 結果が合っているか見る（また知覚）、このループを自分で回します。つまりコーディングエージェントとは、第19章の手を動かすAgentが、あなたのコードプロジェクトで手を動かしているものです。「賢い検索ボックス」だと思うと、できることも、起こしうる事故も、両方を小さく見積もってしまいます。

## 二、どこで使うのか：製品による

2026年10月時点で、Claude Code（Anthropic製、中身はClaudeモデル）とCodex（OpenAI製）は、どちらも複数の入り口を用意しています。ターミナルで動くコマンドラインのプログラム、コードエディタの拡張機能、デスクトップアプリ、Webです。あなたのパソコンで直接ファイルを変えたりコマンドを実行したりする入り口もあれば、クラウドの隔離された環境でタスクを実行する入り口もあります。どの入り口があり、どこで実行されるかは製品と入り口しだいで、しかも変わり続けています。

そのため本書は、変わりやすい細部を第28・29章と付録Cにまとめ、この数章では入り口が変わっても変わらないこと、つまりAIがどう仕事をし、あなたがどう率いるかだけを扱います。

## 三、メンタルモデル：優秀だが初出勤の新人同僚

Claude CodeやCodexを、手が速く能力も高いけれど、今日着任したばかりで会社のことを何も知らない新人同僚だと想像してください。この人物像の一面一面が、実際の振る舞いに対応しています。

- 手が速い：任せた力仕事を、速く、たくさんこなします。これが最大の価値です。
- 流儀を知らない：プロジェクトのルール、命名の習慣、触ってはいけない場所を、言わなければ知りません。（ルールを「覚えさせる」方法は第28章で扱います。）
- 自信たっぷりに間違える：存在しない書き方を、迷いのない顔で使うことがあります。第9章のハルシネーションはコードでも起き、しかもコードは専門的に見えるぶん、詳しくない人をだましやすいのです。
- 知識に期限がある：とても新しい技術は知らなかったり、古いバージョンのまま覚えていたりします。最新の資料を渡さない限りそのままです（第9章）。

こういう新人を任された経験のある先輩は、放っておきもしないし、何でも自分でやってしまいもしません。仕事を振り、要所を見張り、最後に確認します。いきなりAIを全自動の代筆マシンとして扱い、用件を投げて、出てきたものをそのまま使う人は多いのですが、実際には、鍵を渡して任せきる請負業者より、面倒を見る実習生に近い存在です。一行一行を書ける必要はありませんが、仕事を振ることと、できているかを判断することは必要です。

## 四、責任は人の側にある

やり終えたことは、やり遂げたこととは限りません。「できました」と言っても、本当にできたとは限りません。AIは間違えるうえに、本当にあなたのものを変えられます。この二つが重なると、いちばん厄介な事態が起こりえます。迷いのない顔でプロジェクトを壊し、そのうえ「完了しました」と報告するのです。

だから、ツールがどれほど強くなっても動かない一線があります。変更をプロジェクトにマージし、顧客に渡し、あなたの名前を付ける前に、見直して検収するのはあなたの責任です（AIが生成した内容の責任は第39章で扱います）。

プログラミングができない人は、どう検収すればよいのでしょうか。コードを一行残らず読み解く必要はありません。そのかわり、具体的なことをいくつか実行します。「何ができたら完成か」を先に書き出し、変更後にその手順どおり自分で確かめる。何を変えたか、どこに危険があるかを、普通の言葉で説明させる。お金、個人データ、パスワードや鍵、ファイルの削除、外部への公開に関わる変更は、新しい会話の別のエージェントか、詳しい人にもう一度見てもらう。元に戻せない操作は実行しない。第25章で、これを具体的な手順にします。

> **ポイント：** 検収という関所を守ってはじめて、AIの速くて大量の仕事が本当に節約した時間になります。「この件は本当にできたのか」を判断する決め手は、コードを全部読めることではなく、具体的なチェックです。

## 五、この先の章とのつながり

ここまでの話をつなげると、この先の数章の地図になります。

- 手を動かし、しかも間違えるので、決まった手順で仕事を進める必要があります：第24章の「調査 → 計画 → 実行 → 検収」。
- 変更後にはチェックが要ります：第25章でdiffの読み方、チェックの実行、巻き戻し、検収を扱います。第4部でいちばん練習してほしい章です。
- 本当にあなたのものを変えるので：第26章で、やり直しのきく環境で手を動かさせ、危険な操作は先に聞かせる方法を扱います。
- 大きな仕事を一気にやらせてはいけないので：第27章で、先に計画を出させて承認してから動かし、大きなタスクを小さく分けて小さく検収する方法を扱います。

## 六、よくある誤解

| 誤解 | 実際 |
| --- | --- |
| コーディングエージェントは、コードがもっと上手なチャットAIだ | 手を動かすAgent（第19章）。自分でプロジェクトを読み、ファイルを変え、コマンドを実行し、何歩も進む |
| 特定のWebサイトかソフトのことで、形は決まっている | ターミナル、エディタ、デスクトップアプリ、Webなど入り口は複数あり、ローカルでもクラウドでも実行される。製品による |
| AIなのだから、書いたコードは正しいはず。そのまま使う | 自信たっぷりに間違える。やり終えた ≠ やり遂げた。検収が必要 |
| プログラミングができないと使えない | 一行一行を書ける必要はない。仕事を振り、具体的なチェックでできたかを判断できればよい |
| 「完了しました」と言われたら、責任はAIに移る | 署名も責任もあなたのもの。マージや引き渡しの前の見直しは人の仕事（第39章） |

## まとめ

- コーディングエージェント（Claude Code、Codex）は、第19章の「手を動かすAgent」がプログラミングの領域に現れた姿です。自分でプロジェクトを読み、ファイルを変え、コマンドを実行し、何歩も進んで一つの仕事を片づけます。
- 入り口はターミナル、エディタ、デスクトップアプリ、Web。ローカルとクラウドのどちらで実行されるかは製品しだいです。変わりやすい細部は第28・29章と付録Cにあります。
- メンタルモデルは、優秀だが初出勤の新人同僚。手が速くよく働くけれど、あなたの流儀を知らず、自信たっぷりに間違えます。
- 責任は人にあります。コードを一行残らず読めなくてよいが、具体的なチェックで正しくできたかを確かめます（第25章）。
- この先の章は順に、ワークフロー（第24章）、検収（第25章）、許可と巻き戻し（第26章）、計画を先に見る（第27章）を扱います。

1. **[基礎・概念問題]** 「コーディングエージェント」を第19章の「Agent」と照らし合わせたとき、最も正確なのはどれ？ <!-- quiz: q01 revision: 2 -->
   - A. Agentの一種で、手を動かす場所があなたのコードプロジェクトなだけ
   - B. チャットAIの上位版で、違いは主にコードをより正確に書けること
   - C. Agentとは別物。Agentは手を動かすが、こちらは助言をくれるだけ
   - D. Agentはその中に組み込まれた小さな機能で、資料検索の専用
   > **答えA。** 第19章のAgentは、自分で目標を分解し、ツールを呼び出し、何歩も続けて進むAIです。コーディングエージェントは、この本領を「コードプロジェクトを変更する」ことに使ったものです。Bは「コードを書く」ことしか見ておらず、自分でプロジェクトを読み、ファイルを変更し、コマンドを実行する点を見落としています。Cは「チャットAIは文字をくれるだけ」という古い印象のままで、Dは包含関係が逆です。

2. **[基礎・概念問題]** 「コードが書ける」と「仕事ができる」、コーディングエージェントにとって違いはどこにある？ <!-- quiz: q02 revision: 2 -->
   - A. 本質的な違いはなく、「仕事ができる」は宣伝用の言い方にすぎない
   - B. 前者はコードを渡すだけ。後者は自分で読み、変更し、コマンドを実行する
   - C. 「仕事ができる」とは、より長く完全なプログラムを一度に書けること
   - D. 違いは速さで、「仕事ができる」ほうが答えが返ってくるのが早い
   > **答えB。** これこそチャットレイヤーとエージェントレイヤーの境界です。前者は文字を出し、あなたが実行します。後者は自分で実行し、何歩も続けて進みます。CとDは違いを「たくさん書ける」「早く答える」と捉えていますが、肝心なのは誰が手を動かすかです。Aは、本当にあなたのファイルを変更するという点を見落としています。

3. **[基礎・誤解問題]** 「それはAIなのだから、書いたコードは正しいはず。やり終えたらそのまま使う」――どこが間違い？ <!-- quiz: q03 revision: 2 -->
   - A. AIのコードはたいてい正しく、書き方の癖をそろえる手直しが要るだけ
   - B. AIが書いたコードはたいてい動かないので、受け取ったら全部書き直すべき
   - C. 間違えるのは無料版だけで、有料版が書いたコードならそのまま使える
   - D. 自信たっぷりに間違えることがあり、やり終えた≠正しい。まず検証する
   > **答えD。** ハルシネーション（第9章）はコードを書くときも起き、しかもコードは「専門的」に見えるぶん専門知識がない人をだましやすいのです。だから後で「diffを見る、テストを走らせる」を学びます。Aは問題を小さく見ています。Bは逆の極端で、たいていは動きます。問題は「動く」≠「正しい」という点です。Cのように有料なら間違えないということもなく、どの版でも間違えます。

4. **[応用・誤解問題]** 「Claude Code / Codexは、ある固定のWeb（あるソフト）であって、形態は決まりきっている」――なぜそう考えると問題が起きるのか？ <!-- quiz: q04 revision: 2 -->
   - A. 問題は起きない。主流の形態はこの先数年ほとんど変わらない
   - B. 問題が起きる。実はクラウドのWebページの中でしか動かないから
   - C. 形態は多様で更新も続く。一つに決めるとすぐ古くなる。公式を参照
   - D. 問題が起きる。コマンドラインでしか使えず、画面がまったくないから
   > **答えC。** 形態は「変わる」ほうの類です。製品によって、ターミナル、エディタ、Web、クラウドなどで使います。だから本書は古くならないメンタルモデルだけを扱い、「どこで使うか、どうインストールするか」は公式ドキュメントに委ねます。BとDは、別の一つの形態に決めつけ直しているだけです。ただし二点は安定しています：Claude CodeはAnthropic発（コアはClaude）、CodexはOpenAI発です。

5. **[基礎・場面問題]** 初めて使うとき、AIがあっという間に「機能を追加できました」と言った。「率いる側の人」として、次にすべきことは？ <!-- quiz: q05 revision: 2 -->
   - A. AI自身にもう一度見直させ、問題ないと言えばそのままマージする
   - B. 確認する：何を変えたか、ほかを壊していないか、説明できるか
   - C. 先に次の機能も作らせて、最後にまとめて確認することにする
   - D. まず公開して様子を見て、問題が出たらAIに直させればよい
   > **答えB。** 「やり終えた≠正しい」。優秀だが着任したての新人同僚のようなもので、確認は率いる側の人の責任です（具体的な三つの動作は第25章）。Aは自己採点を任せているだけで、確認になっていません。Cは問題をため込み、後で原因を探しにくくします。Dは「鍵を渡して任せきる請負業者」扱いで、最もよくある失敗の姿勢です。

6. **[応用・操作/観察問題]** どんなツールも実際にインストールする必要はありません：身の回りで「仕事をするvs助言をくれるだけ」の対比を一つ探してください――たとえば「ナビが直接あなたを曲がり角まで連れていく」のと「通りすがりの人が方向を指さす」の対比。考えてみましょう：コーディングエージェントはどちらに近い？ また「ひとまとまりのコードを渡してあなたにコピーさせるだけ」のチャットAIとは、どのステップで違う？ <!-- quiz: q06 revision: 2 -->
   > **観察できるはず：** コーディングエージェントは「直接あなたを曲がり角まで連れていく」ナビに近い――自分で実行し、何歩も続けて進む。チャットAIは「方向を指さす」通りすがりの人に近い――情報をくれるが、道はあなたが自分で歩く。違いは「誰が手を動かし、誰が何歩も続けて進むか」にあります。AIが自分で手を動かし、なお道を間違えうるからこそ、「確認」という関所はあなたに残さねばなりません（第25・26章）。具体的なツールの形態・インストール・コマンドは **公式ドキュメントを参照**。
