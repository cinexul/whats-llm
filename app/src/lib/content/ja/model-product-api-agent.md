チャットアプリを開くとモデル選択があり、同じ会社がAPIやエージェントも提供していると聞く。これらの言葉は、システムの異なる部分を表しています。区別できると、何を使い、何に支払い、AIに何ができるのかを判断しやすくなります。

## 一、まず地図：四つの見方

| 用語 | 表すもの | 簡単な例 |
| --- | --- | --- |
| **モデル** | 入力を処理して出力を生成する仕組み | 文章を読み、要約を作る |
| **製品** | 人が使うアプリ。画面、保存機能、ツールなどを含む | チャットアプリで文書をアップロードする |
| **API** | ソフトウェアがサービスを要求するための決まった窓口 | 文書アプリがモデルサービスに文章を送る |
| **エージェント** | 目標に向けて手順を選び、多くの場合ツールを使って結果を確かめる仕組み | 文書を探し、比較して出典付きの報告書を作る |

第1章のレストランのたとえを続けると、モデルは料理人の腕前、製品はメニューや席や給仕のそろったレストラン全体です。APIはレストランが宅配サービス向けに開いた注文窓口で、ほかのプログラムが決まった形式で注文し、料理を受け取ります。エージェントは「誕生日の会食を用意して」と頼まれると、自分でメニューを調べ、苦手な食材を確かめ、品切れがあれば計画を変える給仕長のような存在です。

これは四つの見方です。互いに排他的な分類でも、必ず順番に積む四階建てでもありません。製品がエージェントを含み、そのエージェントがAPI経由でモデルを呼ぶことがあります。ローカルアプリがクラウドAPIを使わず、パソコン上で直接モデルを動かす構成もあります。

## 二、見方① モデル：内容を生み出す「コア」

モデルは言語の理解、画像の読み取り、文章生成などの能力を担います。対応する入力と出力は、個々のモデルによって異なります。画像を読めても画像を生成できるとは限らず、音声を処理できても製品がリアルタイム会話を提供するとは限りません。

モデル名だけでは、ウェブ検索、好みの保存、ファイル編集が使えるかは分かりません。周囲の仕組みにも依存します。また、モデル自体は会話をまたいであなたを覚えていません。いわゆる「メモリー」は、製品が保存した情報を後の会話でコンテキストに入れ直す機能です（第9章）。

## 三、見方② 製品：「人」が使うために包んだ面

ChatGPTはOpenAIの製品です。ClaudeとGeminiは、モデル群と、それぞれの会社の製品の両方を指す名前です。区別が必要なら「Claudeのアプリ」「Geminiのモデル」と言い分けましょう。

製品は、複数モデルの選択、会話履歴の保存、ファイル検索、別サービスによる画像生成、エージェントモードなどを組み合わせます。プラン、地域、組織設定、権限も使い勝手に影響します。そのため、同じモデルでも、組み込まれた製品が違えば使い心地はかなり変わります。

## 四、見方③ API：「プログラム」が使うための窓口

APIは、ソフトウェアが記入して読み取れる注文票のようなものです。プログラムは、要約したい文章などを決められた形式で送り、形式の決まった応答を受け取ります。APIが提供するのは、モデルを動かすこと（推論、inference）、つまり入力をモデルに渡して出力を計算させる処理の場合もあれば、検索やファイル操作の場合もあります。ここでの「推論」は「モデルを動かす」という意味で、第8章の「推論の強さ」（回答時にどれだけ考えるか）とは別物です。API自体もモデルではありません。

APIを使って作られた製品を利用するだけなら、プログラミングの知識は不要です。また、チャットの有料プランに、別途課金される開発者向けAPIの利用が自動的に含まれるわけではありません。サブスクリプションのアカウントでログインするツールも、APIキーや別の残高が必要なツールもあります。実際に使うツールの支払い経路を確認しましょう。APIキーはアクセスや支払いを許可することがあるため、パスワードと同じように管理します。

## 五、見方④ エージェント：「自分で手を動かす」働き方

エージェントは成果に向かって作業を進めます。検索結果を読み、足りない点に気づいて再検索し、成果物をまとめる、といった流れです。本章で重視する特徴は、**観察した結果に応じて手順を選び、調整すること**です。

一度ウェブ検索しただけでは、有意な自律性があるとは言えません。固定された処理手順でもツールを呼べます。一方、外部ファイルを変更せず、調査と報告だけを行うエージェントもあります。「エージェント」という呼び名は広く使われるため、実際の動作と権限を見て判断しましょう。

## 六、四つの見方はどう組み合わさるか

「この三つの契約書を比較して」という依頼なら、例えば次の構成が考えられます。

```text
利用者が製品を使う
  → エージェントが確認すべき条項を選ぶ
  → ツールが閲覧権限のある箇所を取り出す
  → API 経由でその箇所をモデルに渡す
  → モデルが比較結果を生成する
  → 製品が結果と出典を表示する
```

これは構成例の一つです。ツール、モデルサービス、ファイル保存先が別々の会社に属する場合もあります。

> **ポイント：** ノートパソコン上のプログラムでも、文書の抜粋をクラウドモデルに送ることがあります。プライバシーを考えるときは、アプリの置き場所ではなく、内容の送り先を追います。

## 七、実用的な見分け方：今向き合っているのは何？

三つの具体的な問いを使います。

1. **何を開いているか。** ウェブサイト、スマホアプリ、デスクトップツールは製品です。
2. **何が、どこで内容を処理するか。** モデルやサービスと、ローカルかリモートかを確認します。公開されていない詳細は不明とします。
3. **何を判断し、実行できるか。** 提案だけなのか、固定の自動処理なのか、次の手順を調整するエージェントなのかを区別し、実際のツールと権限を確認します。

## 八、よくある誤解、まとめて訂正

| 誤解 | 訂正 |
| --- | --- |
| Claudeは必ずモデルだけを指す | 製品を指すこともあり、文脈で決まる |
| 有料プランならAPI呼び出しもすべて含まれる | 認証と課金の仕組みはサービスごとに異なる |
| エージェントは必ず別の強力なモデルだ | モデルやツールを組み合わせた仕組みがエージェントの動作を作る |
| ツールを呼べば自律的だ | 固定の処理手順でもツールは呼べる |
| デスクトップアプリなら処理もローカルだ | モデルや接続先のツールはクラウドにある場合がある |

## まとめ

四つの言葉で、**何が生成するか、何を使うか、ソフトウェアをどう接続するか、仕事をどう進めるか**を整理できます。実際のシステムでは重なり合います。次章では、この地図を使って自分のタスクに合う製品を選びます。

## 小テスト

1. **[基礎・概念問題]** 四つの用語の説明として最も適切なのは？ <!-- quiz: q01 revision: 1 -->
   - A. 順に積み重なる四層で、全製品が全部を持つ
   - B. 競合する四種類のモデルで、最強を選べばよい
   - C. 同じシステムを見る別の角度で、重なり得る
   - D. APIとエージェントは同じものの別の呼び名
   > **答えC。** 製品がエージェントを含み、エージェントがAPI経由でモデルを呼ぶこともあれば、別の組み合わせもあります。Aは順番に建てる階層だと誤解しています。Dは「プログラムをつなぐ窓口」と「仕事を進める働き方」を混同しています。

2. **[基礎・概念問題]** APIとは？ <!-- quiz: q02 revision: 1 -->
   - A. プログラムがサービスに要求を出す決まった窓口
   - B. パラメータが多く、能力の高い種類の大規模モデル
   - C. チャットの有料プランに付いてくる上位機能の一つ
   - D. 次に何をするかをAI自身に決めさせるための仕組み
   > **答えA。** APIはプログラムとサービスをつなぎます。その先はモデルの場合も、検索やファイルなど別のサービスの場合もあります。API自体はモデルではなく（B）、チャットの有料プランにAPI利用が自動で含まれるわけでもありません（C）。Dはエージェントの説明です。

3. **[基礎・誤解問題]** アシスタントがウェブを一度検索しました。何が分かりますか？ <!-- quiz: q03 revision: 1 -->
   - A. エージェントであり、仕事全体を自力で完了できる
   - B. あなたのファイルを編集する権限も同時に得ている
   - C. 検索はローカルで行われ、内容は外に出ていない
   - D. 検索はできるが、自律的とはまだ言えない
   > **答えD。** 一度ツールを呼ぶだけなら固定の処理手順でもできます。エージェントかどうかは、結果に応じて次の手順を選び直すかで判断します。検索機能はファイル権限の証拠ではなく（B）、処理場所も示しません（C）。

4. **[応用・場面問題]** チャットの有料プランに加入した後、別ツールでAPIキーを求められました。何を確認しますか？ <!-- quiz: q04 revision: 1 -->
   - A. 確認は不要。プランで全利用が賄われている
   - B. そのツールの認証と利用料が別課金かどうか
   - C. 二つの製品に表示されるモデル名が同じか
   - D. キーをチャットに貼ってAIに設定させてよいか
   > **答えB。** チャットのプランと開発者APIの残高は、自動的に同じ利用権にはなりません。プランのログインを使えるツールも、キーや別の残高が必要なツールもあります。Aはまさにその誤解です。モデル名が同じでも課金方法は分かりません（C）。キーは認証情報なので、チャットに貼りません（D）。

5. **[基礎・場面問題]** デスクトップの助手がクラウドモデルで文書を読んでいます。文書の内容はどこで処理され得ますか？ <!-- quiz: q05 revision: 1 -->
   - A. アプリの送信内容によっては、クラウドで処理される
   - B. アプリがパソコンにあるので、パソコン内だけで処理
   - C. 文書がパソコンのディスクにあるので、手元でだけ処理
   - D. 手元で暗号化されるので、クラウドは中身を見られない
   > **答えA。** インストール場所と処理場所は別の問題です。クラウドモデルを使うなら、アプリが送った抜粋は提供元のサービスで処理されます。BとCはアプリや文書の置き場所を処理場所と取り違えています。Dは製品が約束していない保護を前提にしています。

6. **[基礎・観察問題]** 製品が今回使用したモデルを公開していません。適切な説明は？ <!-- quiz: q06 revision: 1 -->
   - A. 回答の文体から、最もありそうなモデルを推測する
   - B. その会社の最新で最も強力なモデルだと書いておく
   - C. 製品と見える機能を書き、モデルは不明とする
   - D. 製品自身にモデル名を答えさせ、それを書き写す
   > **答えC。** 役に立つ地図には不明な項目があっても構いません。文体（A）やブランド名（B）では具体的なモデルのバージョンは分かりません。モデルが名乗る名前も正確とは限りません（D）。
