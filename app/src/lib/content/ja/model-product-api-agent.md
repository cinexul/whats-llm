チャットアプリを開くとモデルを選ぶ欄があり、同じ会社がAPIやエージェントも提供していると聞きます。これらの言葉は、同じシステムの別々の部分を指しています。区別できれば、自分が何を使っているのか、お金がどこにかかるのか、AIに何を任せられるのかが分かります。

## 一、まず地図：四つの見方

| 用語 | 表すもの | 簡単な例 |
| --- | --- | --- |
| モデル | 入力を処理して出力を生成する仕組み | 文章を読み、要約を作る |
| 製品 | 人が使うアプリ。画面、保存機能、ツールなどを含む | チャットアプリで文書をアップロードする |
| API | プログラムがサービスに依頼するときの決まった窓口 | 文書アプリがモデルサービスに文章を送る |
| エージェント（agent） | 目標に向けて手順を選び、多くの場合ツールを使って結果を確かめる仕組み | 文書を探し、比較して出典付きの報告書を作る |

第1章のレストランのたとえを続けると、モデルは料理人の腕前、製品はメニューや席や給仕のそろったレストラン全体です。APIはレストランが宅配サービス向けに開いた注文窓口で、ほかのプログラムが決まった形式で注文し、料理を受け取ります。エージェントは給仕長のような存在で、「誕生日の会食を用意して」と頼まれると、自分でメニューを調べ、苦手な食材を確かめ、品切れがあれば計画を変えます。

この四つは同じシステムを見る四つの角度で、互いに重なります。順番に積み上げる四階建てでもありません。製品がエージェントを含み、そのエージェントがAPI経由でモデルを呼ぶことがあります。ローカルアプリがクラウドAPIをまったく使わず、パソコン上で直接モデルを動かす構成もあります（第21章）。

## 二、見方① モデル：内容を生み出す「コア」

モデルは、入力を出力に変える部分です。文章を読み、画像を見て、答えを生成します。対応する入力と出力はモデルごとに違います。画像を読めても画像を生成できるとは限らず、音声を聞き取れても製品がリアルタイムの音声会話を提供するとは限りません。

モデル名だけでは、ウェブ検索、メモリー、ファイル編集が使えるかは分かりません。それらは周りの仕組みが加えるものです。また、モデル自体は会話をまたいであなたを覚えていません。製品の「メモリー」は、保存した情報を後の会話でコンテキストに入れ直す機能です（第9章）。

## 三、見方② 製品：「人」が使うために包んだ面

ChatGPTはOpenAIの製品です。ClaudeとGeminiは、それぞれの会社の製品名であると同時に、モデル群の名前でもあります。区別が必要なら「Claudeのアプリ」「あるGeminiモデル」と言い分けましょう。

製品はモデルの外側にいろいろなものを加えます。モデル選択、会話履歴、ファイルのアップロードと検索、ウェブ検索、別サービスを呼んでの画像生成、エージェントモードなどです。どれが使えるかは、プラン、地域、組織の設定にも左右されます。そのため、同じモデルでも、組み込まれた製品が違えば使い心地はかなり変わります。

## 四、見方③ API：「プログラム」が使うための窓口

APIは、プログラムが記入して読み取れる注文票のようなものです。決まった形式で依頼を送り、決まった形式の結果を受け取ります。次はモデルを呼ぶ一回分を簡略化したもので、項目名は会社によって少しずつ違います。

```text
プログラムが送る依頼:
  モデル:(あるモデル名)
  入力:「次の会議記録を三点に要約して:……」
  最大出力:300トークン

サービスが返す結果:
  出力:「1. …… 2. …… 3. ……」
  使用量:入力812トークン、出力96トークン
```

結果に含まれる使用量が、従量課金の根拠になります（第38章）。APIの向こう側にあるのは、モデルを動かすサービスのこともあれば、検索やファイル保存など別のサービスのこともあります。モデルを動かすことを英語でinferenceといい、日本語では「推論」と訳されます。これは単にモデルに出力を計算させるという意味で、第8章の「推論の強さ」（回答時にどれだけ考えるか）とは別物です。API自体もモデルではありません。

APIを使って作られた製品を使うだけなら、プログラミングの知識は要りません。ただ、チャットのサブスクリプションと開発者向けAPIは、たいてい別会計です。2026年10月時点で、AnthropicのヘルプセンターはClaudeの有料プランにAPIの利用は含まれず、APIは開発者プラットフォームで別に課金されると明記しています（MaxとTeamのプランには毎月一定のAPIクレジットが付きます）。OpenAIのCodexは、ChatGPTアカウントでログインするとプランの利用枠を使い、APIキーを使うとAPI料金で別に課金されます。APIキーの入力を求めるツールに出会ったら、まずどの支払い経路を通るのかを確かめましょう。APIキーはそのまま費用を発生させるので、パスワードと同じように管理します。

## 五、見方④ エージェント：「自分で手を動かす」働き方

エージェントは成果に向かって作業を進めます。検索して結果を読み、足りない点に気づいて再検索し、最後に成果物にまとめる、といった流れです。本章で重視する特徴は、見た結果に応じて次の手順を選び、調整することです。

一度ウェブ検索しただけでは、どれほど自律的かは分かりません。固定された処理手順でもツールは呼べます。逆に、外部のファイルを一切変えず、調査と報告だけを行う仕組みもエージェントでありえます。製品では「エージェント」という言葉が広く使われるので、実際の動作と権限を見て判断しましょう。詳しくは第19章で扱います。

## 六、四つの見方はどう組み合わさるか

「この三つの契約書を比較して」という依頼なら、例えば次の構成が考えられます。

```text
利用者が製品を使う
  → エージェントが確認すべき条項を選ぶ
  → ツールが閲覧権限のある箇所を取り出す
  → API 経由でその箇所をモデルに渡す
  → モデルが比較結果を生成する
  → 製品が結果と出典を表示する
```

これは構成例の一つです。ツール、モデルサービス、ファイル保存先が別々の会社に属することもあります。

> **ポイント：** ノートパソコン上のプログラムでも、文書の抜粋をクラウドのモデルに送ることがあります。プライバシーを考えるときは、アプリがどこに入っているかではなく、内容がどこへ送られるかを追います（第37章）。

## 七、実用的な見分け方：今向き合っているのは何？

三つの具体的な問いを使います。

1. 何を開いているか。ウェブサイト、スマホアプリ、デスクトップツールは製品です。
2. 何が、どこで内容を処理するか。背後のモデルやサービスを特定し、ローカルかリモートかを確認します。公開されていない詳細は不明とします。
3. 何を判断し、実行できるか。提案だけなのか、固定の自動処理なのか、結果に応じて次の手順を調整するエージェントなのかを区別し、実際に持っているツールと権限を確認します。

## 八、よくある誤解、まとめて訂正

| 誤解 | 訂正 |
| --- | --- |
| Claudeは必ずモデルだけを指す | 製品を指すこともあり、文脈で決まる |
| 有料プランならAPI呼び出しもすべて含まれる | サブスクリプションとAPIはたいてい別課金で、ログイン方法も違う |
| エージェントは必ず別の強力なモデルだ | モデルやツールを組み合わせた仕組みがエージェントの動作を作る |
| ツールを呼べば自律的だ | 固定の処理手順でもツールは呼べる |
| デスクトップアプリなら処理もローカルだ | モデルや接続先のツールはクラウドにある場合がある |

## まとめ

四つの言葉は、四つの問いに答えます。何が内容を生成するか（モデル）、何を使っているか（製品）、プログラム同士をどうつなぐか（API）、仕事をどう一歩ずつ進めるか（エージェント）。実際のシステムでは重なり合います。次章では、この地図を使って自分のタスクに合う製品を選びます。

1. **[基礎・概念問題]** 四つの用語の説明として最も適切なのは？ <!-- quiz: q01 revision: 2 -->
   - A. 順に積み重なる四層で、全製品が全部を持つ
   - B. 競合する四種類のモデルで、最強を選べばよい
   - C. 同じシステムを見る別の角度で、重なり得る
   - D. APIとエージェントは同じものの別の呼び名
   > **答えC。** 製品がエージェントを含み、エージェントがAPI経由でモデルを呼ぶこともあれば、別の組み合わせもあります。Aは順番に建てる階層だと誤解しています。Dは「プログラムをつなぐ窓口」と「仕事を進める働き方」を混同しています。

2. **[基礎・概念問題]** APIとは？ <!-- quiz: q02 revision: 2 -->
   - A. プログラムがサービスに要求を出す決まった窓口
   - B. パラメータが多く、能力の高い種類の大規模モデル
   - C. チャットの有料プランに付いてくる上位機能の一つ
   - D. 次に何をするかをAI自身に決めさせるための仕組み
   > **答えA。** APIはプログラムとサービスをつなぎます。その先はモデルの場合も、検索やファイルなど別のサービスの場合もあります。API自体はモデルではなく（B）、チャットの有料プランにAPI利用が自動で含まれるわけでもありません（C）。Dはエージェントの説明です。

3. **[基礎・誤解問題]** アシスタントがウェブを一度検索しました。何が分かりますか？ <!-- quiz: q03 revision: 2 -->
   - A. エージェントであり、仕事全体を自力で完了できる
   - B. あなたのファイルを編集する権限も同時に得ている
   - C. 検索はローカルで行われ、内容は外に出ていない
   - D. 検索はできるが、自律的とはまだ言えない
   > **答えD。** 一度ツールを呼ぶだけなら固定の処理手順でもできます。エージェントかどうかは、結果に応じて次の手順を選び直すかで判断します。検索機能はファイル権限の証拠ではなく（B）、処理場所も示しません（C）。

4. **[応用・場面問題]** チャットの有料プランに加入した後、別ツールでAPIキーを求められました。何を確認しますか？ <!-- quiz: q04 revision: 3 -->
   - A. プランの更新日。APIの途中で切れないように
   - B. そのツールの認証と利用料が別課金かどうか
   - C. 二つの製品に表示されるモデル名が同じか
   - D. キーをチャットに貼ってAIに設定させてよいか
   > **答えB。** チャットのプランと開発者APIの残高は、自動的に同じ利用権にはなりません。プランのログインを使えるツールも、キーや別の残高が必要なツールもあります。AはAPIの利用がチャットのプランで賄われると思い込んでおり、まさに本章で正した誤解です。モデル名が同じでも課金方法は分かりません（C）。キーは認証情報なので、チャットに貼りません（D）。

5. **[基礎・場面問題]** デスクトップの助手がクラウドモデルで文書を読んでいます。文書の内容はどこで処理され得ますか？ <!-- quiz: q05 revision: 2 -->
   - A. アプリの送信内容によっては、クラウドで処理される
   - B. アプリがパソコンにあるので、パソコン内だけで処理
   - C. 文書がパソコンのディスクにあるので、手元でだけ処理
   - D. 手元で暗号化されるので、クラウドは中身を見られない
   > **答えA。** インストール場所と処理場所は別の問題です。クラウドモデルを使うなら、アプリが送った抜粋は提供元のサービスで処理されます。BとCはアプリや文書の置き場所を処理場所と取り違えています。Dは製品が約束していない保護を前提にしています。

6. **[基礎・観察問題]** 製品が今回使用したモデルを公開していません。適切な説明は？ <!-- quiz: q06 revision: 2 -->
   - A. 回答の文体から、最もありそうなモデルを推測する
   - B. その会社の最新で最も強力なモデルだと書いておく
   - C. 製品と見える機能を書き、モデルは不明とする
   - D. 製品自身にモデル名を答えさせ、それを書き写す
   > **答えC。** 役に立つ地図には不明な項目があっても構いません。文体（A）やブランド名（B）では具体的なモデルのバージョンは分かりません。モデルが名乗る名前も正確とは限りません（D）。
